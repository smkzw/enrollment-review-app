# Quality Guidelines

> 后端质量以临床逻辑正确、可追溯、可恢复和跨项目泛化为核心。

## Overview

V2 必须把方案事实、证据事实、候选解释、确定性判定和用户动作分开。质量门禁不能只证明流程能跑通，还要证明布尔逻辑、时间窗、单位、例外条件、证据完整性和阶段边界正确。

## Forbidden Patterns

- 在系统级代码写入特定项目、中心或受试者 ID 的修补规则。
- 让 LLM 直接产生最终总体结论、自动关闭待办或覆盖人工 override。
- 用正则或理由文本关键词修补“和/或”、实验室指标、梅毒例外等语义错误。
- 缺失条目、解析失败、冲突证据或未知值默认判为通过。
- 用 Markdown、mtime、缓存文件或单个 `overall_verdict` 作为事实源。
- API 路由直接访问多个存储实现并拼装领域结论。
- 捕获所有异常后返回成功或空数组。

## Required Patterns

- RuleExpression、EvidenceRequirement、EvidenceSpan、ReviewEpisode 和 ActionItem 均有版本化契约。
- Agent 只提出结构化候选；确定性 evaluator/gate 负责最终状态、rollup 和待办动作。
- 所有副作用节点幂等；长任务有 durable Job、检查点、重试范围和取消状态。
- 修改持久数据使用 revision/乐观锁；过期候选不能覆盖新状态。
- 证据必须指向文件、页码及可用的 bbox/text range/excerpt，定位能力降级要明确记录。
- 用户界面文案由稳定状态和结构化字段生成，不解析模型自由文本。
- 新 V2 写路径与 legacy 存储物理隔离；旧项目仅作为只读回归锚点。
- 草稿差异必须由前后完整结构快照确定性计算，覆盖规则、组件、资料要求、流程映射、来源绑定和解释层；发布不能信任调用方提交的局部差异声明。
- 冻结目录映射使用有序且不重复的来源集合；合同构造器与发布门禁都要独立拒绝重复、换绑、跨访视或跨期来源，防止低层复制绕过模型重验证。
- 官方父规则目录、基线及以前必做项目录和允许来源必须在语义模型调用前作为独立检查点落盘；模型失败或服务不可用时，来源与冻结目录仍必须可查。
- 局部修订的防回退比较同时检查问题数和问题指纹；即使总数减少，只要用新问题替换了旧问题也必须拒绝。默认语义修订器可将确定性拒绝原因回填后有界重试一次，不得无限重试或换模型。
- 父规则冻结原文中的实质性列举项、时间窗、阈值、例外和注释必须逐项进入子规则并保留来源；仅结构化“包括以下情况”等引导语不算覆盖。

## Testing Requirements

- 单元测试：领域值对象、四值逻辑、AND/OR/NOT、子规则 rollup、时间窗、单位换算、日期精度。
- 属性/变异测试：重点验证把 AND 改 OR、阈值运算符变化、未知值传播时测试必然失败。
- 契约测试：JSON Schema、API 请求/响应、Agent 输入输出、PromptVersion 与 SchemaVersion 匹配。
- 临床回归夹具：脱敏覆盖实验室不同指标、否定词、联合条件、例外条件、阶段锚点和溯源提醒。
- 恢复测试：节点重试、任务中断恢复、重复提交幂等、revision 冲突、过期结果拒绝。
- 存储反例：外键绕过、非空绕过、列/正文镜像漂移、创建时间篡改、列表过滤隐藏坏行和部分发布写入回滚。
- 集成测试使用系统实际运行时；当前 legacy 基线为 `/usr/bin/python3`，131 项通过、1 项跳过。

## Code Review Checklist

- 是否把临床语义放进结构契约，而不是项目特异文本规则？
- 未知、冲突和缺失是否仍保持不确定，而非被误判通过？
- Agent 是否越过 gate 直接写最终状态？
- 证据引用能否回到原文件具体位置？
- 重试、重复执行和并发修改是否幂等且不丢历史？
- 是否有针对根因的测试，并覆盖相邻共享逻辑？
- 是否在真实运行时执行测试，而非另一套缺依赖的 Python？

## 事件与证据归属

- Patient Profile 事件若声明 `fact_ids`，事件携带的每个 EvidenceSpan 必须属于这些事实之一；同一审核节点内存在证据不构成事件证据。
- 事件只与规则相关但无事实级定位时，应输出“关联规则资料”关系，不得伪造 `direct` 关系。
- 可点击事件的目标规则组件必须由当前审核节点内 EvidenceSpan 的 FinalAssessment 归属确定，并与前端深链参数一致。
- 回归测试至少包含：事件借用同节点其他事实证据时拒绝；无独立证据时前端无链接；汇总事件的 URL 组件、页面选中项和证据属主一致。

## Phase 5 事实门禁聚合

- 页覆盖、引用闭包、定位和语义门禁必须在整个 `FactNormalizationRun` 上按真实 call 归属合并；同一 candidate+gate 只持久化一个按 `BLOCKED > REJECTED > ACCEPTED` 收敛的结果。单 call 通过不能冒充跨文档闭包通过。
- 事件冲突身份必须包含其引用事实的语义对象；仅用 `event_type` 会把不同疾病、检查或治疗对象的同类型事件误并。
- 临床事实稳定身份必须包含被断言对象；仅用事实类型、数值和时间会把同值同单位的不同检验指标误并。发布事实必须显式保留该对象，不能只藏在肯定/否定断言依据中。
- 冲突成员应通过冲突检测门并并列进入 `ConflictGroup`，不能把“存在冲突”实现为全部成员 `REJECTED`。冲突不择优，但也不丢失可发布事实。
- 来源强度先由完整处理修订冻结的 Phase 4 文档元数据划定允许范围。客观报告、既往原始资料和不可核实资料不得由候选语义抬升；只有同时承载本研究记录与既往史转述的病历类资料，才允许在 `current_study_chart` 与 `screening_record_transcription` 两者之间按候选原句语义区分，仓储层必须再次核对该范围。
- 否定断言必须由当前定位有效原文覆盖完整断言文本，并证明否定词与被断言对象在同一语句；邻近句否定、page-only 定位和沉默均拒绝。
- 同一语句出现否定词仍不充分：否定表达必须直接约束被断言对象；“疾病存在但未治疗”等其他状态否定不得生成疾病否定事实。
- 事件或用药候选声明事实引用后，其证据定位必须属于所引用事实定位的并集；不得借用同审核节点、同调用或其他调用中无关事实的定位。
- 页覆盖门禁必须收到当前运行的真实调用清单；缺少调用上下文时不得以“由上层负责”为由隐式通过。
- Evidence Normalizer 的模型输入除页级有效文本外，必须携带本调用可引用定位的页码、来源层、精度、来源文本哈希和可回放局部原文；只有定位编号而无真实局部原文时，不得要求模型自行猜测引用位置。
- 模型只生成语义草稿和本响应内临时引用。运行编号、调用编号、逻辑文档编号、创建时间、候选稳定身份及断言来源哈希均由系统从冻结输入确定性注入；事件和用药引用必须在持久化前改写为系统候选身份。
- page-only 定位不能支撑具体临床断言；非 page-only 定位缺少可回放局部原文时应在规划阶段失败，不能降级为模型自由摘录。
- 中文资料类型与来源方是正式领域输入，不得只识别英文内部值。冻结元数据负责限定来源类别边界；混合病历中的候选语义只负责区分“当前研究病历直接记录”与“筛选病历转述”，不得把病历中的日期、医院名称或历史叙述升级为既往原始资料。
- 历史迁移的 metadata 快照必须明确排除所有后续新增表，并剥离后续追加列；每次新增迁移都要同步复核各历史版本快照，不能让当前 ORM 结构污染旧版本验收。
- 不可变记录若由 canonical payload 与镜像列共同回放，新增带默认值的合同字段或镜像列必须兼容旧 payload；读取时应与合同解码后的默认值核对，不得把旧正文缺少新增路径直接判为漂移。
- Patient Profile 的定位详情必须按该 Profile 冻结的完整处理修订批量读取；定位缺失、跨修订或不属于冻结闭包时必须拒绝响应，不能静默省略或改用当前活动修订。
- Profile API 复用 Phase 4 定位协议映射，必须返回真实资料版本、页码、定位精度和可回放摘录；只有真实坐标存在时才返回坐标并允许界面画框。
- 同一冻结权威下，事实或事件的稳定语义身份不能因后续运行改变 Profile 泳道而变化；跨运行泳道冲突必须在发布前拒绝，避免重复事实和历时线分叉。

## 方案逻辑的输出形状与原文语义分层

- Agent 紧凑输出层只校验 JSON 形状、值类型、单位、必填字段、完整批次、重复身份和复杂度上限；不得另建一套“包含或/不/非字样即通过”的中文逻辑判定。
- `scalar` 只承载有限数值，`set` 只承载非空字符串分类值且单位固定为 `unitless`；`negated=true` 与 `ne/not_in` 不得叠加造成双重否定。
- ALL/ANY/NOT 只在水合为正式 `RuleExpression` 后由方案发布门禁统一复核。ANY 的每个分支必须能绑定原文中各自的临床术语和真实连接语；“筛选或基线”、‘2次或以上”、“大于或等于”不能为无关替代分支授权。
- NOT 必须由“无、未、否认、不存在”等明确否定直接约束被断言对象；“阴性”是检验分类值，“不良事件”和“非特异性抗体”是完整术语，不能仅因含否定字样而反转整个谓词。
- `ne` 必须绑定原文的“≠/不等于/不是”和具体值；`not_in` 必须绑定“不属于/不在/不包括/非”与具体分类值，不得借用同句其他词的“非”或“阴性”。
- 回归必须同时覆盖正例与误触反例：真实中文临床替代条件保留 ANY，合取条件不得被弱化，节点词/次数阈值/分类结果/完整术语不得触发无关逻辑。

## 方案期别语义与来源闭包

- “未限定某一期”“未区分两期”或正文未出现期别名称只表示未见排他性限定，不能单独证明两期共同适用；跨期共用必须有共同章节结构、明确共用原文或可靠交叉引用等正向依据。
- 方案全局章节不在任何期别专属分支下，且正文明确形成研究要求、限制、操作或人群条件时，可正向支持当前所选期别纳入；这不等于已经证明跨期共用，也不能仅因缺少另一期间共用证据而把当前项目控制降为未决。
- 本期、对侧期或跨期共用的支持来源必须直接指向目标，或通过明确规则标题、表题或交叉引用指向目标所属义务家族；同包内无关段落不能因为期别文字相近而成为支持来源。
- 用户可见中文理由中的引号、括号、书名号和方括号必须成对；不完整句应进入同会话修复。该检查只验证文本完整性，不得扫描医学理由固定词语来替代语义判断。
- 每条 Agent 证据优先引用一个直接结构单元及其自身来源片段；引用多个来源单元时，每个片段必须属于同条证据列出的某个来源单元，不得把标题链或相邻单元片段挂到一个来源单元下。
- `unresolved` 是最终处置，不是候选期别。候选只能是实际期别、共享或无缝候选，并通过未解决证据索引表达缺口；同会话修复仍须返回完整冻结批次。
- 相邻小章节可以为减少模型调用而合批，但不能拆散本可完整容纳的结构段来填满上一个批次；表格、明确期别边界和显式处理屏障不得跨越。旧冻结计划的版本、身份和输入哈希必须可原样恢复。
- 人工控制矩阵重新绑定当前冻结清单时，只允许“来源引用完全相等 + 摘录属于该单元原文 + 唯一命中”的确定性连接；不得按标题相似、邻近位置、行序或项目特异关键词模糊择优。结构单元编号、来源范围、标题路径和清单身份必须一起替换，原始矩阵另存为只读输入。
- 来源闭包、关系闭包和期别闭包分别报告，任何一项通过都不能推导其他项通过。外部关系目标计数只统计实际被关系引用且不在当前矩阵内的唯一目标，不统计允许目标全集。
- 冻结清单未完成全文声明或最终处置时，映射产物必须保持 `claims_complete=false`；旧清单的汇总和执行状态不得混入当前清单的验收证据。
- “同一义务家族”、共同章节边界和期别特异兄弟内容属于 Agent 语义任务；确定性门禁只能核对结构化来源、目标所有权、处置和闭包，不得扫描理由文本是否命中固定词语。结构明确支持选定期别时只能标记为结构支持候选，不得命名为临床语义已闭合。
- 同一完整句内出现并列期别义务时，只能在新分句具有独立主期别，且右侧直接出现新期别或重复同一主语时拆分；“基于某期结果决定另一期间安排”等因果或引用关系必须保持完整，不得因同时出现两个期别名称而机械拆开。
- 相同检查、治疗或操作名称不等于跨期完全共用。只要访视时间、时间窗、阈值、剂量、人群或执行条件不同，就必须分别保留所选期别的实际义务；无法在原文边界内独立闭合时应保持待确认。
- 修复轮收到结构化的“跨期共用缺少正向来源”问题后，必须补充同一义务的有效共同来源，或改为本期、对侧期或待确认；不得原样重复同一无效共同处置和同一不足来源。
- Agent 输出通过 JSON Schema 和水合只证明结构可读，不证明可发布。发布门禁必须在同一会话修复链内运行，并把结构化问题回传给原会话；不得在 Runner 返回后另行发现问题却失去修复机会。
- 局部修复必须以首次完整水合输出为不可变基线，只允许修改原始问题关联的结构单元。范围外候选及处置须逐字段保持一致；任何越界改写均应拒绝，不能因最终问题数为零而接受整批重写。
- 代表组或金标准中的“预期应生成某候选”只用于父级最终验收，不能作为同会话修订错误回传给 Agent。可回传修订的问题必须能由冻结输入、输出合同或确定性发布门禁独立证明；否则会把人工答案泄露给模型并诱发虚构控制点。预期候选遗漏仍须记录并阻断最终接受，但保留 Agent 首轮原始处置供父级核对。

## 场景：证据风险汇总与关闭语义

### 1. 适用范围

- 当证据页、文件或处理修订需要展示风险总数、待核对数，或允许用户关闭风险时适用。

### 2. 接口与存储签名

- 证据快照响应必须提供 `risk_flag_count`、`pending_risk_flag_count` 和可为空的 `upload_job_id`。
- 风险、页审核、校对和页产物仓储必须提供按一组 ID 批量读取的方法；列表投影不得逐页或逐风险调用单条仓储。

### 3. 合同

- 汇总只使用同一证据处理修订内的风险、页审核和校对；其他修订的记录不得影响当前结果。
- `OUTPUT_REPETITION` 等必须整页校对才能消除的严重风险，不得因普通“已阅”记录而计为关闭。
- 校对命中采用半开区间 `[start, end)`；恰在 `start` 或 `end` 边界外插入文字不构成覆盖。
- 关键校对可用完整上下文判断语义，但持久化范围只保存实际变化的最小原文区间。

### 4. 校验与错误矩阵

| 情形 | 结果 |
|---|---|
| 同修订、可人工阅览关闭的风险已有有效页审核 | 计为已关闭 |
| 严重整页重复风险只有普通页审核 | 仍为待核对 |
| 校对与风险区间真实重叠且通过确认门禁 | 计为已关闭 |
| 校对仅触及半开区间边界 | 不关闭风险 |
| 审核或校对属于其他处理修订 | 忽略 |
| 不可变记录正文与镜像列不一致 | 拒绝投影，不得静默漏计 |

### 5. 正常、边界与反例

- 正常：两页风险使用一次批量加载得到与逐条计算相同的计数。
- 边界：空风险集合返回两个零值，不制造虚假待办。
- 反例：严重整页重复只有“已查看”时显示为已处理；这是错误实现。

### 6. 必需测试

- 一页与多页快照的 SQL 查询数保持常数级，并断言不超过既定上限。
- 覆盖严重整页重复、普通可阅风险、区间内部校对、左右边界插入和跨修订污染。
- 覆盖镜像漂移、原文哈希不一致和处理中快照 `upload_job_id` 的真实任务深链。

### 7. 错误与正确实现

- 错误：`resolved = reviewed or corrected`，把所有风险视为相同关闭条件。
- 正确：先由风险类型决定允许的关闭方式，再在当前处理修订内批量核对有效审核或真实重叠校对。

## 跨章节方案控制点的语义增量

- 时间窗口必须结构化保存大于、小于及边界是否包含；`>N`、`>=N`、`<N`、`<=N/N以内` 不得退化为同一闭区间。可定位到语义原子时，缺少命名时间锚点的错误必须包含原子身份和原句，候选级错误只能作为无可识别原子时的兜底。
- 同一来源先给一般访视、时间窗或基线取值规则，随后对明确列举项目规定更精确节点时，后者是前者的特例。较宽窗口不得传播到特例项目；冻结流程目录已在精确节点覆盖特例时，不得重复建立义务。
- 时间相关义务必须先区分语义对象：访视安排作用于冻结流程节点，检查结果有效期作用于精确流程必做项，基线值选取作用于通用流程节点或精确检查项。三者不得用通用“完成/核对”承载；通用基线原则与具体检查特例不得混在同一候选中。

- 补充候选必须表达正式入排标准或既有流程目标尚未覆盖的真实义务增量；不得为了保持叙述完整而复制已覆盖的检查、排除条件或操作。只有共同后果为新增时，应保留原条件分支并将其显式绑定到该共同后果。
- 条件、义务、例外必须分层表达。即使只有一个条件-操作句，也必须建立唯一触发分支并绑定后果；“除非、除外、例外”出现在本候选引用的语义内容时必须进入例外层，不能只留在义务文字中。
- 例外门禁只检查候选自身引用的陈述和逐字摘录，不得因同一来源段落的兄弟候选包含例外而误拦当前候选。
- 同一 DNF 合取组不得出现去除系统身份后语义完全相同的重复原子。重复身份检查不能替代重复语义检查。
- “可、允许、可以”等选择性操作必须在义务陈述中保留选择性语气；不得改写为无条件必做。
- “不得随机、不得首次给药”等描述锚点事件本身的禁止义务使用 `direction=on`；事件前的治疗、洗脱或结果有效窗须由独立直接来源表达。
- 筛选期当前应完成的操作与基线、随机或首次给药前才能最终判定的有效性要求必须拆为不同控制点，分别绑定真实审核节点。
- 同一来源单元同时包含已知目标已覆盖分支和唯一新增分支时，不得为了保留整段叙述而重复发布已覆盖内容；候选仅保留新增分支，其余分支逐项记录为已覆盖。
- “无需、不要求、可免于检查”是适用豁免，不是“禁止发生检查”；不得用 `prohibit_event` 表达豁免。
- 首次给药后、治疗期间和退出访视的常规操作不属于基线及以前的入排控制。若同段还包含筛选或首次给药前控制，应先按决定阶段拆分，不能让后续操作污染当前候选。
- 确定性门绿色只证明合同可发布，不等于父级临床接受。父级核对发现重复控制、阶段弱化或语气强化时，必须保留绿色结果为反例并继续阻断发布。
- 连续修订反复出现同一问题指纹或相同响应时，应判为当前输入/输出契约非收敛，停止增加重试；下一步改变来源分解或预分类合同，而不是继续堆叠提示词。
- 补充控制若改变已知必做项的适用人群、豁免、阈值或不满足后果，其审核绑定和最低证据到期节点不得晚于该变化首次影响的流程节点；只绑定更晚的基线、随机或首次给药前节点会遗漏较早筛选控制，必须由结构化关系与节点目录共同阻断。
- 方案原文中的动作主体、实际动作和完成强度必须分别保真。“建议参与者休息”要求核对实际休息这一准备动作，但未记录不得被强化为必备资料，也不得改写成仅核对是否已告知建议；“尽量”同理不能变成硬性先后条件。
- 正式义务、最低证据和用户审核指引必须覆盖同一列举项与同一阶段集合。显示时拆分收缩压/舒张压可以形成五个读数，但不得把方案的四类生命体征项目误称为五项检查；关系新增动作或要求时不得降为普通解释。
- 一个原文结构单元若由多个访视级流程目录项共同完整覆盖，当前处置必须显式保存全部目录身份并按 ID 排序去重；只保存最早或最后访视会形成不可见的来源闭包缺口。历史单值字段只用于旧快照读取，新输出不得与多值字段同时使用。
- 流程目录项的来源摘录范围不得大于其访视身份。共享的跨访视说明可以作为共同来源，但必须另有结构化访视归属，发布时用链接目录项的访视集合核对处置所声称的覆盖范围；不能因筛选、基线和首次给药前目标携带同一整段说明，就推断它们也覆盖 W12、提前退出或其他治疗后访视。审核阶段相同也不等于节点相同，首次给药前节点不得退化为一般基线节点。
- 同一水合结果若同时存在发布合同问题和临床拒绝问题，修复前必须汇总两类问题涉及的全部结构单元与候选。逐个失败即返回会把尚未暴露的错误冻结为修复基线，导致模型在不同缺陷间反复摆动。
- “自筛选访视以来”“自上次访视以来”只定义回顾区间起点，不定义当前操作在哪个访视执行。已知流程事项必须另存冻结执行访视；发布门禁同时拒绝漏绑和额外绑定，不能用相同审核阶段、访视可合并或宽摘录替代精确节点。
- 上游已冻结为流程必做事项的单元不得改成普通补充说明、非控制或治疗后事项来规避访视闭包。该身份与执行访视必须由结构合同传入，不解析模型理由。
- 同一访视的流程目录目标应声明稳定资料家族。独立结构期望只进入确定性门禁，不进入 Agent 首轮输入；门禁核对并列资料家族是否全部链接，不得通过中文关键词、项目目录编号或人工金标准直接生成链接答案。

## 本地严格结构化输出

- MTPLX 的严格 JSON Schema 请求必须显式使用自回归解码。不得依赖守护进程环境变量、提示词缩短或重启后的临时状态规避推测解码与语法状态失步。
- 方案解构、跨章节控制、期别适用性和证据规范化使用同一传输约束；DeepSeek、oMLX 和非严格结构化请求不得被连带改写。
- HTTP 200 不是结构化输出成功证据。正文必须非空、可解析为目标 Schema，并通过对应产品门禁；空正文、自由文本或只含推理内容均按失败处理。
- 真实运行证据应记录严格结构化生成模式，避免仅凭当前代码路径反推历史请求参数。父级临床验收以独立追加决策文件表达，不回写原始响应、运行摘要或门禁工件。
- `recommended` 和 `best_effort` 义务在未来受试者判定引擎中只能形成提示或复核事项；不满足不能自动转成证据缺口、不符合或排除结论。
