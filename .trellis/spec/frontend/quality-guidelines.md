# Quality Guidelines

> 前端完成标准是医学监查员在真实浏览器中能看懂、能定位证据、能恢复任务，而不仅是构建通过。

## Forbidden Patterns

- 可见区域出现英文技术术语、内部枚举、模型名、日志或程序错误堆栈。
- 整页横向滚动、无意义换行、文字与控件重叠、按钮内容被裁切。
- 依赖固定屏幕像素尺寸或 viewport 字号缩放适配单一设备。
- 只用颜色表达结论；把“证据不足”和“需研究者判定”合并为“待补证”。
- 点击复选框、排序或筛选导致页面跳顶、选择丢失或打开错误受试者。
- 父子规则同层展示、阶段结论混成一个状态或证据无法回到原文。

## Required Patterns

- 所有页面有明确的任务标题、当前位置、主要下一步和可恢复状态。
- 已发布的方案任务直链显示正式版本只读摘要和“重新解构此项目”入口；完成后清除本机的“继续上次任务”记录，不得把历史检查点当成中断任务。
- 受试者列表直接展示各审核阶段入口和状态；每列支持适当筛选、排序。
- Patient Profile 首屏突出入排相关、异常、临界、趋势和潜在风险，完整资料按类展开。
- 原始文件、OCR 文本和规则证据联动，高亮定位并显示引用来源。
- 原件重点框默认不显示；用户选择具体定位后只显示当前一个。描边绘制在真实定位区域外侧、内部透明，短数字和日期在 1080P 下也不得被边框覆盖；纯标点风险可保留在风险核对中，但不单独进入通用原件定位清单。
- 批量操作仅作用于明确勾选范围，执行前显示数量和动作，执行后保留结果摘要。
- 图标按钮有工具提示；危险动作有明确对象、影响和可恢复边界。
- 页面内吸顶上下文带必须避开全局顶栏，并在滚动后的真实浏览器中验证两者可见且不重叠；只看静态首屏截图不足以验收。

## Testing Requirements

- 组件测试覆盖加载、空、部分失败、只读、stale、冲突和权限无关的单用户状态。
- Playwright 覆盖项目创建、方案解构、上传、OCR、分阶段审核、证据跳转、override、报告和任务恢复。
- 产品只面向最大化宽屏桌面；视觉验收至少覆盖 1920×1080、2560×1440、3840×2160，浏览器缩放 100%、150%、200%，不新增移动端或窄屏专用流程。
- 检查页面无横向溢出、文字裁切、重叠、布局跳动和空白宽度浪费。
- 键盘导航、焦点恢复、表单标签、对比度和基础 axe 检查必须通过。
- 对全部可见文案执行中文词汇审计，禁止技术日志式措辞。

## Code Review Checklist

- 医学监查员能否在首屏知道当前对象、阶段、风险和下一步？
- 关键证据是否能在 3 次操作内定位到原文件？
- 桌面流式布局是否基于内容约束而非某张截图的固定尺寸，并能在1080P至4K充分利用宽度？
- 列表排序、筛选、勾选和增量更新是否保持稳定 ID、滚动和焦点？
- 状态是否准确区分证据不足、研究者判定、溯源提醒和后续复核？
- 是否在真实浏览器和实际用户视口截图确认，而非只读 CSS？
- Patient Profile 入口是否准确区分事件原始依据、判断依据和关联规则资料？没有事件级定位时是否诚实显示不可定位，而不是借用同节点其他证据？
- 深链中的受试者、审核节点、规则组件和 EvidenceSpan 是否在异步数据加载完成后仍保持同一上下文？桌面视口测试不得在页面上下文尚未加载时判断标签是否存在。
- 规则树若为降低视觉负担默认只展开当前父项，端到端用例必须先执行真实的“展开父项”动作再定位子项，不得倒逼界面恢复全部默认展开。
