# Component Guidelines

> 组件必须支持高密度临床审阅，同时让不熟悉系统的用户无需理解技术实现。

## Component Structure

- 页面组件只编排工作区；业务状态、数据加载和动作放在 feature hook/model 中。
- 优先组合小而明确的组件：阶段状态、规则树、证据片段、原文查看器、时间轴、待办动作。
- 同一事实只由一个组件拥有编辑权，其他视图通过 ID 和 revision 同步。
- 加载、空数据、部分失败、只读、过期和冲突状态必须是组件显式状态。
- 层级较长的规则树默认只展开当前选中父项；深链或程序化切换到子项时必须自动展开其父项，不让已选内容隐藏在折叠层。

## Props Conventions

- Props 使用命名 `interface` 或 `type`，禁止 `any` 和含义不明的布尔参数堆叠。
- 传稳定 ID、领域值和动作回调，不传整套 API 响应或全局 store。
- 复杂组件用判别联合表达状态，避免 `isLoading/isError/isEmpty` 同时为真。
- 事件名称表达用户动作，如 `onOpenEvidence`、`onRequestSupplement`，不用 `onClick1`。

## Styling Patterns

- 使用 CSS Grid/Flex、`minmax()`、`clamp()` 的间距约束、容器查询和自然换行；不按某台显示器写死大段像素宽高。
- 页面主体充分使用宽度且不出现整页横向滚动；原文、规则树等专业工作区可在组件内部滚动。
- 卡片圆角不超过 8px，不嵌套装饰性卡片，不使用营销式 hero、渐变球或单一色调铺满界面。
- 表格列由内容优先级和响应式约束分配；中心代号为主、全名用次级小字，操作使用图标和工具提示。
- 图标优先使用项目选定的图标库；状态不能只靠颜色，必须同时有文字或图标。

## Accessibility

- 所有输入有可见标签；图标按钮有 `aria-label` 和中文工具提示。
- 键盘可到达上传、规则选择、证据跳转、日期选择和主要动作。
- 焦点样式清晰，弹窗关闭后焦点返回触发位置，勾选不得导致页面跳顶。
- 支持浏览器 100%、150%、200% 缩放，文字不得裁切或覆盖。
- 异常、临界和风险使用文字含义，不仅依赖红绿颜色。

## Common Mistakes

- 把父规则和子规则渲染成同一层级，丢失 AND/OR 关系。
- 在受试者列表只显示一个结论，隐藏筛选期与基线期入口。
- 把批量操作说明永久占据页面，而不是在上下文中按需提示。
- 为适配单一截图写死容器宽度，导致高 DPI、缩放或4K桌面出现裁切与大块空白。
- 在页面显示“重新跑 pipeline”“模型返回失败”等技术日志式文案。
