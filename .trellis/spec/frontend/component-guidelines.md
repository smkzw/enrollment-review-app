# Component Guidelines

> 组件必须支持高密度临床审阅，同时让不熟悉系统的用户无需理解技术实现。

## Component Structure

- 页面组件只编排工作区；业务状态、数据加载和动作放在 feature hook/model 中。
- 优先组合小而明确的组件：阶段状态、规则树、证据片段、原文查看器、时间轴、待办动作。
- 同一事实只由一个组件拥有编辑权，其他视图通过 ID 和 revision 同步。
- 加载、空数据、部分失败、只读、过期和冲突状态必须是组件显式状态。
- 层级较长的规则树默认只展开当前选中父项；深链或程序化切换到子项时必须自动展开其父项，不让已选内容隐藏在折叠层。

## Props Conventions

- Props 使用命名 `interface` 或 `type`，禁止 `any` 和含义不明的布尔参数堆叠。
- 传稳定 ID、领域值和动作回调，不传整套 API 响应或全局 store。
- 复杂组件用判别联合表达状态，避免 `isLoading/isError/isEmpty` 同时为真。
- 事件名称表达用户动作，如 `onOpenEvidence`、`onRequestSupplement`，不用 `onClick1`。

## Styling Patterns

- 使用 CSS Grid/Flex、`minmax()`、`clamp()` 的间距约束、容器查询和自然换行；不按某台显示器写死大段像素宽高。
- 页面主体充分使用宽度且不出现整页横向滚动；原文、规则树等专业工作区可在组件内部滚动。
- 卡片圆角不超过 8px，不嵌套装饰性卡片，不使用营销式 hero、渐变球或单一色调铺满界面。
- 表格列由内容优先级和响应式约束分配；中心代号为主、全名用次级小字，操作使用图标和工具提示。
- 图标优先使用项目选定的图标库；状态不能只靠颜色，必须同时有文字或图标。

## Accessibility

- 所有输入有可见标签；图标按钮有 `aria-label` 和中文工具提示。
- 键盘可到达上传、规则选择、证据跳转、日期选择和主要动作。
- 焦点样式清晰，弹窗关闭后焦点返回触发位置，勾选不得导致页面跳顶。
- 支持浏览器 100%、150%、200% 缩放，文字不得裁切或覆盖。
- 异常、临界和风险使用文字含义，不仅依赖红绿颜色。

## Common Mistakes

- 把父规则和子规则渲染成同一层级，丢失 AND/OR 关系。
- 在受试者列表只显示一个结论，隐藏筛选期与基线期入口。
- 把批量操作说明永久占据页面，而不是在上下文中按需提示。
- 已保存且覆盖数量完整、没有关闭范围/失败/缺报/重试的识读状态可默认收起，用原生可展开详情保留原信息；“已保存”不改成“已核实”。失败、未知和处理中状态不能因completed标签而折叠隐藏。折叠内容仍在DOM，测试应核实际可见性及用户展开动作。
- 为适配单一截图写死容器宽度，导致高 DPI、缩放或4K桌面出现裁切与大块空白。
- 个例不为短受试者列表常驻留列：`SubjectsPage`节点栏内切换受试者，默认分类时间线；原件点开共享`EvidenceReader`原生dialog。关闭回焦点并保留分类／展开；切换对象清除旧来源。全局导航默认图标轨，悬停／聚焦叠加展开，可固定；核对页列表＋详情不被常驻原件挤压。验证须包含实际长页面与关闭返回，不能只看首屏。
- 在页面显示“重新跑 pipeline”“模型返回失败”等技术日志式文案。
### Clinical Profile Display

Profile正文用于入排要求、检验检查、病史时序及方案控制点，不是OCR字段转储。普通报告医师/申请医生姓名、打印信息、页码只留原件和原始记录；展示过滤不得删除事实、来源索引或历史。仅精确识别的行政字段可以省略，不能靠包含“医生”等字样隐藏研究者书面判断、CS/NCS、临床日期或未知含义。关联规则、事件、冲突、高亮或来源待核的条目保留。显示计数按实际可见条目，原始记录数不改。

### 规则审定（0.2.0）

1. 范围：`ProtocolRuleReviewPanel` 的显示分类／重点只来自当前草稿、绑定、来源和检查提示，不改变规则或医学语义。表格整体 `page_only` 可无单独摘录；具体来源缺失仍提示。
2. 接口：`POST /api/v2/protocol/deconstructions/{job}/draft/reviews`；单条 POST/DELETE 共享 `review_rules` 事务路径。
3. 输入／输出：请求 `expected_revision_id, reviewer_kind, entries[{official_code,rule_content_hash,note,result_variables}]`；返回当前审定清单与追加历史。前端不得把多选变成无条件全选，不自动发布。
4. 错误：空集合422；重复、旧修订、错条目／哈希、未知变量409；任一失败全批不写。相同已审定身份／内容／设置重试不追加事件。
5. 正／常／反例：合法勾选一次保存各条记录；有疑点条目列出理由由本人核对；任一过期条目拒绝整批。原文高度相似不证明组合逻辑正确，结构清楚不等于医学正确率。
6. 验证：`test_rule_reviews_api.py` 核原子失败、幂等、验证身份；`ProtocolRuleReviewPanel.test.tsx` 核分类／筛选／明确确认／空详情；`protocolRuleReview.test.ts` 核来源、绑定、101项和显示单位。实际 Ego 核宽屏、条件树与确认取消，不能替本人正式批准。
7. 错／对：错误是只展示摘录并标“AI准确率高”；正确是展示真实全部／任一／否定、时间、例外、计算及具体疑点，完整原文按需展开，审定始终绑定当前内容。
8. 疑点处理：`ruleReviewAdvice(item, content)`只给有源核对方向，不直接改稿；局部观察任选不等于整组任选，无依据不强推。`onEdit(componentId, mainOperator?)`打开既有手工弹层，首次／修订入口均可用；初始化子项与条件必须一致，取消无写入，数字无效明确报错，不回填旧值。实际保存沿editDraft追加修订，改动条款审定失效；原文／兄弟／历史不得顺带改写。
9. 信息层级：默认显示条款、子项组合与状态；长分析／资料说明／历史按原生details展开。多子项备选仅默认打开首组，其他组独立展开；每组用同一行A/B/C、当前解释及有源推荐标识，说明改变组合后的实际影响，不把常规“或”当作解析错误。结构性阻断、真实冲突和下一动作不能藏进一般提醒。
10. 来源去重：`displayProtocolSourceLocators(sourceSpans, refs)`仅用于展示；同快照、同结构位置／页／坐标／摘录／精度及降级原因都相同才折叠。无位置身份只能按原ref去重；不同页、单元、版本或坐标保留。`mapProtocolSourceLocators`与存储分母不变；手工预览只读摘录可精确文字去重，不删除其绑定。同页共用位置标题，但每处原文仍可查看。
11. 病例结果：低置信为简短标记与可选悬停说明；`ReasonText`只按中文句界分段并加粗已有冒号前项目名，不推断逻辑、不删限定语或数值、不改变原文。分点需显式设置list-style，不能被全局reset隐藏。关联事实、核对方式及工作稿操作可下钻；默认列表＋宽判断，原件按需侧栏，所选对象／筛选／原件上下文保持。查看器“定位当前查看页”只重新滚动；“返回本条依据页”恢复真实依据，浏览其他文件时不显示旧引用摘录。
12. 构建自主性与阅读密度（D22）：验证流程使用`builder_verification`，不要求本人逐条验构建；正式身份不自动切换。审定页计数区分待审与有效已审，未改内容不重复批准。正常低置信组可查但默认收起，不与风险／未决混算成“必须处理”；判断、置信及队列成员不改。
13. `ReasonText(text, compact)`只按原句界将首句置主层、剩余句置原生details（超过两句时），不生成新摘要；待核条件标题、结论、动作仍可见。来源展示只合并相同完整引用，不合并不同版本／页／摘录／处置；纯检索范围另展开，无摘录的unresolved不得称已核对未见。选择来源后同时切换摘录和页面、收起引用列表让出原件空间，不借用其他事实坐标；返回恢复原依据。组件正反例覆盖正文保留、去重边界、选中摘录、状态、来源页与返回。
14. 备选radio不直接写审定：保留现状须明确确认；变更进入既有编辑预览／保存。未保存或暂缓选择在切换条目后仍阻断包含它的批量批准；不阻断无关条目。普通档案来源仅铺开当前摘录、其他依据选择可达，定位说明下钻；冲突来源仍并列，不用折叠掩盖不一致。
