# State Management

> 前端不复制后端临床事实，只保存显示和交互所需的最小状态。

## Overview

- 服务端是项目、方案、规则、受试者、审核、证据、待办和 Job 的事实源。
- URL 保存可分享/恢复的工作上下文；组件保存短生命周期的显示状态。
- 状态库是否引入在 Phase 0.5 基于实际复杂度决定，不预先建立全局大 store。

## State Categories

| 类别 | 内容 | 位置 |
|---|---|---|
| 服务端状态 | 项目、版本、受试者、ReviewEpisode、规则判断、ActionItem、Job | API repository/cache |
| URL 状态 | 当前项目、受试者、审核阶段、规则、证据文件 | 路由和 query 参数 |
| 本地交互 | 面板宽度、展开项、临时勾选、未提交表单 | 最近共同组件 |
| 派生显示 | 过滤后列表、状态标签、风险数量 | selector/memo，禁止持久化副本 |

## When to Use Global State

仅当状态跨多个无共同父级的功能域、不能由 URL 或服务端恢复，并且确实需要同步时才提升为全局。主题 token、通知队列等可全局；当前受试者和审核阶段优先放 URL。

## Server State

- 查询键包含资源 ID、阶段、版本和 revision 所需维度。
- mutation 成功后按返回的新 revision 精确更新或失效，不整页刷新。
- 一次可重试的确认动作必须在其完整生命周期内复用同一幂等键；只有创建新的候选或用户明确取消后，才能生成新键。响应中断不得把用户重试变成另一项写入。
- 临时预览、草稿或候选不能只清空前端引用。切换方式、重新选择资料或移除文件前，必须先确认服务端取消成功；清理失败时保留原候选和恢复入口。
- 离开页面不取消后台 Job；Job 状态由服务端持久化，重新进入可继续查看。
- 人工 override 使用显式 mutation，并展示被替代状态、理由和审计记录。
- 不从多条规则在前端重新计算总体结论；使用后端确定性 rollup 结果。

## Common Mistakes

- 在组件、URL 和全局 store 同时保存当前受试者，造成选择漂移。
- 保存过滤后的数组副本，原数据更新后不一致。
- 用浏览器本地存储保存临床事实或完整受试者资料。
- Job 进度仅存在内存，刷新页面后丢失。
- mutation 后全量重新加载，导致焦点、滚动和勾选状态丢失。
- 用审核节点修订号、列表长度或创建时间猜测当前资料版本；当前版本必须来自服务端活动指针或明确的活动状态投影。
