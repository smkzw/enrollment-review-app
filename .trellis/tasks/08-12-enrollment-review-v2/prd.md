# 入排审核系统 V2 分阶段构建

## Goal

基于最终设计完成本地单用户、AI lead、多 Agent 协同但确定性门禁裁决的 V2 系统，并通过真实临床回归与浏览器验收。

## Requirements

- 本机单用户使用，删除登录流程，启动后直接进入“今日工作”。
- 方案及现行修订案是授权基座；Q&A、澄清函、邮件和医学解释仅在不违背现行方案时作为补充权威来源。
- II/III 期分别解构为独立研究、独立项目和独立受试者集合。
- 方案解构覆盖 IN/EX 原条目、逻辑子组件、预筛/筛选/基线前必做检查、评分、操作及时间冲突；原编号和数量与方案一致。
- Agent 负责语义候选，RuleExpression、EvidenceRequirement、Gate、确定性 evaluator 和 rollup 负责最终状态。
- 同一受试者支持全量上传和增量上传；不同审核阶段使用独立 ReviewEpisode，后期资料不得静默改写早期资料结论。
- Patient Profile 汇总基本情况、疾病历程、症状、诊断、病史、用药/治疗、手术、检验、检查、评分、特殊经历及证据时间轴，并标记入排契合点和风险。
- AI lead：对于不满足、模棱两可或证据不足，给出具体责任方和需要补充的资料或描述；不作为最终入排决策系统。
- 所有可见文案使用医学监查员可理解的自然中文，不展示程序、模型或日志术语。
- 旧项目仅作为只读回归锚点；V2 从头创建新项目和新持久化模型。
- 每阶段有独立退出门槛，Phase 1.5 量化 UAT 未通过不得开始 Phase 2。

## Acceptance Criteria

- [ ] Phase 0 至 Phase 9 均有版本化产物、测试证据、浏览器验收和停止点。
- [ ] 方案、证据、事实、判断、行动、报告均可追溯到版本与原文件定位。
- [ ] 所有 Agent 输出经 Schema/Gate；Agent 不能直接写最终审核状态或自动选择冲突证据。
- [ ] 已知“和变或”、指标串项、否定词误读、例外条件错配、时间锚点误用等回归样例零复发。
- [ ] 筛选期、基线期等阶段在列表和个例工作台中直接可见且互不污染。
- [ ] Patient Profile 代表个例逐事件与原始资料核对通过，首屏突出入排相关、异常、临界和趋势。
- [ ] 核心旅程在真实浏览器完成，页面级无横向滚动，关键证据不超过 3 次操作可达。
- [ ] 全量/增量上传、8 路 OCR、OCR 与 LLM 流水并行、任务恢复、批量操作和报告导出通过测试。
- [ ] 旧项目和旧报告未被 V2 写路径修改；切换前保留明确回滚能力。
