# Phase 3 切片 8 独立医学监查员试用合同

## 目标

由三名彼此独立、没有参与实现的测试者，以“专业但不愿学习技术细节的中文临床试验医学监查员”身份，真实使用方案解构工作台。测试重点不是页面能否打开，而是两份真实方案能否形成临床语义正确、来源可追溯、期别独立、可审阅和可发布的规则草稿。

## 指定测试者

1. CodeBuddy CLI：`hy3`，推理强度 `max`。
2. Pi：`cms-router/minimax-m3`。
3. Grok Build：`grok-4.6`，推理强度 `medium`。

每一路先做真实连通性测试，再启动正式试用。用户指定的 harness、provider、model 和推理强度必须原样尝试；不得因目录预检、等待时间或单次告警静默替换。

## 测试范围

### 必须完整试用

- 首次方案解构入口、上传、自动提取方案信息、研究期别确认。
- MG-K10-SAR V2.1 仅选择 III 期；父规则应为 IN 7、EX 16。
- D001 V1.0 仅选择 II 期；父规则应为 IN 6、EX 30。
- 规则树父子层级、全部满足/任一满足/例外、时间锚点、数值阈值、研究者复合判断。
- 基线及以前必做检查、检验、评分和再次核查的访视实例覆盖。
- 方案原文、规则、来源定位三者联动；不得用标题或页眉冒充具体依据。
- 完整性问题能否准确指向受影响规则及来源。
- 保存草稿、取消、手工修改、按反馈修订、并列比较、发布或阻止发布。
- 重新解构入口、项目选择、当前正式版本保护、差异展示和版本追加。
- 1920x1080、2560x1440、3840x2160 宽屏下的布局、信息密度、中文自然度和操作效率。

### 当前阶段明确不包含

Phase 3 不实现受试者资料上传、OCR、ClinicalFact、Patient Profile、实际入排判定和报告导出。这些属于 Phase 4-6。测试者可以确认导航不会把未实现能力伪装成已完成，但不得把本阶段边界写成方案解构缺陷，也不得声称已完成受试者端到端审核。

## 独立性与允许操作

- 测试者只读访问仓库代码、任务文档和工作区内的方案副本。
- 测试者不得修改源代码、测试代码、任务文档或原始方案。
- 测试者可通过浏览器在分配给自己的清洁 SQLite 数据根中创建、保存、发布、取消或删除测试项目。
- 每名测试者使用独立端口、独立数据根和独立截图/报告目录，不能读取或覆盖另外两名测试者的运行数据。
- 不测试登录、多用户权限、移动端或安全攻击面。

## 发现问题的证据要求

每项发现必须包含：

1. 严重程度：阻断 / 高 / 中 / 低。
2. 页面与具体操作步骤。
3. 预期表现和实际表现。
4. 方案条款、规则编号或来源定位；视觉问题需附截图。
5. 判断其为共享机制问题还是单次模型波动的依据。
6. 对不确定内容明确写“尚未证实”，不得凭感觉下结论。

遇到零规则、数量不符、空必做目录、错误期别、来源断裂或异常临床语义时，立即深挖到最早出现偏差的步骤，不得继续点击并把后续页面能显示当作通过。

## 交付格式

每名测试者输出一份中文 Markdown 报告，至少包括：

- 实际 harness、provider、model、推理强度、会话标识和耗时。
- 实际浏览器、URL、视口与被测数据根。
- 两份方案逐流程记录与关键计数。
- 医学逻辑、来源、流程覆盖、中文、视觉和交互分项评价。
- 可复现发现，按严重程度排序。
- 明确通过项、未验证项、阶段外能力。
- 最终建议：接受 / 修正后接受 / 阻止进入下一阶段。

测试者只能提出建议。Codex 负责复现、共享根因判断、修复、回归和最终接受。

## 等待、停止与清理

- 正式试用单路硬等待 100 分钟；运行中无输出或状态未变化不构成失败，不轮询、不重复派发。
- 仅在终止状态、明确运行时失败或硬等待返回后检查结果。
- 修复后的复测必须使用新鲜上下文和新数据根。
- 接受后只保留精简报告、必要截图、模型调用记录和决定性测试输出；删除重复浏览器缓存、构建缓存和可再生数据库。
