# Phase 4 证据快照、上传与 OCR V2

## 目标与用户价值

为单机、单用户的入排审核系统建立可信的受试者资料底座：医学监查人员能够在明确的受试者和审核节点下，选择“补充资料”或“建立完整资料快照”，先看清文件去重、替换和处理范围，再确认上传；系统保存不可变原文件、页图、原始识别结果、校对记录和真实定位精度，并能在中断或部分失败后继续处理。

本阶段只回答“本次审核实际使用了哪些资料、每一页识别成什么、证据能精确定位到哪里、哪些识别结果需要核对”。临床事实归一化、Patient Profile、逐条入排判断和行动闭环分别由后续 Phase 5、Phase 6 实现。

## 已确认背景

- Phase 3 已建立项目、方案版本、研究期别、审核节点和规则发布基座；Phase 4 必须沿用这些作用域，不回写旧系统项目。
- 同一受试者可以选择增量或全量上传；不同审核节点保留独立快照，后续节点资料不得静默改写早期结果。
- 原始文件和原始 OCR 永不覆盖；校对另存并记录原因、确认动作和影响范围。
- OCR 全局并发上限为 8；浏览器关闭不应取消已确认的后台处理。
- 产品只面向 1080P 至 4K 最大化宽屏桌面，不设计移动端或窄屏变体。
- 所有面向医学监查人员的页面文字使用中文临床试验语境，不展示模型名、字段名、运行日志或程序员术语。

## 范围内需求

### P4-R01 受试者与审核节点作用域

- 每次上传必须绑定一个项目、受试者和审核节点。
- 新资料只能进入所选审核节点的候选快照；不得跨受试者、跨项目、跨研究期别或跨节点串入。
- 页面持续显示当前项目、受试者、审核节点和现行方案版本，防止用户在错误对象下操作。

### P4-R02 两种上传方式与确认前预览

- 用户可明确选择：
  - “补充资料”：在上一有效快照的完整文件集合上合并新文件；
  - “建立完整资料快照”：本次所选文件构成新的完整集合，不继承上一快照。
- 选择文件后先生成预览，不立即进入正式快照。预览逐项显示新增、内容重复、名称相同但内容不同、不支持、无法读取和预计需要重新识别的文件。
- 名称相同但内容不同的文件不得自动覆盖。用户必须选择“作为原资料的新版本”或“作为另一份资料并列保留”；新版本建立明确的逻辑资料版本关系，旧版本只留在历史快照中。
- 只有用户确认后才创建正式处理任务；取消预览不得留下临床快照或活动任务。
- 首版支持 PDF、DOCX、DOC、TXT、JPG、JPEG、PNG、BMP、TIFF、TIF、WEBP；压缩包明确提示暂不支持，不静默展开。
- PDF 保留原始分页；DOCX/DOC 经版本固定的 LibreOffice 派生 PDF 后分页；TXT 按原始行序形成单个无坐标文本页；TIFF 每个 frame 为一页，其他图片为单页。每条路线保存渲染器/解码器版本、派生物哈希、页图输入哈希和失败原因。
- 全量方式仍保留旧快照，并展示本次与上一有效快照的差异基线。

### P4-R03 内容身份、去重与文件版本

- 文件内容以 SHA-256 为身份；相同内容在存储层只保存一份原始二进制，但可在不同受试者、节点或快照中形成各自可审计的资料关联。
- 同一内容、同一页、同一识别配置不得重复 OCR；文件内容或识别配置变化必须产生新的识别结果。
- 文件名不能作为内容身份或缓存键；重复上传不得生成重复快照成员、重复页记录或重复处理任务。

### P4-R04 不可变证据快照与阶段隔离

- 已确认快照及其成员集合不可原地改写或物理删除。
- “补充资料”快照必须有且只有一个前序快照，并继承前序仍有效的逻辑资料版本和本次新增成员。经用户确认被新版本替代的旧版本不再进入新快照活动成员，但其原文件、旧快照成员和替代关系永久保留。
- “建立完整资料快照”不继承前序成员，但保存与上一有效快照的比较关系供用户回看。
- 同一作用域、上传方式和活动成员集合再次确认时返回既有候选或活动快照并记录重复请求，不生成内容完全相同的新快照。
- 候选快照只有在所有发布门禁通过后才成为审核节点的活动快照；发布必须带打开时的修订号，避免并行窗口互相覆盖。
- 活动资料不仅固定文档集合，还必须固定一份不可变“证据处理修订”，逐页指向实际 PageArtifact、OCRProfile/OCRPage、定位器版本和当时生效的 CorrectionRecord。后续校对只能产生新的证据处理修订，旧修订回放结果不变。
- 候选快照、证据处理修订和激活事件使用明确状态机。取消、可重试失败、终止失败、待核对、修订冲突、激活和回滚均追加记录；回滚通过新的激活事件完成，不静默改写指针。
- 页面或任务失败时，上一有效快照仍可使用；失败候选不得伪装为最新完整资料。
- 候选失败或取消不得把上一有效快照及其既有审核结果标成“需要更新”；只有新的快照/处理修订成功激活后，基于旧活动版本的当前投影才可标记为“已有更新版本”，历史结果仍可复现。

### P4-R05 文档分类、页清单和被引用资料

- 每个文件保存用户可改的资料类型、来源方、审核节点和页清单；自动分类必须显示为建议而非既定事实。资料类型、来源方等元数据不得原地改写，用户修改时形成新的不可变元数据修订。
- PDF/多页图像必须校验页数和每页处理状态；任一页失败时，文件显示部分失败及失败页，不得把成功页当作完整文件。
- 病历中明确提到但本次未提供的检查报告、既往病历或其他资料，可登记为“资料中提及但未提供”，并保留触发它的原文位置。
- Phase 4 只允许用户手工登记，或由确定性文本模式生成“待确认候选”；用户可确认、修改、解除或把后续上传文件关联为已提供。自动临床事实抽取、规则影响和入排判断不得在此步骤发生。

### P4-R06 页级 OCR、缓存与全局准入

- 每页保存识别配置、不可变原始请求/响应工件、原始识别文本、布局结果、页图、质量指标、开始/结束时间、失败原因和尝试历史。
- 缓存键至少包括文件内容哈希、页码、识别模型/参数版本和页面渲染版本。
- 全局最多同时执行 8 个真实外部 OCR 推理请求；页面、裁剪块或布局流水线每发起一个实际模型请求均占用一个共享 oMLX OCR 租约，本地解码/布局计算不占该额度。限制必须跨任务、跨受试者和应用重启生效，不能只依赖单进程内信号量。
- 数据库工作项租约只防止同一页被重复执行，不是第二套并发额度。先取得页工作租约，再在每次推理前排队取得 oMLX 租约；两者均续租。失效 worker 的晚到结果只有在租约代次和输入哈希仍匹配时才能提交。
- 页面渲染与 OCR 分开限流，避免大量 PDF 同时渲染耗尽内存。
- OCR 任务经过共享 oMLX 工作负载门禁；调用方不得自行绕过模型选择和租约。

### P4-R07 原文保存与诚实定位

- 原始文件、页图、原生文本层、原始 OCR 输出和布局旁路结果分别保存，任何后处理不得覆盖它们。
- 原生 PDF 优先使用项目现有 MIT 许可的 `pdfplumber` 获取字符/词坐标；扫描页和照片先验证完整 PaddleOCR-VL 布局流水线，不能把单独 VLM 文本输出当作布局结果。
- 证据定位按“区域坐标 > 文本范围 > 页内摘录 > 仅页码”逐级降级；只有真实返回并可映射到页图的坐标才能标为区域定位。
- 多处相同文本无法稳定消歧时必须降级并说明原因，不生成伪精确高亮。
- 页面向用户显示实际定位精度和降级原因。
- Slice 4.0 必须冻结可量化金标准：原生 PDF 目标文本回读一致率 100%、目标定位成功率不低于 95%；扫描/照片布局候选只有在目标块定位成功率不低于 90%、所有已输出区域均落在正确页且覆盖正确目标文本时才可正式采用。达不到门槛则诚实降级，不以“完全不输出区域”冒充定位验收通过。

### P4-R08 高风险识别核对与校对历史

- 对否定/肯定极性、关键数值、小数点、单位和日期建立结构化风险提示，不能仅靠自由文本警告。
- 用户校对时保存原值、校对值、理由、确认人、时间、修订号和受影响页/范围；原始识别结果保持不变。
- 极性、关键数值、单位或日期发生改变时，提交前必须明确二次确认。
- Slice 4.0 的种子风险集要求关键风险漏检为 0、页面级误报率不高于 10%；会改变极性、关键数值、单位或日期解释的未核对风险阻止证据处理修订激活，纯提示性风险不阻断。风险等级矩阵在实现前冻结。
- 校对只使受影响范围进入待重算状态，不得无关地重跑整个项目；Phase 4 记录影响范围，后续阶段消费该范围。

### P4-R09 持久任务、恢复与部分失败

- 用户确认上传后先落持久任务，再开始文件处理；刷新页面、关闭浏览器或重启服务后仍可看到并继续。
- 任务按文件和页保存检查点、租约、重试次数和幂等键；重试只处理失败或受影响范围。
- 取消只在安全步骤边界生效，并保留已完成的不可变产物和取消记录。
- 页面以“等待处理、正在处理、部分完成、需要处理、已完成”等中文业务状态解释当前结果，不暴露内部日志。

### P4-R10 宽屏上传与证据工作台

- 路由位于受试者资料上下文，例如 `/subjects/:subjectId/evidence?episode=...`；受试者列表和个例工作台均可进入。
- 首屏采用宽屏三栏：左侧文件与页清单，中部识别文本/风险核对，右侧原文件页图；所选文件、页码和定位同步。
- 右侧原始资料区按文件实际页序连续滚动展示 PDF、图片及文档派生页，切换中栏证据时自动滚动到对应页和位置，但不得抢夺用户正在进行的手动滚动。
- 只有证据定位包含经真实性门禁验证的页内区域坐标时，才在对应原始页上绘制风险红 `#C00000` 重点框；红框必须随缩放、浏览器缩放和栏宽变化正确映射。缺少真实坐标时不绘制红框，改为页码、原文摘录或文本范围提示，并明确当前定位精度。
- 顶部固定显示项目、受试者、审核节点、方案版本、当前资料版本和待处理数量。完整资料方式必须另列“上一快照有、本次未选择”的遗漏清单；每个文件均有移除、作为新版本、并列保留和下一步动作。
- 上传方式、待确认差异和主要操作在首屏可见；高级运行信息收纳到“处理详情”，不让用户阅读后台术语。
- 页面级不得出现横向滚动；密集页表仅允许组件内部滚动。布局用 Grid/Flex、`minmax()`、容器查询和相对尺寸，不以固定像素宽高作为主要策略。
- 视觉遵循康哲站点式 HTML：浅底为主、橙黄作克制识别、红色仅用于风险；状态不只依赖颜色；键盘可选择文件、切页、打开证据和返回。

## 验收标准

- [x] **P4-AC01 去重与缓存：** 同内容重复上传不增加原始二进制或重复 OCR；更改文件内容或识别配置后仅相关页重新处理。
- [x] **P4-AC02 两种上传方式：** 补充资料继承前序仍有效成员并正确处理显式替代；完整资料快照只含本次选择；两者均可预览、取消并保留旧快照；同集合重复确认不创建新快照。
- [x] **P4-AC03 作用域隔离：** 项目、研究期别、受试者和审核节点任一不一致均被确定性门禁拒绝；基线资料不能改变筛选快照。
- [x] **P4-AC04 页面完整性：** 多页文件缺页或单页失败时显示准确失败页和部分完成状态，且候选快照不能发布为活动快照。
- [x] **P4-AC05 全局并发：** 多任务、多进程、外部门禁已占槽、布局多请求、进程崩溃和租约代次测试中，真实外部 OCR 推理峰值不超过 8；晚到结果不能覆盖新代次，服务重启后无永久处理中任务。
- [x] **P4-AC06 定位诚实性：** 原生 PDF 文本回读一致率 100%、目标定位成功率≥95%；扫描/照片布局候选正式采用时目标块定位成功率≥90%，所有区域均在正确页且覆盖目标文本；无法达标时明确降级，不允许用零区域输出冒充通过。
- [x] **P4-AC07 关键识别风险：** “否认/确认”、小数点、单位和日期种子集关键风险漏检为 0、页面级误报率≤10%；会改变关键解释的未核对风险阻止激活，纯提示风险不阻断。
- [x] **P4-AC08 校对与可复现：** 校对不会修改原 OCR；关键变更需明确确认并生成新证据处理修订；任一旧快照+处理修订可精确回放当时页图、OCR、定位、有效校对、资料类型/来源方元数据及被引用资料/满足关系。
- [x] **P4-AC09 幂等与状态机：** 重复确认、重复回调和双标签页提交不产生重复快照/任务；候选、处理修订和激活事件只能合法转换；旧修订提交被拒绝并显示差异，回滚新增激活事件。
- [x] **P4-AC10 恢复：** 文件读取、页渲染、OCR、缓存写入和发布各步骤故障注入后可限定范围重试；浏览器关闭和服务重启不丢任务；失败候选不影响上一活动快照。
- [x] **P4-AC11 宽屏体验：** 在有效 CSS 宽度不低于 1280 的组合下覆盖 1920×1080（100%/125%）、2560×1440（100%/150%）和 3840×2160（100%/150%/200%），完成上传预览、遗漏核对、确认、连续滚动查看原始资料、证据跳转、风险校对和失败重试；页面级无横向滚动、关键文字无裁切或重叠。具备真实区域坐标的证据在全部组合下红框均覆盖正确页和目标原文；仅有文本范围、摘录或页码的证据不得出现伪红框。
- [x] **P4-AC12 数据完整性：** 数据库迁移前自动备份；迁移后 schema、外键、WAL、内容哈希和镜像字段一致；旧项目保持只读。
- [x] **P4-AC13 独立试用：** 完整回归通过后，由 Cursor CLI `cursor-grok-4.6(medium)`、Pi `cms-router/minimax-m3(high)`、Pi/oMLX `Qwen3.8-27B-oQ8e-fp16-mtp(medium)` 分别先做连通性测试，再以资深医学监查人员角色按无辅助任务脚本独立端到端试用。三路使用互不污染的新架构 D001 II 期项目副本及各自不同的真实受试者资料，只通过产品界面和产品配置的独立 Agent 完成 Phase 4 范围内的上传、快照、OCR、页核对、校对、定位和恢复；不得由测试模型自行替代产品完成医学抽取或入排判断。脚本记录完成率、用时、误操作、遗漏和关键证据交互数，Codex 复核真实浏览器、测试输出、数据库不变量和临床边界后才接受。本地 oMLX 测试必须在交流电源下运行，首次使用先做真实连通性检查，完成后卸载测试模型；不得把它与产品 OCR 请求并行运行而污染性能结论。用户已明确不亲自参与本阶段试用，因此保留“模型角色不能等同真实用户研究”的残余风险。

## 范围外

- 临床事实抽取、Patient Profile 与 Patient Journey（Phase 5）。
- 逐条入排判断、缺口责任方、行动闭环和 Critic（Phase 6）。
- 跨受试者批量审核、报告导出和批量个人 Markdown（Phase 7）。
- 使用真实临床资料形成入排结论（Phase 8）；Phase 4 可在隔离副本中使用真实方案和受试者资料验证证据链，但不得形成或验收入排结论。
- 旧项目迁移或写入、登录/多用户权限、安全性专项测试、移动端和窄屏适配。
- 真实医学监查人员现场可用性研究；本阶段按用户授权使用三名独立模型测试者和量化无辅助任务脚本替代，不把它表述为真人验证。

## 技术约束与延后事项

- 本阶段先用能力试验确认 PaddleOCR-VL 在当前 Apple Silicon 环境中是否能稳定产出与页图一致的布局坐标；不通过时保留现有 oMLX 文本识别适配器，并按真实能力降级定位。
- 不引入 OCRmyPDF，不重建或改写用户 PDF。
- 不把仅有 Markdown/纯文本的识别结果伪装为来源坐标。
- OCR 与后续 LLM 流水并行只建立可调度边界；本阶段不实现临床审核 LLM。
