# Phase 5.5 双模型逐页判读合同与评测

## 目标

按 R3 设计建立产品自有的逐页判读合同、确定性对账边界与评测入口。系统主读为对称的 GLM-5.3-Flash（low，zhipu-coding-plan）与 Gemini-3.7-Flash（high，google-antigravity OAuth 直连）（2026-09-08 用户裁决，覆盖本文早期 MiniMax/Qwen 组合表述）。产品运行、自动测试和凭据解析不得依赖 Hermes、OMP、ZCode 或其他外部 harness。

Phase 5 的 31001 临床事实收口仍保持未完成，`claims_complete=false`。本任务与 Phase 5 受控重叠，仅用于补齐已被真实资料暴露的手写覆盖能力，不把失败运行或未完成临床核对包装成 Phase 5 验收。

## 需求

- 从已发布 `RuleSet` 修订确定性投影紧凑、内容寻址、可版本化的 ClausePack；保留官方规则编号、父子身份、原文、结构化表达和资料要求。
- 每条条款必须携带 `determination_mode`：专业判断优先；明确数值、日期、时间窗及结构化逻辑归为确定性；其余语义存在性或描述性条件归为语义判断。分类只读通用合同，不识别项目、疾病、药物、评分名称或固定阈值。
- 定义严格的 `PageReviewRecord`、`PageReconciliation`、`SubjectPageCoverage`。页级方向仅允许 `evidence_for / evidence_against / mentions / none`，合同必须拒绝任何判定词字段。
- `PageReviewRecord` 必须保存读道、页与条款包身份、归一化前原文、归一化键、摘录位置及结构化 `handwriting[]`；手写类型覆盖签字缩写和日期、CS/NCS 判断、便签、手写表格单元及其他。
- 主读 A/B 对称且互盲，两路均提取普通事实及手写内容；归一化先于对账；手写多源一致采信，单源或冲突保留待核对。
- 确定性条款的页级方向信号在对账时丢弃，只保留事实；无方案阈值的检验异常仅在存在研究者书面判断时进入专业判断输入。
- 失败页必须在覆盖合同中显式记录，不得静默漏页或让其他模型代写失败读道。
- 后续 harness 直接通过产品内 HTTP 客户端及显式环境变量连接模型端点；不读取外部 harness 数据库、配置或会话。
- 判断检索（书面判断检索）single-v4/batch-v1 模块须接入正式持久任务、缺口生产者与界面（2026-09-10 接管后的当前执行主线）。

## 验收标准

- [ ] SAR III 与 D001 两个已发布规则修订均能生成稳定 ClausePack；重复投影哈希相同，源规则变化后哈希变化。
- [ ] `determination_mode` 的项目无关单元测试覆盖专业判断、阈值、时间窗、逻辑组合与语义存在性。
- [ ] 页级合同强制 `handwriting[]`、原文和归一化键，且额外字段严格拒绝；注入 `exclusion_triggered`、`supports_not_met` 等判定词的 Gate 测试必须失败。
- [ ] 对账测试证明归一化先于比对、确定性方向被丢弃、多源一致才采信、单源/冲突不静默择优。
- [ ] 覆盖合同证明每一页只能落为已采信、无入排价值舍弃或失败待原读道复读，且舍弃和失败均有可审计原因。
- [ ] 新代码位于独立小模块，不并入现有巨型文件；聚焦测试和相关全量回归通过。
- [ ] 判断检索纵向接线：从正式 API 入队的持久作业可取消/恢复、成功回执不丢，双读完整且当前适用且确需书面判断而未见时，Profile/资料要求界面出现限定"本次提交资料"的中文无法判定原因（不要求用户二次确认缺失）。
- [ ] 产品 harness 在同一金标集复跑后，双主读并集事实召回率不低于 0.95，金标负判定静默漏判为 0；未达阈值时不进入 Phase 6。

## 范围外

- 本任务不发布入排结论；真实受试者页面仅按受控隔离实例处理。
- 不回改 Phase 4 冻结的 OCR 或证据快照，不激活失败快照。
- 不以外部测试 Agent 或外部 harness 代替产品内判读链。
- 不新增项目特异医学规则、安全专项、移动端或多用户能力。
