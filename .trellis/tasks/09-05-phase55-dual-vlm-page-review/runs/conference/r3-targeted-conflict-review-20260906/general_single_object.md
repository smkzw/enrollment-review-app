## Independent Work Product

### 总体判断

提案方向正确：冲突触发式（非每页四读）、轮次有界、原读不可变、复核记录全溯源、失败与原图不清保留待核对、用户确认三要素（原件+两路差异+理由）、手写不进事实仲裁——这些与既有合同架构（`prd.md` 的对账边界、`implement.md` 的“对关键字段分歧和单源候选保持冲突，不自动择优”）一致，值得继续。但按“独立性、版本来源、错误趋同、失败覆盖、用户确认边界”五项核对，提案有**一个会阻断集成的最高影响缺陷、两个独立性/趋同上的实质漏洞、一处未覆盖的状态分支**，且在其自设前提（复核能解决多数冲突）上尚无任何测量。均为可修复的合同层缺陷，不需要扩成多层代理框架。

### 最高影响缺陷：同版本多候选碰撞未解，复核结果无法被现有覆盖选择器消费

提案要求复核产生新记录并保留原记录，这必然使同一页在同一执行版本下出现两个 `PageReconciliation`（原对账 + 复核后新对账）。但 `CHECKPOINT_20260905_R3_NORMALIZER_WIRING_PAUSED.md` 明确记录当前选择器行为：“旧记录仍在库，不参与当前版本选择；**同版本多个候选仍拒绝，不自动择优**”，且“同版本受控重读的候选替代关系仍待实现”。即：两轮复核跑得再好，产出也会被 `coverage_selection` 整体拒绝，规范化入口失败关闭——设计在现有集成点上走不通。

补救（最小完整）：引入**显式替代链（supersession chain）**而非“自动择优”——新对账内容身份中写入 `parent_reconciliation_id + resolution_id`，同版本多候选时选择器只接受“链头”（无后继者），存在两个无后继候选仍拒绝。这与既有“不自动择优”立场不矛盾：旧立场拒绝的是无替代关系的并列候选，链头是有审计痕迹的受控替代。需要一处 `coverage_selection` 合同变更 + 任务版本冻结升级（见测试 9）。

### 实质漏洞一：同族复读被当成独立第二源，独立性主张被高估

复核双路是 GLM-5.3-Flash:high 与 MiniMax-M3:high，而原读 A 是 GLM-5.3-Flash:**low**。GLM-high 复读 GLM-low 的产出是**同权重自审**，两者错误高度相关——`LIVE_LOW_MAIN_A_QC_20260906.md` 已给出实例：GLM-low 把出生日期等字段 field_name 误写“现病史”，同类字段身份混淆完全可能被 GLM-high 复现。若任何采信规则（类比手写“任二一致采信”）把 GLM-low+GLM-high 视为两个不同读道，就会把相关错误算成双证据，这正是错误趋同的隐藏通道。

补救：合同中显式引入 `independence_class`（如 `glm_family` / `minimax_family`），任何“两条一致记录支持同一候选”的采信路径必须要求两条记录 `independence_class` 不同（测试 3）。同族复读的价值定位是**自一致性提纯**（提升该路读质量），不是第二独立源。

### 实质漏洞二：第一轮提示内容未定，锚定风险敞口未关闭

提案只规定了“不见另一模型答案”，未规定第一轮提示里**有什么**。若第一轮提示包含任一原读的候选值、field_name 或归一化键（哪怕措辞成“核对出生日期是否为 X”），两路复核者被同一候选空间锚定，会系统性收敛到同一错误候选——提案只在第二轮规定了匿名化，第一轮敞口未闭。盲与不盲必须是合同字段而非实现习惯。

补救：`ConflictReviewRecord.blindness ∈ {blind, adjudication}` 为强制字段；第一轮提示 payload 白名单 = 页图字节哈希 + 区域坐标 + 整页降采样上下文 + 条款包身份 + 提取 schema，**禁止**出现两路原读的任何观察内容（测试 1）。第二轮才允许匿名候选 + 来源位置，并记录候选→标签置换表以防顺序偏置。第二轮任何“调和出第三值”的输出必须拒绝（测试 5）——模型只能选 A、选 B 或判“均不支持”，不能折中出新值。

### 提案未覆盖的状态分支：第一轮产生新值（四读 2-2 分裂）

原读 A=x、B=y，第一轮盲复读两路（异族）一致得 z≠x 且 z≠y。此时 z 有异族双源而 x、y 各单源，按“任二一致”逻辑会采 z——但 z 是复核提示引导下的产物。提案对此无规定。应在状态机中显式列出：z 必须携带页面区域锚定摘录方可作为候选，且默认列为**机器已解决、待人工确认**状态（不是静默采信），归入下方 Q1 政策决策。
