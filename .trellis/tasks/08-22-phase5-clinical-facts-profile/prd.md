# Phase 5 临床事实与 Patient Profile

## 目标与用户价值

把 Phase 4 已激活、可回放的证据快照和完整处理修订转化为可校验、可回源、可增量重算的临床事实、事件、用药/治疗暴露、资料覆盖与冲突，并在真实 Patient Profile 中按临床历时关系呈现。资深医学监查员进入受试者后，应先看到与当前入排节点最相关的异常、临界、趋势、冲突和证据质量问题，再按需展开全部历时信息；任何事实均可回到原文件实际位置。

本阶段不做逐条入排结论，不让模型决定规则状态或创建最终行动；它只建立 Phase 6 可依赖的事实基座和资料缺口基座。

## 权威边界与已确认事实

- 基线为 Phase 4 归档提交 `32f5997`；旧项目和 legacy 事实/报告只读。
- 每次规范化只读取一个审核节点当前已激活的 `EvidenceSnapshot + CompleteEvidenceProcessingRevision`。候选、失败、未激活或其他节点修订不能进入事实真相。
- 后续节点资料可扩展受试者历时记录，但不得静默改写早期审核节点当时的 Profile revision；每个 Profile 均带审核节点、证据快照和处理修订身份。
- 方案及现行修订案仍是规则权威；Phase 5 只借助已发布 EvidenceRequirement/Expectation 建立事实到规则组件的索引，不重新解释方案。
- 既往原始记录优先于筛选病历转述。只有筛选病历转述的阳性既往史或长期病程可作为当前事实，但必须标为较弱来源并生成加强的溯源提醒；沉默绝不生成否认事实。
- 用户为本机单用户；不增加登录、所有权或安全专项。
- 前端只面向最大化 1080P 至 4K 宽屏桌面，使用中文原生临床措辞，不展示 Agent、schema、provider、pipeline、日志等内部词。

## 范围内需求

### P5-R01 当前证据权威链

- 事实运行必须显式绑定 `project / subject / review episode / protocol version / rule set revision / evidence snapshot / complete processing revision`。
- 必须解决 Phase 2 占位事实表绑定旧 `evidence_snapshots`、Phase 4 当前版本绑定 `evidence_snapshots_v2` 的错链风险；新写路径只有一个明确权威源，旧占位数据不得被混入真实 Profile。
- 活动证据版本变化时，只把受影响的旧事实/Profile 标记为过期并创建新运行，不覆盖旧版本。

### P5-R02 Evidence Normalizer 候选

- 独立 Agent 读取经过校对后的有效文本、真实页/文本定位、文档类型/来源方、记录时间、当前审核节点和相关 EvidenceRequirement，输出结构化候选。
- 候选覆盖：人口学、目标疾病、症状体征、诊断与病程、现病史/既往史、过敏、感染与免疫、生育、家族史、社会/环境暴露、既往研究、献血/输血/移植、检验、检查、评分、手术/操作、非药物治疗及药物暴露。
- 药物暴露保留原始药名/类别、适应证、剂量、单位、频次、途径、起止日期范围、持续状态和来源类型；不得在本阶段判断是否违反洗脱期。
- Agent 只写候选和未解决项，不能写接受事实、冲突裁决、Expectation 最终状态或入排结论。
- 候选合同与发布合同物理分离；模型置信度只作为候选质量审计信息，不能成为发布、隐藏或首屏排序阈值。
- 默认按逻辑文档切片；超长文档可按连续页组切片，但每次运行必须对活动完整处理修订的页清单逐页闭合，整页遗漏不能被当作“未发现事实”。

### P5-R03 确定性事实门禁

- 校验合同、作用域、当前处理修订、EvidenceSpan 真实性、原文哈希、否定/肯定/未知、值与单位、日期精度与上下界、记录时间、来源强度、覆盖完整性和候选引用闭包。
- `unknown` 不得携带被断言值；肯定/否定事实必须明确被断言对象；数值必须有规范单位或 `unitless`。
- 沉默、文档未提及或应有而没有只形成 EvidenceExpectation 缺口，不形成“正常”“阴性”“否认”事实。
- 关键 OCR 风险未完成所需校对时，相关候选不得发布为确定事实；可保留为被拒候选和明确影响范围。
- 否定事实必须有指向被断言对象的明确否定原句；空白、未勾选、邻近句否定或未提及不能作为否定依据。
- Agent 只能引用 Phase 4 当前完整处理修订已经认证的定位；新定位建议必须再次通过 Phase 4 定位真实性门禁，模型坐标不能直接生成红框。

### P5-R04 日期、时态与历时关系

- 区分事件发生时间、起止范围、记录时间、资料上传时间和审核节点锚点。
- 年、年月、完整日期分别保留精度和确定性上下界；不得用筛选日或操作日替代缺失日期。
- 支持持续、已结束、间歇、单次、未知状态；不能从“既往”自动推断终止日期。
- 确定性计算病程下限/上限、暴露区间和到当前锚点的可判定范围，为 Phase 6 时间窗计算提供输入，但本阶段不产生洗脱是否满足结论。

### P5-R05 重复、冲突与来源强度

- 精确重复候选可按稳定内容身份合并引用，但保留全部来源定位。
- 同一语义对象的不同来源存在不兼容值、极性、日期或持续状态时，建立 ConflictGroup 并列展示，不自动择优或覆盖。
- 来源强度至少区分同期客观结果、既往原始资料、当前研究病历直接记录、筛选病历转述和无法确认来源；强度影响资料覆盖/溯源提示，不直接改变事实值。
- 人工事实修订必须保留原候选、接受记录、修订理由、来源定位和影响范围；不得修改原 OCR 或旧事实 revision。
- 重复身份不包含模型置信度和来源定位；同内容多来源合并后保留全部定位。值、单位、极性、日期范围或持续状态不兼容时不得合并。

### P5-R06 事实、事件、暴露与规则索引

- 发布接受的 ClinicalFact、ClinicalEvent、MedicationExposure、ConflictGroup 及其到 Phase 4 EvidenceLocator 的不可变引用，并记录 GateResult、AgentCall、输入哈希和重算范围；不得复制出另一套可漂移的定位真相。
- ClinicalEvent/MedicationExposure 的事实引用和证据引用必须属于同一审核节点与处理修订。
- FactRuleLink 只连接到已发布 RuleComponent/EvidenceRequirement；确定性精确匹配优先，不能用自由文本模糊相似度把事实串到无关规则。
- 索引是双向可查询、可重建的下游结构，不写回方案规则。

### P5-R07 EvidenceExpectation 覆盖

- 从当前审核节点绑定的 EvidenceExpectationTemplate 创建/刷新受试者级期望，确定性投影 `已观察 / 较弱证据 / 已引用未提供 / 未观察到 / 尚未到期`。
- 覆盖状态必须给出来源 Span、具体缺口类型和关联规则；“资料中否认近 X 周使用某治疗”可支持当前事实和覆盖，但若规则要求更高等级历史来源则另给溯源提醒，不能同时误报为证据不足。
- Phase 5 不创建最终 ActionRequest；保留可供 Phase 6 生成责任方、补充内容和到期节点的结构化缺口。

### P5-R08 Patient Profile 投影与界面

- Profile 按 13 条主题泳道组织：研究节点、人口学/基线、目标疾病、症状体征、病史、药物暴露、非药物治疗/操作、检验检查/评分、过敏/感染/免疫、生育、社会环境、家族史/特殊经历、证据冲突与资料质量。
- 首屏默认仅突出入排相关、异常、临界、趋势变化、冲突、弱来源和当前到期资料缺口；提供“全部历时信息”切换，不删除或隐藏后台全量事实。
- 顶部显示人口学、疾病状态/病程、当前审核节点、关键锚点、证据版本、Profile 生成时间和待核对数量。
- 点击事件可查看原始依据、关联规则和资料覆盖；证据跳转使用 Phase 4 真实文件/页/定位精度，具备真实 bbox 才画红框。
- 冲突来源并列；部分日期显示精度/范围；事件发生时间与记录时间分开；不同审核节点带清晰阶段标签。
- 真实 HTTP API 替换当前 fixture/stub Profile 路径，运行时解码拒绝合同漂移；原型 fixture 继续只用于隔离前端测试。
- 首屏突出集合由后端确定性投影生成；“有关联规则”本身不等于首屏风险。异常/临界仅来自原报告标记或原报告参考范围，不能提前使用 Phase 6 的方案阈值裁决。
- 本阶段 Profile 不展示受试者入排主结论、行动数量或“通过/不通过”标签；这些位置在 Phase 6/7 接入真实结果后再出现。

### P5-R09 运行、恢复与增量重算

- 规范化是持久 Job，浏览器关闭后继续；每个文档/页候选、门禁、发布和投影步骤有检查点、幂等键、租约和限定重试。
- 同一活动处理修订、PromptVersion、ModelConfig 和输入范围重复运行不得创建重复事实或 Profile。
- OCR 校对、文档增量上传或事实人工修订只重算受影响文档/Span/事实/事件/期望/Profile；无法证明局部范围时保守扩大，不静默漏算。
- 失败或被拒候选不能污染上一活动 Profile；任务详情使用用户可理解的中文说明当前进度、失败范围和下一步。
- 使用独立 FactNormalizationRun 身份绑定处理修订，不为规范化任务伪造 Phase 6 ReviewRun；发布提交前再次核对活动快照、活动完整处理修订和审核节点 revision，任一变化即拒绝陈旧结果。

## 范围外

- 逐 RuleComponent 入排判断、阈值/AND/OR/例外/洗脱裁决和节点主状态（Phase 6）。
- 最终责任方与 ActionRequest 创建、自动关闭、人工 override、批量审核和报告导出（Phase 6/7）。
- 真实项目大规模盲后医学准确性验证（Phase 8）；Phase 5 只使用隔离副本做事实/Profile 代表性核对。
- legacy 项目迁移或写回、登录/多用户、安全专项、移动端/窄屏适配。
- 引入新的向量数据库、知识图谱数据库或通用图编排框架；SQLite 关系与稳定索引足以覆盖本阶段。

## 验收标准

- [ ] **P5-AC01 权威链：** 任一接受事实、事件、暴露、冲突、期望和 Profile 均可验证到当前审核节点已激活的证据快照与完整处理修订；候选/旧/失败修订被拒绝，legacy 占位事实不混入。
- [ ] **P5-AC02 来源回放：** 代表样本所有关键事实和事件均可在不超过 3 次操作内打开正确文件、页和真实定位；无真实坐标时诚实降级，无伪红框。
- [ ] **P5-AC03 沉默与否定：** 否认语句形成明确否定事实；沉默、未提及和资料缺失不生成否认/正常事实，只形成对应 Expectation 缺口。种子集关键极性错误为 0。
- [ ] **P5-AC04 来源强度：** 只有筛选病历转述的阳性长期病史保留为当前较弱事实并生成加强溯源提醒；已有既往原始资料时并列显示并正确提高覆盖强度，不覆盖冲突。
- [ ] **P5-AC05 日期范围：** 年/年月/日、持续/终止/未知、事件时间/记录时间均正确保存和展示；病程与暴露上下界通过边界和属性测试，不猜缺失锚点。
- [ ] **P5-AC06 重复与冲突：** 精确重复不产生重复事实，多个来源定位完整保留；矛盾值/极性/日期并列进入冲突组，系统不自动选择赢家。
- [ ] **P5-AC07 期望覆盖：** 到期、未到期、较弱来源、病历已记载但需溯源、明确引用文件未提供和确实未完成检查分别得到正确状态，不把它们合并成单一“待补证”。
- [ ] **P5-AC08 增量与历史：** 新增/校对一份资料仅使受影响范围生成新事实与 Profile revision；旧审核节点版本可完整回放，后期资料不静默改写早期资料。
- [ ] **P5-AC09 Profile 内容：** 13 条泳道完整覆盖；首屏只突出入排相关、异常、临界、趋势、冲突和质量风险，全部信息按需展开；500 个事实时仍可在 1080P、2K、4K 无页面横滚使用。
- [ ] **P5-AC10 真实运行：** Evidence Normalizer 使用真实模型输出结构化候选，经 Schema/Gate 后发布；Agent 失败、空输出、遗漏整页、虚构 Span 或跨节点引用均明确失败，不以空 Profile 冒充成功。
- [ ] **P5-AC11 恢复与幂等：** 浏览器关闭、服务重启、重复请求、任务中断和部分失败测试后无永久处理中或重复事实/Profile；失败候选不影响上一活动版本。
- [ ] **P5-AC12 代表性核对：** 在隔离 D001 II 与 MG-K10-SAR III 新架构副本中，各选至少一名资料结构不同的受试者逐事件与原始资料核对；关键人口学、疾病历程、MH、CM/治疗、检验检查/评分、日期、冲突和溯源提醒无已知错误。
- [ ] **P5-AC13 独立审查与试用：** 确定性回归通过后，使用届时用户指定且先通过连通性的会商/测试路线分别进行架构审查与真实浏览器医学监查员视角试用；会商与测试证据不得互相替代，Codex 复核真实文件、数据库和浏览器后裁决。

## 阻断问题

无。现有设计书、分阶段计划和用户此前确认已决定本阶段产品范围；技术实现细节由 `design.md` 收敛并接受独立会商挑战。
