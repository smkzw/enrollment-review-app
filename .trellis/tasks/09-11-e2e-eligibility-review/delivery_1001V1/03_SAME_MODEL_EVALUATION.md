# 1001V1｜不新增模型的同源对照与验收

## 1. 比较的问题与不能回答的问题

本轮只问：**在现有可用模型和相同产品终点下，候选workflow是否减少错误采用、错误拒绝、重复读取及人工负担，并让正常要求更稳定到达实际消费者？**

不问“哪款模型最强”，不依赖新高质量API模型。没有模型因素的交叉实验，不能估计不同模型的能力差异，不能推断现用模型的理论上限，也不能证明所有剩余失败都是harness所致。

同模型不同流程同时改变提示、上下文组织和恢复时，只能归因为“候选机制的组合效果”。需要声称某个具体因素改善时，用该因素的受控消融验证；不把一个小样胜出解释为所有因素都正确。

## 2. 两个实验臂

| 项 | RV1001-BASELINE | RV1001-FLOW |
|---|---|---|
| 来源与预期任务 | 同一冻结原文/原图、角色、节点、目标、依赖 | 相同，不删要求 |
| 模型 | 该任务族当前已批准的同一路线与实报身份 | 相同，不悄悄升级或切换 |
| 控制 | 现行固定提交的已知路径 | 02定义的固定责任＋单主责＋按需取证/复核 |
| 资源 | 事前冻结单逻辑任务总预算、超时与重复规则 | 使用可比较的总包络；实际消耗单列 |
| 终点 | 相同现有装配／采用／工作稿消费者 | 相同；不以短答代替消费者 |
| 判分 | 独立来源核对的预期关系及下游结果 | 同一标准，不放宽门禁获得优势 |

官方规则与跨章分别成对，不把不同任务族、不同模型、不同difficulty合并作一个简单准确率。保持端点档案、reasoning档位、响应机制及调用参数可比；若某差异是候选机制本身的一部分，明列为处理因素，不称完全只改Prompt。

历史回执只有在源、目标、模型/配置、代码/合同和终点可核一致时才能节省基线调用。版本不一致列为历史诊断，不拼成公平对照。当前基线不安全的结果只用于隔离评估，绝不因此发布。

## 3. 有限起步，不新增大型榜单

优先从已有回归资产取6个来源任务：

1. 普通、来源清楚、现有消费者支持的条件。
2. 描述语气的取值或计算定义，确实影响已存在条件。
3. 带量词/否定/例外的完整条件分支。
4. 表头/脚注或跨章限定关系，原件有足够依据。
5. 含义已核但某执行精度尚不支持的R1受限要求，另有独立可用要求。
6. 原文真实歧义或证据不足，应当准确保留未决。

每任务每臂先一次：共12个**逻辑实验**，不是保证只有12个物理API请求。每个逻辑实验仍受02的共享预算约束，真实修复/复核调用全部计入。

只有首轮确认没有新增危险错误采用且已有完整消费者结果后，对最不稳定的两个任务各臂再做两次独立初始运行：增加8个逻辑实验，总计建议最多20个。若首轮只是返回更短但未到消费者，先修接线，不扩大运行。该数量是小规模工程诊断，不是统计学临床性能证明；不成为每次代码修改的固定必跑数。

失败若在调用前即可确定（签名、来源或状态错误），先做离线反例，不耗真实模型来重复证明。暂停或预算到期时保留实际停止状态和缓存，不因样本不齐填补结果。

## 4. 不用另一个大模型当金标

优先使用已经有原文依据和独立核对记录的正常／反例；可使用人工审定的关系与程序算术作为实验预期。仍没有可信预期的题不作对错排名，列为未裁决材料。

开发Agent可以组织材料和提出预期，但自己的模型答案不能既当待测输出又当金标。关键语义应由具备领域能力的核对者对源检验；仅需围绕有限样本，不要求用户逐句给整本方案或每例病例制作JSON。工程会商意见不是临床采用授权。

同模型新会话、两个现有模型相同回答都不能自动升级成真值。带引用也可能解释错。评测时应检查未出现在模型结果中的实质含义，避免以输出集合为分母。

## 5. 首错隔离：不必更换模型也能定位一部分原因

在隔离测试中用经过核对的中间材料替换一层，再运行后续消费者。替换材料标为 `diagnostic_only`，保存原失败证据，绝不进入正式事实/规则采用。

| 干预 | 观察 | 能支持什么，不支持什么 |
|---|---|---|
| 用正确原生表结构替换错误投影 | 后续理解/消费恢复 | 结构是原因之一；不能证明模型普遍足够 |
| 保持同源与模型，缩小到完整语义任务 | 从错误变正确 | 分解/上下文机制有收益；非模型间比较 |
| 给装配器正确语义提案 | 仍失败 | 优先查结构/消费者；不是继续让模型读 |
| 各分段正确，合并后错误 | 范围或量词变化 | 合并/编排有缺陷；不能靠多模型投票 |
| 给合法明确未决及独立正例 | 独立正例也被阻断 | 采用/依赖传播问题 |
| 独立核对者也无法由原件裁决 | 保持真实未决 | 不是继续增加提示就能获得唯一医学答案 |

同模型在完整、清楚材料和合理任务下仍失败，记录“现有路线在该任务下能力/可靠性尚未达标”；没有其他模型对照，不宣布哪款更强或此模型不可用。继续隔离影响并交付独立正确部分；若某核心能力始终不能满足，诚实报告交付缺口，不降低标准。

## 6. 记录指标：质量与可用性并列

每个任务至少记录：来源范围、预期关键关系、首次错误层、正确输出及遗漏、错义/错误采信、错误拒绝、应判未知及原因、是否到真实消费者、重试/回退范围、实际模型请求与报告身份、总用量/耗时、人工操作。

质量对比不把全部未决当安全胜出；至少一个普通可确定正例必须完成，合法风险与合法未决按各自真值检验。技术错误、语义错误、证据不足、能力缺口分开，不能减少技术报错就宣称医学准确性提高。

时间包括图像编码、网络/排队、生成、本地校验、重试和必要人工主动时间；取得不到细分就记未知。模型token/s、短答字符数不能代替整例结果。小样主要给逐任务配对表和全部实值；不以很小样本的P95或零错误宣称可靠性保证。

## 7. 迁移判断与停止条件

### 可进入有界迁移

相同消费者终点成立；关键正反例、正常正例、等义及真实反事实没有已知新增危险错误；合法未决与错误拒绝分别正确；至少一个有源动作闭合；候选机制在实际错误、重试、耗时或人工负担方面有可解释收益。进一步做当前改动受影响家族及少量未参与调优的独立来源。

### 不迁移或先继续修复

新危险错义/错误采信；原件覆盖降低；靠更多UNKNOWN、删能力门禁、只比短答或更大预算“胜出”；源/模型/参数/消费者无法对齐；没有净收益。仅保留独立有价值的控制流修复；不为采用新名字强行替换。

机制验证获准不等于临床签发、正式数字自动采用或所有既有作业重算获准。迁移走版本化新计划，旧失败和历史保留，不回写“已成功”。

## 8. 验收资产的使用

`acceptance_cases.json`列出12个整合家族，复用既有测试而不是另起96题必跑工程。恢复控制、身份和合同用合成/故障注入；语义质量用有限有源小样；真实病例/宽屏在P3候选窗口验收。源不自然同时含全部结果时，用独立合成案例补类，不篡改真实病例。

本包没有执行上述任何产品测试、模型比较或临床验收。实际运行结果必须由执行Agent以测试/代码同版本的回执给出。
