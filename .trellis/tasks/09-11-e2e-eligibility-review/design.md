# 0922增量设计：统一语义、真实来源与可操作闭环

2026-09-26 有源关系实现边界：已在深审计划中提供有版本身份的跨章节只读来源短名单，目标核对亦能看到该线索；产品 DeepSeek 的真实对照仍误报“频次相同即流程完整覆盖”，原校验拒绝。故检索/扩上下文只是**召回**，不是语义对账。后续不能通过降低 `FREQUENCY_ONLY_COVERAGE` 或把只读单元冒充官方/流程目标来闭合；须新增有源双端关系（动作、对象、剂量/频次、时期、例外、否定逐项核对），该关系只有在被引用来源的深审结果已通过且最终发布门禁复验后才能采信。关系不成立、对端失败或多解时摘要仍未决；未完成前不得让批次从 `failed_final` 变成成功。相关实测与代码范围见现行 `implement.md` 文头。

2026-09-26 W6 跨章节同一要求边界：同一冻结方案中，摘要可能把动作、剂量和时期拆散，后续规范章节才在同一段明确表达。当前逐批逐条核对不能把后续段落的时期借给摘要句；单纯加长提示或降低时间门禁不构成解决。允许先用词汇中立的文本检索找候选，但数字/药名相似只是检索线索，不能自动认证临床等价；须由内置方案 Agent 在有源短上下文中核动作、对象、强度、时期、例外和否定，记录双方结构单元及逐字来源。摘要待核不得在后续规范单元完成并通过现行门禁之前被采信；最终共同发布及每次有据修订重入须复验关联，未匹配/多重匹配/矛盾保持未决。不得重复发布同一控制，也不得把建议晨间用药升为强制。方案无关，不能写特定药名/疾病阈值。此能力未实现，当前 `claims_complete=false`；审阅及所有者裁决见 `reviews/codex_conference_enrollment-w6-cross-chapter-scope-20260926_review.md`。

实现定位补充：现有 `SourceTargetReviewItem.target_id` 只能指冻结官方条款或流程项目；`ControlCrossSourceRelationDraft` 的模型可选对端也仅官方/流程/工作流节点，不能冒充为两个原始结构单元的等价证明。应在来源解释之后另做受限的原文单元配对核查，保留原摘录、双方单元/页源身份与逐项语义差异；批内“待后续来源核验”只能作为未完成状态。正式水合时须读取被引用批次的已通过结果，验证对应动作、强度、时间、例外及否定，形成候选/控制级关系后再走既有发布门禁；被引用批次未通过、存在多解或关系不成立时仍拒绝发布。旧失败检查点不可因新增字段被就地解释为成功，配对身份须随来源和模型提示版本变化。此定位不授权先把第2批改为成功，再于将来补最终核验。

2026-09-25 W6 目标纠错收窄：初次逐条核对仍可查完整冻结官方/流程目录；只有“频次相同被错认同一访视覆盖”的有定位校验失败，下一轮才限定为刚才被误认的目标并附同单元原文。上下文供核语义，不自动把另一句的时期赋给本句。纠错不能换引未提供的目标；不能证明完整阶段覆盖时保持增量或未决，后续仍须有源装配和原发布门禁。实际单条小样成本降低不代替全方案速度/质量验收。

2026-09-25 W6 补答边界：多个候选各有结构错误时，可逐项请求短答，但每项只能替换其原来源范围，合并后仍必须通过整批来源与发布门禁。不同原文定位的日历错误可分别核对；同一处反复失败及超过三处仍拒绝。单项时间短答若仅漏唯一外层包装，程序只在内部时间合同完整合法时恢复包装；删除时间窗时，模型须给出该原子时间用途，程序仅清除已无时间窗对应的日期操作字段。数值、方向、锚点及其临床含义不得由程序猜测。“自某节点开始”不能机械地变成零天定量窗口；冻结访视名称可作为范围参照，但不是本动作时间窗的数值依据。格式成形和批次候选门禁通过都不代表逐项来源目标核对通过。真实小样已见模型把跨阶段背景治疗与仅属导入期的流程项目误判完整覆盖；须保持来源范围不等价时的拒绝，不能凭相同剂量/频次自动采信。

2026-09-25 W6 时界处置补充：同源目标核对只证明引用与摘录的结构对应，不自动决定当前审核节点。给药频次相同不代表审核时期、持续期相同；明确疗程、持续义务、跨节点要求或仅给药频次的增量陈述，不得因短装配失败再退回整候选补写，也不得以一次访视的 `decide_at_node` 代替完整时间语义。此类有源陈述保留逐项待核，最终完整发布仍需现有规则结构表达当前义务与未来义务并通过原门禁。保守词形筛查只负责发现已明确的复杂时界；未命中不构成临床安全证明，不可硬编码研究、疾病、药物或具体访视数值。成功的简单单访视/相对节点仍须有原文支持、消费者可用。隔离 GLM 对照仍未生成合规草稿，不能把模型可连接写成 W6 通过。

2026-09-25 W6 同批装配补充：多个简单有源短答先各自保留原始回执，再同批合并成候选，一次通过既有来源闭包、目标覆盖和整批发布门禁；不能用尚缺其他条目的中间状态提前否定第一条。混合批次只保存已通过门禁的局部 wire，时间复杂项仍留待核；任何局部草稿都不是完整规则的正式发布。执行与深审组件身份独立于旧版逐条提前校验回执。

2026-09-25 A13 操作完成证据：用户确认，方案仅要求本审核节点完成检查/核查、未要求结果正常时，可据本次资料中明确的完成记录核对该操作；检查结果仍由其他条款独立判断。方案 Agent 必须按原文将单纯操作与结果要求区分，混合、例外、持续期或不明要求不借操作模式简化。操作模式的两次原文核对各保留逐字完成/明确未做见证、对象及节点；缺记录、范围不清、读道冲突均不推断完成或未完成。系统再次核冻结当前判定节点，来源与双读取同一消费路径进入工作稿及正式计算；同一范围既有完成又有未做时保留冲突，不能靠任一有利记录消除反证。此模式只判操作是否完成，不自动证明资格合格或研究者判断已书面作出。新提示、证据和计算版本与旧回执隔离；旧 `unresolved` 不倒填新结论。当前只完成工程合同，正式方法评测、真实病例来源验收和完整规则发布仍是退出条件。

2026-09-25 当前节点采信约束：跨章控制的命题资料只有在冻结受试者审核节点与发布目录的判定节点映射一致时，才可能进入共用工作稿/正式计算；模型的 `node_correspondence` 不能代替此核对。历史回执保持原状，新的采信消费版本单独评测。普通操作的完成见证仍不能由仅有一次记录、未见否认或“已做检查”的孤立表述推定为整条资格满足。

2026-09-25 模型路线更新：以下 D4 段中的 `cms-router/deepseek-latest-cloud:high` 为历史部署选择，不再是现行配置。当前第二独立模型、事实整理及方案控制发现/深审改为 `ollama-cloud/deepseek-v4.1-flash`，请求思考强度 `high`；主读 A 与官方方案解构的 GLM 配置不变。产品直连 `https://ollama.com/v1`，按云端 API 模型列表使用不带 `:cloud` 的标识；`:cloud` 是本机应用/CLI 的标识。Ollama 只使用其专用 `OLLAMA_API_KEY`，历史角色密钥及地址不得继承；没有凭据或真实模型身份核验时拒绝临床调用，旧作业回执维持原路由身份。

0924V1 W6 有源增量装配（2026-09-25）：来源解释及目标核对先确认额外要求，内置方案 Agent 再分别回答单项访视动作或先后节点动作，不承担最终规则 JSON 的机械成形。装配器只从冻结目录确定目标节点的 `decide_at_node` 角色和已有流程关系，严格校验原文动作、范围、先后顺序及目标流程摘录；原文未规定观察选择时保留 `unresolved`。多条增量与原候选一起经既有合并、水合、整批门禁和逐条来源覆盖核对。此路径只接受无条件、无例外、可明确对应冻结节点的短义务；其他类型继续走原有受限恢复或保持失败，不把小样通过写成临床发布。

0924V1 W6 来源文字与重复定位格式：来源解释的 `quoted_text` 偏离冻结原文时，仅对单条有源陈述请求一次逐字短答；必须同一来源单元、数值不变、文本高度相近且完整来源校验通过，否则维持失败。原子本身已有成对来源而求值项漏写相同字段时，可在解析前复制这两个同源字段；显式冲突不改写，继续由 Schema 与发布门禁拒绝。两类处理都不补医学阈值、时点或结论，不复用失败快照。

0924V1 W6 来源逐项核对：对本期必做/禁止且未在候选义务中完整表达的有源陈述，逐条核冻结官方/流程目标；不因来源单元已有候选或目录同名而整体通过。已明确其他研究期、给药后执行等处置不被误拉回当前节点。完整覆盖须有两侧逐字动作、明确时间的两侧共同原文、例外及草稿原链接一致；部分对应只能保留为核对线索并说明缺口，不能发布成已覆盖。失败作业保存有源清单、覆盖账、目标核对与原始响应，不伪造成功或临床待补资料。相对时点与访视日期即使看似接近，若方案没有证明同一审核时点，仍保持未核；不要把这些表述写成某个方案的通用硬编码。新结构仅依附既有方案Agent批次结果，不建立第二规则库。

0924V1 纵向纠偏增补（2026-09-24）：`time_operand_attribute` 缺项仅属同候选纯结构错误时允许按原子位置短答；模型可明确 `unresolved`，代码不默认事件期或单日记录、不再整候选改写。日期属性补齐与时间窗口数值来源是两个不同问题；相邻陈述的期限不得被借到当前义务，后者仍须有源语义解释与装配闭环证明。该增补不改变原有发布门禁或临床验收标准。

0924V1 冻结反证后的界限：来源陈述只保存属于该陈述逐字摘录或所属标题的连续时间措辞片段，不输出“当前/以后/两者”的结论；真实模型会把“每日一次”等用法误分类为跨期。后续时间范围必须由具体动作、冻结审核节点及同源原文共同确定。单原子结构修订只能改求值和时间字段，若错误要求改义务类型或后续持续义务，转同源候选级并保持完整门禁；不得用程序猜测删除后续义务。后续需完成来源解释到既有候选的有限装配与双向核对，此前的字面覆盖账仅供诊断，不能当医学等价或发布证明。

0923V1 隔离试跑后补充：发现模型的候选/不确定处置不能覆盖已冻结且**仅属于另一研究期**的明确期别标注。深审计划对此种单元做有源、单元级的本期不适用处置；若被本期候选引用仍保留只读上下文。`mixed`、`shared`、`unknown` 或同时标注本期者不得跳过。原始发现回执保留，收口记录保存确定性路由后的结果，发布门禁继续要求全部单元闭包。缩小每批单元数不必然省时：固定 Schema/合同按批重复，需比较实际完整提示量、模型质量与失败率，而非仅看单次输入长度。
首批真实深审还揭示结构通过与临床时间语义不同：一句原文同时约束节点前与节点后时，不能让基线判定要求证明未来治疗期持续未发生变化。节点前已有控制不得丢失；未来持续义务仍留在来源和后续说明。若作者不能合法分离，必须作为语义未核而非确定满足。本边界需在后续真实候选核对中证明，单靠提示增加或 JSON Schema 通过不构成验收。

0923V1 后续隔离诊断：即使把真实跨期用药限制缩至单个来源单元，同一深审合同在两轮修订后仍不能稳定区分节点前事实与未来义务；因此不得以单纯减小批次或增加提示句作为临床修复。候选作者若拆分时间范围，必须逐项保留同一原文定位、现行阶段和后续持续义务；既有发布门禁仍拒绝在当前节点证明未来未发生。输出合同的自动生成字段标题可在**提示副本**中省略，临床描述、正式响应 Schema 和确定性校验保持原样；此项是输入成本优化，不是质量验收。

0924V1 来源核对补充：内置方案 Agent 的有源陈述是输入解释，不是另一份可发布规则。成功批次留逐条诊断：必做、禁止、建议要求只有在候选的义务或后续持续义务直接摘录中找到原文才记“已表达”；适用、触发、例外层命中单列，不冒充义务。既有官方/流程目录同名、候选引用同单元或备注声称已覆盖都不是逐要求覆盖证明。对疑似已由现有目标覆盖的陈述，后续须有指向该目标的结构化关系、实际覆盖维度与原文核对，不能凭关键词自动补链接。字面未命中也不能自动判医学遗漏，因此当前覆盖账只作诊断，不替代发布门禁。短上下文单候选修复的 v66/v67 隔离实跑没有证明稳定收益，已撤回，下一步应从小样的语义解释和确定性结构装配入手，不增加同类随机整批重试。

0924V1 局部来源修订补充：只有单项最低证据的来源政策结构不合规时，可在现有 Agent 会话身份下独立补答该政策；授权来源为候选所属的冻结原文，程序逐对验证位置和连续摘录、冻结其余全部字段，再走完整校验。来源不明、临床语义冲突或多字段问题不能由此自动修成已完成。覆盖账另列与已知官方/流程目标原文的完整字面对应，但它既不补结构关系，也不证明动作、时间、例外已语义覆盖。

0924V1 失败取证补充：深审调用若在限定补答后失败，失败事务可保存单独标记的诊断检查点，含每轮原始模型输出及其哈希、错误类、批次/提示/模型身份；它没有 `run_result`，步骤仍为失败，不能作为成功批次复用或发布。原始模型输出仅留在任务本地数据，不在普通错误提示中回显。诊断必须区别初答与补答的字段变化，否则不能从最终错误倒推根因。

0923V1 门禁补充：禁止类义务若把研究/治疗期间的持续遵守直接写进筛选、导入或基线节点的求值命题，则拒绝发布；通用“治疗期”及其“期间/内”表述均识别。此拦截只证明该类明确越界被发现，不证明所有未来时态均可由词形识别。模型仍须保留截至本节点可核的既往事实和以后持续义务，不得靠删来源或改为研究者判断绕过。新门禁和执行作业均须版本化，旧候选不能以新门禁名义免核续跑。

0923V1 时间合同修订：同一禁止原文兼有当前节点前事实与其后治疗/研究期间的持续要求时，在同一来源化义务原子内分别保存当前求值命题与 `continuing_obligation`。后者有自己的原文定位、期间和固定“本次未到期”状态，不产生当前节点真假，也不创设治疗期审核节点。两者来源必须闭合；当前原子不得同时持有 `prospective_period`。不能区分时保持未核，禁止改写为研究者判断、删掉节点前控制或仅靠提示/正则制造合格结果。正式方案预览应明确显示后续持续要求；正式受试者求值仍只计算当前原子。此合同是防止提前证明未来的结构条件，不代表模型已稳定产出，也不等于临床审核通过。
工作稿对同一控制只计算当前节点义务，另外显示“后续持续要求（本次不判定）”；不能因为当前节点已满足而隐去后续义务，也不能把未到期义务作为另一项当前未满足。历史结果保留其原版本语义。

## D3 真实读取政策
保留original-page-images/v1。默认主OCR/可靠原生文字→覆盖和重要字段核查→局部视觉/人工；复用selective_vision和既有持久任务。
政策必须类型化，绑定原件、读数、核实产物和版本；self_consistent仅为内部一致，不等于关键字段已交叉核实。字符串/布尔不作已核证明。
生产→仓储→coverage→规范化/locator→候选校验→共同发布→Profile/资格→恢复完整接通。禁止仅关require_page_review、假A/B、旧gate_id或model_construct绕过。
旧记录按旧版本回放，新来源按真实政策验证；同报告多工具仍是一份临床来源；无可靠坐标只承诺页/区域定位。
完成回执不只核页数和观察数：每个被允许进入事实整理的观察 ID 必须回读追加写原记录，核成功状态、模型/文字层复合计划身份及实际所属原件页，并与本次待核页逐页一一对应；错页、缺记录、关闭记录均不取得采用范围。
局部格式修复保留合法观察与多时点身份，不默认重发全图全规则；用户不用JSON。

0923V1 读取身份补充：选择性视觉任务按资料修订、规划版本和不含密钥的供应商/地址/模型/思考档位/输出额度指纹冻结；页观察身份再绑定原图、OCR原文哈希、提示和风险范围。连接配置在进程内变化时不热切到另一供应商，明确要求重启。事实整理只接收当前已完成任务回执列明的观察ID与页ID；旧观察可追溯但不混入新病史，冻结任务范围变化则拒绝续跑。无需新任务平台或第二套事实库。

## D4 模型合同与资源
开发fork模型不替换产品模型；产品依当前明确配置及授权。现行产品配置为：GLM通道使用 OmniRouter `cms-router/glm-5.3-flash:high`，第二独立模型及事实整理使用 `cms-router/deepseek-latest-cloud:high`；方案语义、局部视觉核实、证据整理和补充控制等角色分别配置provider/model/effort/output budget，不互相继承旧平台参数。该组合只是部署选择，harness合同不得包含模型、方案、疾病、药品或病例特异逻辑；供应通道只扩展传输配置和能力声明，不改临床提示、Schema、来源门禁或采信标准。旧角色专用密钥与地址不得因模型切换而被带往新的供应商；CMS 路线存在自身凭据时优先使用它。requested/reported/resolved与别名依据分开，缺报身份不回填。
供应商凭据必须同供应商端点绑定，不向新provider回退其他provider密钥。现场发现的ollama-cloud取GLM密钥不得发请求，见模型诊断记录。
替代供应商的模型配置必须先解析其自身端点和凭据，再作模型标识预检；不得继承正在运行角色的另一供应商地址或密钥。持久作业如在不同进程恢复，发现与深审读道的模型/端点/思考档位/预算也必须与冻结运行身份相符，未冻结前不得在换路由后盲目续跑。
真实诊断走产品客户端，留脱敏合同和错误；先单变量/单页，再必要小批，不以HTTP400猜图太大，不从头重跑25页。
预算按职责/能力配置，不统一下限、不无据短超时；本地串行及内存释放检查保留，OCR既有准入，不停别人任务/扩共享服务。用量缺失unknown。

0925V1 来源与复用合同：原文段落、表格单元及编号脚注属于结构来源图；动作、时期、例外和已有目标属于其上的语义引用图。访视目录并非全方案覆盖分母，未映射到目录的段落仍按全方案来源单元逐一处置。无编号续行换样式时，只在同一节后续恢复原编号列表且无新标题/表格的结构证据下归属；列表尾部无此证据保留未决，不凭样式或模型自信吞并。新深审作业在入队前形成逐批复用计划，新回执分别存提示、Schema、装配、校验、冻结来源及请求线路摘要；旧回执缺分项不得按版本号反推。计划与旧结果执行时再核，来源/线路损坏拒绝，普通材料变化列明确重算。逐条核对的错误须带编号、字段路径和来源，显示中文可改，修复范围不依赖中文正则。此项没有授权恢复真实临床作业。

同批多个有源增量要求按条目读取；同批可装配短答合并后通过来源、整批发布门禁及目标覆盖核对，才可作为未发布的局部草稿保存。其余条目继续保持未决，不得随已通过条目发布。失败检查点保存局部 wire 和来源解释；人工重试必须核批次、提示、模型线路和组件身份，重新执行当前门禁，并只核尚未闭合的条目。产品进程重启后不能依赖内存会话，来源限定补入使用独立新会话；已保存候选只供去重，不能授权改写。历史回执不可变，旧版本成功结果不因新能力直接采纳。

复用身份细化：首次解构提示与补答合同分别摘要；新成功回执显式记录是否实际调用补答。未使用补答的成功批次不因补答文案变化重读，但仍须逐项核冻结来源、基础提示、线路、Schema、装配器、现行门禁；使用过补答者须核相应合同。旧回执未记使用事实则保守重算，不从错误数或版本号倒推；新版摘要损坏拒绝预检。来源文本实质变更目前仍全局拒绝跨版本复用，只有建立逐批来源依赖闭包与跨章反例后才能进一步缩小范围。

## D5 正式工作台
API同源输出完整要求/选择/计算/缺口，前端不另算医学结论。待处理/全部条款一套左栏，组与成员稳定排序、深链优先、空态清楚；相同类别不自动合为同一问题。
中栏短依据/影响/行动，原文展开；右侧原件优先，引用/候选/浏览分开，snapshot资料版本与episode revision不混。
工作稿可核对，正式冻结真实授权；无研究者判断直接列条款未决和行动，不改为满足。
康哲3D、Ego Lite、1080P/2K/4K；不造手机布局或缩根字号解决密度。

## D6 更正与恢复
同观察由对象/属性/时间/原位置/派生证明，不凭同页。相关候选与确认影响分开；新版本重新派生，幂等。
补证使原范围“未发现”检索失效；局部纠错不全例重读。旧报告/事实/locator身份保留，Profile累积。
复用prepared_review_workflow/JobRunner父子依赖、取消与恢复；退役专用watch只消除现行引用，不另造框架。
