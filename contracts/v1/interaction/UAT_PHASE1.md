# V2 Phase 1 原型脚本化 UAT 合同

## 0. UAT 定位与冻结边界

| 项目 | 合同内容 |
| --- | --- |
| 合同标识 | `enrollment-review/v1/uat-phase1` |
| 目标 | 验证医学监查员能否在不理解电脑或人工智能内部实现的前提下，完成首屏进入、项目/阶段、方案、看板、受试者、Patient Profile、规则/证据、缺口/行动、批量和恢复任务 |
| 被测对象 | Phase 1 真实 React 前端壳与 `fixture/v1` 结构化示例数据；不得以旧 Markdown 或模型自由文本作为界面真相 |
| 样本内容 | 仅使用去标识化或合成的三类示例受试者：未发现明确障碍、明确障碍、缺口/冲突；不得使用真实病历完成本轮原型 UAT |
| 当前状态 | Phase 0.5 草案；通过脚本和指标后仍须用户明确批准，才能冻结默认首屏、术语、页面架构、信息密度和主要路径 |
| 非目标 | 本轮不证明临床准确性、不宣称后端已实现、不进行真实临床重审，不把 UAT 结果当作最终入组决定 |

## 1. 参与者、环境和操作定义

### 1.1 样本量

1. 正式冻结前至少邀请 10 名中文资深医学监查员，尽量覆盖不同项目经验；每人完成全部 14 项任务或明确标记不适用任务。
2. 3 至 5 人可作为预试，用于发现脚本、文案或 fixture 问题；预试结果不能单独作为 Phase 1.5 冻结证据。
3. 正式数据按“参与者 × 任务”计算，预计至少 140 个有效任务运行。若环境、fixture 或脚本本身出错，该次运行标为无效并说明原因，不得用删除失败样本提高完成率。
4. 参与者只接受统一的 3 分钟开场说明：这是一个入排审核工作台，资料均为合成示例，按页面完成任务即可。不得讲解路径、状态含义答案或证据所在位置。

### 1.2 环境矩阵

- 桌面任务至少覆盖 1280、1440、1920 宽度中的两个宽度，并至少有一次 100% 缩放；正式验收需三种宽度均有记录。
- 窄屏任务使用能代表实际使用的窄窗口；记录窗口宽度，不把某一设备像素值当作设计合同。
- 缩放任务分别记录 100%、150%、200% 浏览器缩放；改变的是浏览器缩放，不是只改变截图尺寸。
- 每次测试使用同一 `fixture/v1` 版本、同一页面版本和同一浏览器设置；更换版本必须重新建立测试批次。
- 观察者记录屏幕、计时、操作、错误和参与者原话，不记录真实个人身份信息。

### 1.3 计时与操作数

- **开始时间**：主持人读完“请开始”并显示任务起始页时开始计时。
- **结束时间**：参与者完成成功证据中的最后一项并口头确认“完成”时停止；若参与者明确放弃，记录放弃时间和原因。
- **一次操作**：一次鼠标点击、一次键盘激活、一次勾选/取消勾选、一次标签页切换、一次提交或一次朝目标方向的连续滚动。鼠标移动、页面自动滚动、系统自动打开目标页不计入。
- 组合输入按实际动作计数：点击输入框、输入文字、提交分别计数；连续输入文字算一次输入动作。主持人提示、替用户操作或指出下一步不计入参与者操作，而计为辅助。
- **关键证据操作数**：从任务指定的起始页面到实际文件/页和正确定位精度在首屏可见之间的操作数；打开后自动跳到页码不额外计数。
- 每项任务都记录 `用时（秒）`、`总操作数`、`关键证据操作数`、`是否获得辅助`、`错误类别`、`是否完成`和`备注`。

### 1.4 错误分类

| 分类 | 定义 | 记录方式 |
| --- | --- | --- |
| `E0` 无错误 | 无提示完成，成功证据全部满足 | 记录完成和用时/操作数 |
| `E1` 操作错误 | 点击了错误控件、重复操作、误取消或误提交，但未形成错误结论 | 记录发生位置、是否自行恢复 |
| `E2` 导航错误 | 进入错误项目、受试者、阶段、规则或页面，或无法返回正确位置 | 记录错误入口和恢复动作 |
| `E3` 术语/信息理解错误 | 把中文状态、缺口、责任方或阶段含义理解错，但未正式提交错误结论 | 记录参与者原话和页面线索 |
| `E4` 错误结论 | 因界面、状态或证据表现而把合成 fixture 的状态、规则或冲突判断成相反结果 | 立即按停止条件处理，计数必须为 0 |
| `E5` 证据/溯源错误 | 无法回到正确文件/页、把页码定位说成坐标定位、遗漏冲突来源或把转述当原始证据 | 记录可见精度和实际说法 |
| `E6` 任务状态/恢复错误 | 丢失已完成进度、重复应用动作、误把部分完成当全部完成或无法继续 | 记录页面状态和影响范围 |
| `E7` 布局/键盘错误 | 裁切、重叠、页面横向滚动、焦点丢失、勾选跳顶或键盘无法完成 | 记录视口/缩放和复现步骤 |
| `E8` 获得辅助 | 主持人以路径、按钮、状态或证据答案形式提示，或替参与者操作 | 该任务不计入无辅助完成 |

`E4` 是错误结论，不得用“参与者后来改正”抵销。E1 至 E3 若可自行恢复仍要记录；E5 至 E7 可能同时影响可达性和临床理解，按实际影响多选。

## 2. 统一成功与冻结门槛

### 2.1 每项任务的成功判定

任务只有同时满足以下条件才算完成：

1. 达到该任务列出的全部成功证据；
2. 没有 `E4` 错误结论；
3. 未由主持人提供路径、答案或代操作；
4. 参与者能用页面上的中文说明当前对象、阶段、风险、证据或下一步，而不是只说“系统显示可以”；
5. 任务结束时仍保留正确的受试者、阶段、规则、证据和选择状态。

### 2.2 临时量化门槛

- **无辅助完成率**：正式有效任务运行中，无 `E8` 且成功完成的运行数 ÷ 有效任务运行总数，暂定必须 `>= 90%`。同时单项任务低于 80% 时，不得直接冻结，必须先修订并复测。
- **错误结论**：所有正式有效运行中 `E4 = 0`。任何一例都触发本轮暂停、保留现场和复现记录；修订后从受影响任务重新开始，不能把错误结论算作完成。
- **关键证据可达性**：`UAT-P1-07`、`UAT-P1-08`、`UAT-P1-09` 中明确标记的关键证据，在正确文件/页和实际定位精度可见前，暂定每次不得超过 3 次操作；任一次超过即该运行失败并进入修订复测。
- **布局与键盘**：正式矩阵中不得有页面级横向滚动、文字/控件重叠、关键按钮裁切、焦点陷阱或勾选跳顶；任一项出现都需记录并修订。
- **主观反馈**：每名参与者完成后用 1 至 5 分评价“我能否看懂下一步”和“我是否信任证据定位”；平均分不替代客观门槛，只用于决定文案和信息密度是否需要修订。

### 2.3 用户批准

指标达到临时门槛不等于合同冻结。冻结前必须由用户明确批准以下事项：默认首屏（今日工作或项目看板）、中文状态词、Patient Profile 首屏过滤、规则/证据工作台分区、窄屏降级方式、关键操作路径和临时阈值。未获批准时，Phase 1 原型可以继续试用，但不得进入后续数据层核心实施。

## 3. 脚本化任务

每项任务按“主持人只读任务卡、参与者自行完成、观察者记录证据”的方式执行。任务卡中的受试者代号、规则编号和文件名使用当前 fixture 版本中的值；不要临时替换成真实信息。

### UAT-P1-01 首次进入与今日工作

**前置条件**

- 使用 1440 宽度、100% 缩放和干净的单用户原型入口。
- 已加载三个合成示例受试者、一个项目、多个审核节点和至少一项正在处理/待处理事项。

**用户任务**

> 请直接进入系统，找到今天需要优先处理的事项，并告诉我当前项目、受试者/对象、审核节点、主要风险和下一步。不要寻找登录或账户设置。

**成功证据**

- 直接进入今日工作或项目看板，不出现登录页或营销介绍页；
- 参与者能指出对象、当前节点、至少一个风险/缺口和下一步；
- 页面提供进入相关受试者阶段的入口。

**错误分类**

`E1`、`E2`、`E3`、`E7`、`E8`。

**计时/操作数**

从启动页开始，目标用时 `<= 60 秒`；记录总操作数，目标 `<= 5`。不得把主持人说明计入操作。

### UAT-P1-02 创建项目并选择独立阶段

**前置条件**

- 没有该合成项目的现有 V2 记录；提供一个正式方案版本和可选择的预筛、筛选、导入/洗脱、基线/随机阶段。
- 方案版本、研究期别和阶段名称已在 fixture 中预置来源。

**用户任务**

> 请从方案创建一个项目，确认研究期别，然后进入筛选阶段。请说明筛选和基线是否是同一个审核节点。

**成功证据**

- 项目保存了方案版本和研究期别；
- 筛选阶段被单独选中并在页面标题/当前位置显示；
- 参与者能说出筛选与基线是两个维度，不能把阶段合并成一个总状态；
- 未发生旧项目或其他阶段资料的静默带入。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E7`、`E8`。

**计时/操作数**

从项目入口开始，目标用时 `<= 180 秒`；记录创建、期别确认和阶段进入的总操作数，目标 `<= 12`。

### UAT-P1-03 方案工作台比较当前与新版本

**前置条件**

- 已有一个合成项目的当前规则草稿；另有一份新版本 fixture，至少包含一个新增、一个删除、一个逻辑或时间窗变化。
- 两个版本均提供可回到原文的定位。

**用户任务**

> 请在方案工作台比较当前版本和新版本，找到一处新增、一处删除和一处逻辑或时间窗变化，并说明哪一版仍是当前使用版本。先保存为草稿，不要发布。

**成功证据**

- 当前结果和新结果并列，变化类型清楚显示；
- 参与者能回到变化对应的方案原文；
- 新内容仍是草稿，当前规则版本没有被覆盖；
- 页面不要求用户理解内部运行方式即可完成比较。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E5`、`E8`。

**计时/操作数**

从方案工作台起始页开始，目标用时 `<= 240 秒`；记录打开比较、定位三类变化和保存草稿的操作数，目标 `<= 15`。

### UAT-P1-04 项目看板筛选、排序与阶段计数

**前置条件**

- 看板包含至少三个合成受试者：未发现明确障碍、明确障碍、缺口/冲突；每个受试者至少有筛选和基线两个阶段。
- 看板同时显示主状态和明确障碍、缺口、冲突、专业判断、溯源待办、后续关注计数。

**用户任务**

> 请只看筛选阶段，先筛出有当前节点缺口的受试者，再按阻断程度排序。指出明确障碍和资料缺口各是哪一位，并说明溯源待办是否等于阻断。

**成功证据**

- 筛选条件明确标出当前阶段；
- 结果顺序和计数与 fixture 预期一致；
- 明确障碍、资料缺口和溯源待办没有混为一个状态；
- 切换排序后回到列表，筛选、勾选和滚动位置保持。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 120 秒`；记录筛选、排序和查看计数的总操作数，目标 `<= 10`。

### UAT-P1-05 从看板进入指定受试者阶段

**前置条件**

- 已完成 UAT-P1-04 或恢复到同一看板状态；目标受试者同时有筛选和基线记录。

**用户任务**

> 请从看板直接打开这位受试者的筛选审核，不要先打开基线。进入后说出当前受试者、审核节点和证据快照，再返回看板。

**成功证据**

- 直接进入正确受试者的筛选 `ReviewEpisode`；
- 页面明确显示阶段、方案版本和证据快照；
- 没有把基线资料混成筛选结论；
- 返回后仍保留看板筛选、排序和滚动位置。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E6`、`E8`。

**计时/操作数**

目标用时 `<= 60 秒`；从目标单元格到正确工作台的操作数目标 `<= 6`。

### UAT-P1-06 Patient Profile 首屏风险过滤与完整资料

**前置条件**

- 打开缺口/冲突示例受试者的筛选阶段；资料中同时存在正常项目、异常/临界趋势、冲突、记录不完整和后续节点资料。

**用户任务**

> 请先只看这位受试者当前入排相关、异常、临界、趋势和资料缺口，再找到一项完整资料。请说明“资料中未提到”与“明确否认”是否相同。

**成功证据**

- 首屏先显示风险过滤和关键事件，而不是无差别铺开全部正常结果；
- 参与者能打开完整资料并返回风险视图；
- “资料中未提到”显示为资料缺口，不被说成明确否认；
- 冲突来源并列可见，后续阶段资料有阶段标记。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E5`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 150 秒`；从 Profile 首屏到一项完整资料和返回风险视图，目标 `<= 8` 次操作。

### UAT-P1-07 规则树、父子层级与证据跳转

**前置条件**

- 使用含嵌套 `全部满足/任一满足/例外条件` 的合成规则；目标子项有 `bbox` 或 `text_range` EvidenceSpan。
- 从指定受试者的规则工作台开始，目标规则父级编号已写入任务卡。

**用户任务**

> 请展开指定父规则，找到任务卡中的子项，说明父项和子项的关系，然后打开支持该子项的原文件证据。

**成功证据**

- 父级编号、子项编号和逻辑关系正确；
- 证据区域显示文件、版本、页码、摘录和实际定位精度；
- 从规则起始页到正确文件/页和定位精度可见不超过 3 次操作；
- 参与者没有把任一子项误说成独立父级或把 `任一满足` 说成 `全部满足`。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E5`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 90 秒`；关键证据操作数必须 `<= 3`，同时记录展开、阅读和返回的总操作数。

### UAT-P1-08 EvidenceSpan 降级与定位诚实性

**前置条件**

- 提供四个合成证据项，分别为坐标区域、文本范围、页内摘录和仅页码定位；至少一个包含明确“定位降级原因”。

**用户任务**

> 请依次打开页内摘录和仅页码定位，告诉我系统能确定到什么程度、哪些位置不能当作坐标高亮，并解释定位降级原因。

**成功证据**

- 页面显示“页内摘录”和“仅页码定位”等实际中文精度；
- 仅页码项没有坐标框或虚假高亮；
- 参与者能指出文件、版本和页码，并能打开整页查看；
- 定位降级原因自然可读，不能被误解为已经精确到文字坐标。

**错误分类**

`E1`、`E3`、`E5`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 120 秒`；每个目标证据从起始页到定位精度可见目标 `<= 3` 次操作，记录四级定位的总操作数。

### UAT-P1-09 缺口、责任方、可接受证据与到期节点

**前置条件**

- 缺口/冲突 fixture 至少包含记录不完整、引用资料未提供、必做检查未完成、结果字段缺失、待研究者判断、来源冲突、后续节点尚未到期和溯源待办。

**用户任务**

> 请找到一项当前节点缺口、一项需专业判断和一项溯源待办。对每项说出谁负责、要做什么、什么证据可以关闭、最晚在哪个阶段完成，并指出哪项不阻断当前节点。

**成功证据**

- 判断状态和缺口原因分开显示；
- 责任方只使用研究者方、CRC、CRA、申办方医学或项目组等自然中文；
- 每项有具体动作、可接受证据、到期节点、关联规则和来源；
- 溯源待办可计数但不被说成明确障碍；后续节点尚未到期不被说成当前缺口。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E5`、`E8`。

**计时/操作数**

目标用时 `<= 180 秒`；从当前组件到三类缺口的关键证据/责任信息目标 `<= 3` 次操作，记录总操作数和每类缺口操作数。

### UAT-P1-10 Action override（人工确认）与重新核对

**前置条件**

- 存在一个与具体规则组件绑定、可人工确认的开放行动；另有一个无关文件，不能满足该行动的关闭条件。

**用户任务**

> 请先查看行动为什么存在和什么资料可以关闭。对指定行动进行人工确认，填写真实可读的理由，然后查看关闭后的规则状态、前后差异和新的审核运行。不要把“行动关闭”直接当成规则通过。

**成功证据**

- 确认前显示具体对象、影响、来源和理由要求；
- 无关文件不会关闭该行动；
- 人工确认有理由、时间、操作者和不可变转移记录；
- 页面明确区分行动关闭与规则状态，若状态改变则显示新的审核运行和差异。

**错误分类**

`E1`、`E2`、`E3`、`E4`、`E5`、`E6`、`E8`。

**计时/操作数**

目标用时 `<= 180 秒`；从行动入口到完成确认和查看差异目标 `<= 12` 次操作，记录理由输入动作。

### UAT-P1-11 批量选择与范围确认

**前置条件**

- 看板至少有 6 个受试者，分布在多个页面或筛选结果中；目标只选择当前明确显示的 2 个对象。
- 提供一个可安全回看的批量动作，不改变合成 fixture 的最终临床结论。

**用户任务**

> 请只勾选任务卡指定的两位受试者，执行批量动作，并核对完成摘要。随后排序一次，确认没有其他受试者被包含、原来的勾选范围没有悄悄扩大。

**成功证据**

- 页面显示已选择数量和明确范围；
- 批量确认前显示对象和动作；
- 完成摘要只有两位指定受试者；
- 排序/刷新后选择、滚动和当前范围可解释，没有把跨页未见对象默认加入。

**错误分类**

`E1`、`E2`、`E3`、`E6`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 120 秒`；记录两次勾选、范围确认、执行和核对的总操作数，目标 `<= 12`。

### UAT-P1-12 任务中断与恢复

**前置条件**

- 预置一个已完成部分页面、一个尚未处理页面和一个处理失败页面的合成任务；已保存一处可继续进度。
- 允许用关闭浏览器再重新打开原型或使用“继续未完成事项”入口模拟中断；不得删除任务数据。

**用户任务**

> 请打开任务，确认已经完成的部分，然后关闭页面并重新进入。请继续未完成事项，指出失败资料、影响范围和下一步，不要重复已经完成的部分。

**成功证据**

- 重新进入后显示已保存进度；
- 已完成内容不重复生成，未完成和失败范围清楚；
- 失败资料对应的结果显示“资料发生变化，当前结果需要重新核对”或等价自然中文；
- 参与者能继续、稍后再试或取消未完成部分，且历史已完成部分仍保留。

**错误分类**

`E1`、`E2`、`E3`、`E6`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 150 秒`；从任务详情到恢复入口目标 `<= 8` 次操作，记录关闭/重开是否造成重复或丢失。

### UAT-P1-13 窄屏工作台与页面级横向滚动

**前置条件**

- 使用同一缺口/冲突 fixture；设置代表性窄窗口并记录宽度；保持 100% 浏览器缩放。

**用户任务**

> 请在窄窗口中打开这位受试者的规则、判断和证据，依次切换三个工作区，打开一个证据，再回到当前规则。请告诉我是否需要拖动整个页面才能完成。

**成功证据**

- 规则、判断、证据通过标签页或抽屉堆叠，当前选择持续可见；
- 可以打开关键证据并回到同一规则/阶段；
- 页面没有整体横向滚动，只有必要的密集组件内部滚动；
- 没有裁切状态词、按钮或工具提示，键盘焦点仍清楚。

**错误分类**

`E1`、`E2`、`E5`、`E7`、`E8`。

**计时/操作数**

目标用时 `<= 120 秒`；记录标签切换、证据打开和返回的总操作数，目标 `<= 10`；另记录是否出现页面级横向滚动。

### UAT-P1-14 100/150/200% 缩放下的关键路径

**前置条件**

- 使用 1280 或 1440 宽度，分别设置 100%、150%、200% 浏览器缩放；每个缩放级别从同一规则/证据 fixture 开始。

**用户任务**

> 在三个缩放级别分别打开 Patient Profile 风险项、规则子项和 EvidenceSpan，完成一次证据返回。请指出是否有文字覆盖、按钮裁切、焦点丢失或页面横向滚动。

**成功证据**

- 100%、150%、200% 均能完成关键路径；
- 中文状态、缺口、证据精度和主要动作不被裁切或覆盖；
- 150%/200% 可以收起侧栏、切换标签页或使用组件内滚动，但不能用缩小字号掩盖问题；
- 参与者没有因布局而得出错误状态或错误证据结论。

**错误分类**

`E1`、`E2`、`E4`、`E5`、`E7`、`E8`。

**计时/操作数**

每个缩放级别目标用时 `<= 90 秒`；关键证据操作数目标 `<= 3`；记录每个级别的裁切、重叠、横向滚动和焦点结果。

### 4.2 汇总计算

1. 先剔除有明确环境或脚本故障的无效运行，保存剔除原因和原始记录；同一问题修订后建立新批次，不与旧批次混算。
2. 按参与者和任务分别计算无辅助完成率，再计算全部有效任务运行的总体无辅助完成率；同时报告每项任务的分子、分母和 95% 置信区间或明确说明样本量不足以稳定估计。
3. 错误结论直接统计 `E4` 次数及其任务、页面版本和复现步骤；任何 `E4` 都不能被平均值抵销。
4. 关键证据报告操作数的中位数、最大值和超过 3 次的次数；UAT-P1-07 至 UAT-P1-10、UAT-P1-14 中的关键证据路径逐次列出。
5. 时间和操作数用于发现路径负担，不单独决定临床正确性；异常值不删除，必须说明是否由脚本、环境或参与者中断造成。
6. 主观评价按页面、术语、证据定位、恢复和总体负担分项汇总；主观“信任”不能替代证据定位的客观检查。

## 5. 运行停止、修订与批准规则

### 5.1 立即停止当前任务或当前批次

- 任何参与者出现 `E4` 错误结论；先保存现场、参与者原话、页面版本、fixture 和操作路径，再停止该任务并通知产品负责人；
- 关键证据超过 3 次操作且参与者因此无法确认正确文件、页码或定位精度；
- 出现页面级横向滚动、文字/控件重叠、焦点无法返回、勾选跳顶或 150%/200% 下关键按钮不可操作；
- 发现 fixture 预期状态、来源定位或阶段标签错误；本次运行标为无效，修正 fixture 后重新开始；
- 任务恢复后发现已完成内容丢失、重复应用行动或把部分完成显示为全部完成；
- 两名连续参与者在同一页面因同一中文状态词无法说明下一步；停止继续招募，先修订文案或信息层级。

### 5.2 继续、复测与停止收集

- 单个任务低于 80% 无辅助完成率：暂停该任务的后续正式运行，保留已收集数据，修订后重新跑该任务及受影响任务。
- 总体无辅助完成率低于 90%：不得声明通过；进入一轮定向修订，修订后新增独立参与者或重新开始受影响任务，不能只挑选原参与者的最好结果。
- 任何 `E4`：修复并在同一 fixture、同一任务和受影响路径上复测，直到用户确认错误原因已处理；错误计数历史保持为 1，不抹除。
- 所有任务达到临时门槛、剩余问题有负责人和复测结果后，停止继续打磨，提交用户决定；未经用户批准不得冻结合同或启动 Phase 2 数据层实施。

### 5.3 最终批准材料

提交批准前必须提供：任务逐项记录、样本量、无辅助完成率、`E4` 计数、关键证据操作数、视口/缩放检查、错误修订记录、未解决风险和默认首屏建议。用户批准的是可观察行为和门槛，不是对尚未实现的后端或临床准确性的承诺。
