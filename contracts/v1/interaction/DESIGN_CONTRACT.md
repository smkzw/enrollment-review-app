# V2 Phase 0.5 交互与视觉合同

## 0. 合同定位

| 项目 | 冻结内容 |
| --- | --- |
| 合同标识 | `enrollment-review/v1/interaction` |
| 适用人群 | 不熟悉电脑或人工智能工具的中文资深医学监查员 |
| 使用环境 | 单台 Mac、单用户、直接进入；不以登录、账户或审批流程作为前置条件 |
| 设计目标 | 让用户在首屏知道当前对象、审核节点、风险、证据位置和下一步；让用户可以在不理解系统内部实现的情况下完成工作 |
| 当前状态 | Phase 0.5 设计合同草案；须经用户批准并通过脚本化 UAT 后冻结，不表示前端已经实现 |
| 关键视口 | 1280、1440、1920 宽度；窄屏；浏览器缩放 100%、150%、200% |
| 交互边界 | 页面级不出现横向滚动；密集规则、表格和原文查看器允许组件内滚动 |

本合同冻结可见语言、信息优先级、布局约束、键盘路径、证据定位和异常恢复行为。它不把后台任务、OCR、审核或导出写成已经完成的能力；后续原型必须用版本化 fixture 和结构化 API 数据验证这些行为。

## 1. 面向用户的语言合同

### 1.1 可见状态词

可见文案只使用下列中文状态词。内部枚举、字段名和实现名称不能直接出现在页面、按钮、提示、空状态、错误提示或报告中。

| 业务含义 | 固定中文显示 |
| --- | --- |
| 入选条件满足 | 满足 |
| 入选条件不满足 | 不满足 |
| 排除条件未触发 | 未触发 |
| 排除条件已触发 | 已触发 |
| 资料或事实还不足以确定 | 暂不能明确 |
| 需要研究者作出方案要求的判断 | 需专业判断 |
| 同一事项来源不一致 | 存在冲突 |
| 当前审核节点尚不要求 | 尚未到期 |
| 规则明确不适用于当前对象或节点 | 不适用 |
| 当前节点存在确定性障碍 | 明确障碍 |
| 当前节点仍有到期缺口 | 当前节点缺口 |
| 只有后续节点事项 | 后续节点关注 |
| 当前未发现明确障碍 | 未发现明确障碍 |

### 1.2 可见缺口词

缺口必须与判断状态分开显示。页面同时给出“现在是什么状态”和“还缺什么/为什么不能确定”，不得把所有问题合并成“待补证”。

| 内部类别 | 固定中文显示 | 默认说明方式 |
| --- | --- | --- |
| `record_incomplete` | 记录不完整 | 资料中未见这项询问或记录，需要核对是否实际询问过 |
| `description_insufficient` | 描述不充分 | 已有提及，但缺少判断所需的具体细节 |
| `historical_source_unavailable` | 既往来源无法取得 | 当前转述不足以替代方案要求的既往客观来源 |
| `referenced_file_missing` | 引用资料未提供 | 资料中提到某份文件，但系统中尚未看到该文件 |
| `required_procedure_not_done` | 必做检查未完成 | 当前节点要求的检查、评分或程序尚未完成 |
| `result_fields_missing` | 结果字段缺失 | 报告缺少数值、单位、日期、参考范围或关键页 |
| `date_or_anchor_missing` | 日期或时间锚点缺失 | 无法计算病程、洗脱期或基线关系 |
| `professional_judgment` | 待研究者判断 | 客观资料已具备，仍需研究者按方案作出判断 |
| `source_conflict` | 来源存在冲突 | 同一事项的资料互相不一致，尚未核实 |
| `interpretation_conflict` | 解释材料与方案不一致 | 解释材料与正式方案或现行修订案存在差异 |
| `ocr_or_parse_risk` | 文字或数值需要核对 | 否定词、数字、单位、日期或表格读取不稳定 |
| `future_stage_not_due` | 后续节点尚未到期 | 该资料属于后续节点，当前不作为缺口处理 |
| `provenance_followup` | 溯源待办 | 当前资料可以使用，但建议补充更直接或更完整的来源；默认不阻断 |

### 1.3 可见任务词与错误词

任务状态使用自然中文：

- `准备中`、`正在整理资料`、`已完成`；
- `部分资料尚未处理`、`处理失败，可重试`、`已保存进度，可继续`、`已取消`；
- `资料发生变化，当前结果需要重新核对`；
- `当前没有符合条件的资料`、`当前没有待处理事项`。

系统发生异常时，面向用户只说明三件事：发生了什么、当前资料是否保留、用户下一步可以做什么。例如：

> 这部分资料暂时打不开。已经保存目前进度。请稍后再试；如果仍无法打开，请记录页面上的事项编号并联系系统支持人员。

不得显示程序堆栈、内部枚举、模型名称、请求地址、运行日志、调试指令或“重新跑流程”等技术措辞。内部记录可以保留关联编号，但关联编号不作为用户理解问题的前提。

## 2. 设计 Token

### 2.1 色彩

色彩多样但克制。颜色只能辅助分组和提醒，不能单独表达状态；每个状态必须同时有中文词、图标或形状差异。禁止渐变、装饰性光晕、彩色大面积背景和单一色调铺满页面。

| Token | 建议值 | 用途与约束 |
| --- | --- | --- |
| `canvas` | `#F5F6F7` | 页面底色；不使用纯黑或强烈彩色铺满 |
| `surface` | `#FFFFFF` | 工作区、表格和查看器底色 |
| `ink` | `#1F2933` | 主要文字；确保正文可读 |
| `muted` | `#52606D` | 辅助文字、来源说明和次要信息 |
| `line` | `#D6DCE2` | 分隔线、输入边界和表格线 |
| `teal` | `#0F766E` | 当前选择、主要操作和已确认信息 |
| `blue` | `#1D4ED8` | 可点击来源、证据跳转和信息提示 |
| `amber` | `#B45309` | 临界、待核对和后续提醒 |
| `red` | `#B42318` | 明确障碍、冲突或不可继续事项 |
| `green` | `#237A57` | 满足、未触发或已完成；必须同时显示文字 |
| `violet` | `#6D28D9` | 键盘焦点或少量辅助标识，不作为主色铺底 |

颜色对比、文字标识和图标需共同通过真实浏览器检查。红色不等于“不满足”，绿色不等于“可以入组”；最终含义以中文状态和规则来源为准。

### 2.2 字号、间距和形状

- 字号使用稳定的 `rem` 级别，不使用 `vw`、按视口变化的字号或为单一截图写死的字号。建议正文 `0.875rem`，辅助文字 `0.75rem`，工作区标题 `1rem`，页面标题 `1.375rem`；长中文文案优先换行，不压缩到不可读。
- 文字行高保持 1.45 至 1.65；关键数字、状态词和来源定位不得依赖极细字重。
- 间距按 4、8、12、16、24、32 的节奏使用；同一页面的表格行、工具栏和过滤区保持稳定高度，勾选或更新不能改变行高。
- 卡片、弹窗、按钮和输入框圆角不超过 8px；工作台分区使用平面分隔线和标题，不把页面做成层层嵌套的装饰卡片。
- 图标按钮采用项目图标库；图标按钮必须有可见中文工具提示和可访问名称。只有明确命令才使用文字或图标加文字按钮。
- 固定尺寸只用于可操作控件的最小点击区域、图标和表格基线；页面、分栏和主内容区使用 CSS Grid/Flex、`minmax()`、容器约束和自然换行，不以某台设备的固定像素宽度为主要设计依据。

### 2.3 信息密度

工作台优先支持连续审阅和比较：

1. 页面顶部只保留当前位置、对象、审核节点、主要风险和下一步；不放营销式横幅、欢迎词或功能宣传。
2. 规则、事实、缺口、行动和来源在同一任务上下文中互相链接，不要求用户记住内部编号。
3. 列表优先显示中心代号、受试者代号、审核节点、中文主状态和分类计数；次要全名、文件名和时间放在可展开区域。
4. 默认隐藏与当前入排判断无关的正常检查，但必须能进入完整资料；隐藏不等于删除。
5. 页面信息密度增加时先使用折叠、标签页、抽屉和组件内滚动，不用缩小字号或压缩点击区域。

## 3. 页面架构与响应式合同

### 3.1 全局入口

首屏不出现登录页。一级入口固定为：

- 今日工作；
- 项目看板；
- 方案工作台；
- 受试者与 Patient Profile；
- 行动中心；
- 报告；
- 任务与系统帮助。

Phase 1 同时提供“今日工作”和“项目看板”两种首屏原型：前者突出正在处理的事项、当前节点到期行动、冲突和近期变化；后者突出项目、受试者和各阶段全局状态。默认首屏不得凭偏好提前冻结，须由 UAT 测量并经用户批准；两者都保留为一级入口。

### 3.2 页面级滚动与分区

- `body` 和页面主容器禁止横向滚动；长中文、长文件名和列标题必须换行、折叠或使用组件内滚动。
- 规则树、密集表格、原文查看器、差异查看器可以在自身边界内滚动，并保留滚动位置、当前选择和焦点。
- 入排工作台桌面默认包含规则树、组件判断/行动/差异、识别文本与原始文件三个协同分区；窄屏使用标签页或抽屉堆叠，不把三栏压成无法阅读的缩略图。
- 组件内横向滚动必须显示清晰的边界和当前列上下文；滚动不能遮挡状态词、主要操作或证据来源。
- 任何滚动、筛选、排序、勾选或数据刷新都不能把用户带回页面顶部，也不能丢失当前受试者、阶段、规则或证据选择。

### 3.3 视口与缩放验收矩阵

下表是必须观察的行为，不是把视口写成固定设备像素设计。实现可以采用不同的网格，只要在每个样本中保持内容优先级和可操作性。

| 样本 | 必须可见或可完成 | 允许的降级 |
| --- | --- | --- |
| 1280 宽桌面 | 页面标题、当前位置、受试者/项目、审核节点、中文主状态、风险过滤、主要下一步和进入证据的路径；规则父子关系不丢失 | 工作台分区可以缩窄或切换标签页；专业表格可组件内滚动；页面不能横向拖动 |
| 1440 宽桌面 | 三个主要工作区在文字可读、来源可见和操作可达的前提下并列；筛选、排序、阶段入口不被折叠掉 | 次要说明进入折叠区，不用扩大空白或堆叠装饰 |
| 1920 宽桌面 | 内容有合理最大阅读宽度，长文本仍易扫读；额外宽度服务于比较、来源和历史，不产生大片无意义空白 | 侧栏或辅助历史区可以增加宽度，但不拉伸正文到难以阅读 |
| 窄屏 | 通过标签页/抽屉完成查看对象、切换阶段、打开规则、跳到证据和处理行动；当前选择持续可见 | 分区垂直堆叠；密集组件内部滚动；不要求页面级横向拖动 |
| 100% 缩放 | 全部正文、控件、状态和工具提示不裁切、不重叠 | 无 |
| 150% 缩放 | 文字放大后自然换行；主要动作仍可见；焦点和勾选状态清楚 | 侧栏收起、三栏改为标签页或组件内滚动 |
| 200% 缩放 | 无文字覆盖、按钮裁切、不可到达控件或页面级横向滚动；关键证据仍可打开 | 采用更窄的内容顺序和标签页；不通过缩小字号回避问题 |

缩放验收使用浏览器真实缩放，不以改变窗口截图尺寸代替。所有状态、空数据、错误、部分完成和恢复界面都要在至少一个桌面和一个窄屏样本中检查。

## 4. 首屏与分阶段入口

### 4.1 项目看板

- 每行代表一个受试者，每列或分组代表一个独立审核节点；预筛、筛选、导入/洗脱、基线/随机不得合并为一个总状态。
- 受试者代号、中心、当前节点、节点中文主状态和分类计数在首屏可见；计数至少能区分明确障碍、记录/证据缺口、冲突、专业判断、溯源待办和后续关注。
- 每个阶段单元格都是直接入口。点击筛选阶段时，页面标题和面包屑必须明确当前阶段；不能先进入受试者后再猜阶段。
- 排序和筛选只改变显示顺序，不改变实体 revision、证据或判断；用户返回列表后仍保留筛选、排序和滚动位置。
- 批量操作前必须显示“已选择 n 项”和具体动作；未勾选对象不得被包含。

### 4.2 Patient Profile 首屏

首屏按以下顺序组织：

1. 受试者代号、中心、项目、当前审核节点、方案版本、当前证据快照和最近一次资料变化；
2. 风险过滤：入排相关、异常、临界、趋势变化、存在冲突、资料缺口、后续节点关注；
3. 关键事件/异常摘要，每项带状态词、发生时间或日期精度、关联规则和可打开的证据；
4. 应备证据覆盖：已找到、证据较弱、已引用但资料未提供、尚未见到、后续节点尚未到期；
5. 完整资料按主题展开，包含人口学、疾病历程、症状体征、既往史/现病史、用药、操作、检查评分、过敏/感染/免疫、生育相关、社会环境和特殊经历。

“未记录”必须显示为资料缺口或应备证据状态，不能转成“正常”“否认”或“未发现异常”。同一事实的冲突来源并列展示；点击事件后应能看到关联规则、行动、来源文件、版本、页码和定位精度。

## 5. 规则树与证据工作台

### 5.1 规则父子层级

- 官方 IN/EX 父级编号、原文和适用范围保持在父级；子组件在视觉上缩进并有层级线或清晰的展开关系。
- 逻辑词以自然中文固定显示：`全部满足`、`任一满足`、`不满足以下条件`、`例外条件`、`需要研究者判断`。父级与子级不能排在同一视觉层级，也不能只显示最终父级状态。
- 折叠父级时保留父级状态、子项数量和缺口/冲突计数；展开后当前子项、来源和操作不跳位。
- 规则树键盘操作使用可见焦点：方向键移动同层或父子项，Enter 展开/收起或打开当前规则，Escape 返回上一层；鼠标和键盘结果一致。
- 规则、事实和证据选择必须同步显示，但不把 Agent 的解释性文字作为状态证据。

### 5.2 三分区工作台

桌面工作台按任务分为：

1. **规则区**：父子树、官方编号、阶段和组件状态；
2. **判断区**：当前组件事实、状态、缺口、责任方、行动、人工判断和 ReviewRun 差异；
3. **证据区**：识别文字、原始文件/页图、来源信息和定位精度。

三个分区共享当前规则、受试者和阶段选择。窄屏改为“规则”“判断”“证据”标签页或抽屉，但切换后仍保留同一选择，不得要求用户重新寻找对象。

## 6. EvidenceSpan 视觉诚实性合同

### 6.1 四级定位

每次显示证据都要同时显示文件名、文件版本、页码、原文摘录、定位精度和降级原因（如有）。定位精度固定使用以下中文词：

| 定位精度 | 可以显示的视觉效果 | 明确禁止 |
| --- | --- | --- |
| `bbox` | 在原始页图上显示与实际坐标对应的区域框，并同步显示页码和摘录 | 没有可靠坐标时画一个看似准确的框 |
| `text_range` | 在识别文字中标出实际文本范围，显示页码和摘录 | 把文本范围伪装成页图坐标框 |
| `page_excerpt` | 显示页图/原文页、页码和页内摘录；可以定位到摘录区域，但不得假称字符坐标精确 | 使用高亮框暗示已经定位到字符坐标 |
| `page_only` | 显示文件、版本、页码和“仅页码定位”；用户可打开整页查看 | 任何高亮、坐标框或“已精确定位”字样 |

统一可见表达为：`定位精度：坐标区域 / 文本范围 / 页内摘录 / 仅页码`。如果发生降级，显示“定位降级原因：……”并使用自然中文解释，例如“原文可以确认页码，但无法稳定确认具体文字位置”。没有 `bbox` 时前端不得显示坐标高亮。

### 6.2 证据跳转行为

- 从 Patient Profile、规则树、行动或看板进入证据，最多三次明确操作到达实际文件/页；打开后当前摘录、页码和定位精度在首屏可见。
- 返回上一级时保留原规则、受试者、阶段、筛选、滚动和焦点。
- 证据缺失时显示“资料中提到这份文件，但当前尚未提供”，提供“查看引用位置”和“记录待补事项”，不显示空白高亮。
- 来源冲突时并列显示来源和各自定位；不把其中一个来源隐藏为“系统选择”。

## 7. 键盘、焦点与操作稳定性

### 7.1 键盘路径

- 所有可操作控件均可由 Tab/Shift+Tab 到达，顺序符合页面阅读顺序；跳过重复导航后进入当前任务。
- 规则树、阶段入口、证据链接、日期选择、筛选、勾选和主要动作均可用键盘完成；每个焦点位置都有清晰的外框或底色加文字提示。
- 打开弹窗、抽屉或证据查看器后，焦点进入标题或第一项；关闭后回到触发控件，不回到页面顶部。
- `Enter` 执行当前按钮或打开当前项，`Space` 切换勾选，`Escape` 关闭当前临时层；不可把键盘输入误当成删除或确认。
- 图标按钮提供中文工具提示和可访问名称，例如“返回上一项”“打开证据”“筛选”“下载报告”；工具提示不能替代可见主要标签。

### 7.2 勾选、筛选和列表稳定性

- 点击复选框、全选、排序、过滤或批量更新时，页面不得跳顶，列表滚动位置不得丢失，已勾选项不得无故清空。
- 全选只作用于当前明确范围，并显示数量和范围；跨页选择必须明确告知范围，不能静默包含未见对象。
- 数据刷新后按稳定 ID 恢复选中项和当前对象；如果对象已变化，显示“资料发生变化，当前结果需要重新核对”，并让用户决定是否打开新结果。
- 任何危险或不可逆动作都要先显示对象、影响、可恢复方式和确认理由；按钮文字使用“确认关闭”“重新打开”“取消本次操作”等自然中文。

## 8. 加载、空、错、变化与恢复状态

组件必须显式区分以下状态，不能把它们都显示成一个转圈或“暂无数据”。

| 情况 | 页面可见文案 | 必须提供的下一步 |
| --- | --- | --- |
| 正在加载 | 正在整理资料，请稍候 | 保持当前对象和阶段；允许用户离开，不丢失已保存选择 |
| 空集合 | 当前没有符合条件的资料 | 说明当前筛选/阶段；提供清除筛选或进入完整资料 |
| 无待办 | 当前没有待处理事项 | 显示当前节点和资料范围；不把无待办显示为“满足” |
| 部分完成 | 部分资料尚未处理 | 显示已完成和未完成范围；允许查看已完成资料和继续处理 |
| 暂时失败 | 这部分资料暂时打不开 | 保留目前进度；提供稍后再试和记录事项编号 |
| 资料变化 | 资料发生变化，当前结果需要重新核对 | 显示影响的规则/阶段；提供查看差异和开始新的审核 |
| 可恢复 | 已保存进度，可继续 | 提供继续、查看已完成部分和取消未完成部分 |
| 已取消 | 已停止这次处理，已完成部分仍保留 | 提供查看已完成部分和重新开始；不删除历史结果 |
| 访问受限于业务范围 | 当前资料不属于这位受试者或审核节点 | 显示正确的项目/阶段入口；不显示内部路径或程序原因 |

内部 `stale`、`checkpoint`、`job` 等词不出现在用户界面；可见内容只解释资料是否仍需核对、进度是否已保存和下一步如何继续。

## 9. Action 与人工确认

- 每个缺口或溯源待办都显示“为什么需要、需要补什么、谁负责、何时完成、什么资料可以关闭、关联规则和来源”。
- `溯源待办`与阻断缺口分开显示；不能用颜色或位置暗示溯源待办已经阻断入组。
- 人工关闭或人工确认时，页面用中文说明所针对的具体规则、已查看证据、确认理由和影响范围；理由不能为空。
- 关闭行动只表示该行动的专属缺口谓词已满足或用户完成了有理由的人工确认，不等于规则自动通过。若结论改变，页面必须显示新的审核运行和前后差异。
- 系统自动关闭、人工确认、重新打开和被新资料取代分别使用不同中文词和图标，并可查看不可变的时间、操作者、理由和来源。

## 10. 明确禁止的界面形态

1. 不做营销页、英雄区、产品宣传口号或把主要工作藏在介绍页；打开系统直接进入可用工作台。
2. 不出现程序、模型、日志、调试、请求或内部枚举术语；不要求医学监查员理解人工智能如何工作。
3. 不使用嵌套卡片堆叠页面，不用大面积渐变、光晕、装饰球或单一色彩铺满界面。
4. 不用固定设备像素写死主布局，不为单张截图牺牲窄屏、缩放和长中文。
5. 不用颜色单独表达风险、是否满足、资料缺口或冲突。
6. 不把父规则与子规则渲染为同一层级，不把阶段结论合并为一个总状态。
7. 不因复选框、排序、筛选或刷新让页面跳顶、选择丢失、焦点丢失或打开错误受试者。
8. 不用虚假的坐标框、虚假的高亮或“已精确定位”掩盖 EvidenceSpan 降级。

## 11. 视觉与交互验收记录

每个原型版本验收时至少记录：

- 测试视口、浏览器缩放、日期和构建版本；
- 页面级横向溢出、文字裁切、控件重叠、布局跳动和无意义空白的检查结果；
- 看板阶段入口、Patient Profile 首屏风险过滤、规则父子树和证据三次操作内可达性的结果；
- 四级 EvidenceSpan 的实际视觉表现和降级文案；
- 键盘顺序、焦点返回、勾选稳定性、工具提示和空/错/变化/恢复状态；
- 未通过项的中文描述、影响对象、复现步骤、修订编号和重新检查结果。

本合同的视觉验收只能证明界面行为符合合同，不能证明临床判断正确。临床状态、来源和 Action 仍以 `NODE_CONTRACTS.md` 的 Gate 合同和后续领域测试为准。
