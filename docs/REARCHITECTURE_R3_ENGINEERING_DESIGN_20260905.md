1. 导入正式 DOCX 方案及现行修订，系统完成期别识别、结构解析与控制点解构；用户不预处理文件。

5. 查看个例全景及当前节点问题；点击一个问题到原件页和对应摘录，必要时核对手写。
6. 分开显示明确障碍、记录缺口、未做检查、缺研究者判断、冲突与后续节点关注；每项说明责任方、所需证据和到期节点。
7. 增量补充资料后仅重算受影响范围；原筛选结论保留。关闭行动必须满足具体缺口谓词，并生成新审核记录。

## 5. 方案理解：全方案覆盖不等于全方案重识别

DOCX OOXML 是语义结构来源，LibreOffice 渲染提供页码/位置。保留全文单元清单，每个单元有“与本阶段入排相关/补充/非相关/待确认”处置；廉价结构解析只做一次。全文相关性由独立语义 harness 判断，关键词仅排序，不决定遗漏。

先理解研究期别、流程、官方 IN/EX、合并用药、洗脱、导入、随机/给药前条件及相关定义；模型按需求回看相关正文，不为每条标准重新发送所有页图。原文可完整交给支持范围内的模型，但系统仍校验覆盖、编号、引用和输出；仅上下文/质量确需拆包时分解，不按固定极小包堆调用。

每个控制包括：适用节点、必须做什么、应达到何条件、禁止何事件/暴露、窗口与锚点、例外、证据要求、研究者判断、跨章出处。跨章要求不得伪造新的官方 IN/EX 编号。

方案明示锚点优先；无明示回溯锚点时按用户裁决分别以筛选和基线节点回溯，保存推导依据。部分日期用区间推理，不填造精确日期。阈值、药物类别、病程均来自当前方案，不来自程序员的病例知识。

方案侧维持 DOCX-only（2026-09-01 已批准修订），不因早期 PDF 要求悄悄重开已撤路线。恢复 PDF 方案导入须另作范围决定。

### 6.1 通用 harness 与当前部署分离

沿用既有 PageReaderRoute、配置、任务冻结与传输模块，逐调用点收敛，不平行新建一套模型注册框架：

- 角色合同描述需要视觉、JSON、证据范围、输出结构、是否双盲，而非“此模型适合此疾病”。同一任务两主读使用同一临床提示/条款包；不同任务可以有不同职责提示，但不能按病例答案特调。
- 能力记录包括 provider/公开模型/响应身份、输入与输出物理限制、共享思考额度、支持的 effort 和实际映射、JSON兼容、取消/流式/用量能力及核验版本。名字或 /models 声明不替代最小真实探针。
- 部署配置选择模型，不写死在临床 evaluator/对账/提示中。能力不满足应在任务前明确拒绝，不静默降档、删图、缩输出或换模型。跨provider复用同模型不构成新的独立意见。
- 新语义任务预算起点65536、单次 length 重试最多131072（思考+正文共享）；不得从旧8192/16384默认继承。必须检查真实服务上限和输入+输出约束；若不支持指定额度，明确登记限制，按有语义边界的拆分或请用户决定，不把“给足额度”解释为强行填满输出。此前48,000仅为历史运行的批准额度，不覆盖本轮新任务。
- 针对性复核不得把xhigh覆盖为high。任务冻结请求/有效档位与额度，恢复校验一致性；改配置不修改旧作业或重新领取两轮。
- 云端当前最多2–3并发；本地主读先1路，所有本地平台在同一资源所有者下串行，包括OCR安排。复用已有准入与租约，不为提速同时加载另一平台。当前并发是部署资源策略，不是通用模型能力假设。
- MTPLX解码兼容措施属于传输合同，不混同temperature等采样设置。当前产品页读适配器对纯文本严格JSON使用AR，对带图请求使用MTP，因为当前服务拒绝图片与AR组合；这不是所有模型通用的设置，也不代表当前视觉接入已通过。以实际请求模态、服务版本及回执核验兼容性，保留既有文本AR修复。先核端点实际权重与effort，再最小视觉/JSON/额度探针，不动其他线程服务。

泛化验收必须同时覆盖：SAR/D001已见集与按受试者隔离的未调参留出资料；与疾病无关的结构化反例；模型适配器替身与真实当前双模型。变形测试包括重命名研究/药物标签、改变页序/条款序、等效单位、同值异物/异时、重复页和多文件同页码。重命名只用于合成测试，不改真实原件。单纯接受任意model字符串不等于兼容；新模型无需改临床业务代码才是目标。

泛化验收分开报告三个层级，不能相互替代：同方案未见受试者、未参与提示调优的新方案、不同模型的接入与同源任务表现。仅更换研究名称、疾病标签或II/III期标记不算新方案验证；新方案须具有不同的实际要求结构。留出资料一旦用于修订提示，即归入校准资料，并另留未调优资料复核。缺少某层真实材料或模型接入证据时，该层标记未验证，不宣称适用于所有疾病或模型。

每项优化须说明属于通用职责提示、来源与规则合同、确定性算法、传输适配或部署参数，并提供适用范围及反例。不得因某页错读而把该页答案、固定药名、评分阈值、条款编号或默认日期写进共享提示/算法。模型不支持所需能力时保留明确限制；兼容不同模型不意味着所有模型都有同等质量，也不意味着为提高某模型分数放宽证据要求。

## 7. 页级输出与精确归一化

模型仅负责观察：原文字段标签、原始值、单位/日期/极性原文、摘录、位置及手写。规范值与归一化键由代码生成，不能要求模型自己猜算法。

删除页级判定词。has_eligibility_value 仅表示是否返回观察，不表示受试者符合标准；空/非空与布尔值矛盾时拒绝，不自动翻转。无价值须保留模型给出的理由，而非只存系统模板语句。

工程修订：废止旧设计 `float→g`。使用 Decimal 保留全部有效数字；零值不等于缺失；保留原始数值字符串。日期验证有效日历，部分日期保留粒度。单位剥离只在合法数值/单位语法内执行，不能把普通词尾当单位；不同量纲不得比较。等效单位转换只使用有版本的确定性换算，不能模糊近似。

新归一化算法必须具备版本身份：旧记录按旧版本解码，新结果使用新版本；禁止原地重算历史键。提示文本哈希与版本、响应原文哈希、Schema 版本一起冻结。当前试跑 v2/v3 仅技术证据，不能转为正式发布记录。

## 8. 实体关联与对账

核心问题不是“两个字符串一样”，而是“同一来源对象在同一时间的同一属性是否相同”。事实键必须绑定页面、来源目标/项目、时间粒度、属性、极性、数值和单位。手写还须绑定所指报告/项目、签署人和日期（可未知），不能用同页两处 NCS 凑双源。

来源标签与展示字段名分开：先按实际来源区域、原文标签及可证明的结构关系关联；不同展示名称不自动构成临床冲突。字段同义表需通用、有版本和测试；不能为 SAR/D001 或本轮合成页添加专用别名。

没有可靠来源对应时列为“待核对关联”，不自动择优。位置匹配容差、手写置信阈值须在金标校准，未批准前不把浮动阈值用于自动采信。

双主读必须是不同模型读道、相同页哈希/条款包；同读道重复不算两票。普通事实单源候选可见但不进入确定结论；关键字段冲突阻断相关组件。手写按A/B相同对象逐项核对，仍有分歧保留，不存在C缺席字段或第三票。

deterministic 的方向信号丢弃，事实保留。semantic 信号仅供下游参考；investigator_judgment 只报告判断记录与针对对象，不由模型决定临床意义。

“一致”“单源”“关联待核对”“矛盾”分别展示，避免大量标题同义被误标为医学冲突。受影响组件边界可追踪，不能一处非关键标题差异阻塞全部个例。

### 8.1 来源关联的实施补充（2026-09-06，尚未验收）

v9/v10 真实病历页均出现双读有效但零采信。自由位置说明不是稳定来源身份；仅增加提示不足以修复。按 §8 落实以下确定性关联，不引入第三模型普通事实仲裁：

1. 页任务从已冻结的完整处理修订取得侧车有效文本版本及哈希。该文本只供后置文字定位，不加入两主读消息，不作为新的事实来源。
2. 对每条原文摘录解析唯一字符范围，绑定文档版本、页码和文本哈希。允许逐字符 NFKC 与空白规范化，并保留每个规范字符至原文偏移的映射；不删除数字、日期、否定、比较符号或其他标点。规范化后重复、不可定位、OCR 与原件内容不一致时保留待核对，不用模糊距离或猜测范围。
3. 两主读均唯一指向同一范围时，该来源范围可替代自由 location_text 作位置身份；保留两份原位置说明。仅同段并不充分：对象、属性、日期精度、极性、规范值及单位仍须一致。字段同义使用通用版本表，不写研究、药物或疾病特例。
4. 同一范围任一路多条同对象观察时拒绝自动配对；时间或对象未知/冲突不由范围一致消解。摘录范围不同也不自动按重叠率合并。
5. 新对账版本保存定位依据并纳入结果身份，正式 coverage 复核按同一冻结文本重新计算；历史记录及历史对账只读保留。缺少定位依据时沿用未解决状态，禁止将新算法套到旧结果冒称已验收。
6. 必测：同范围不同展示名、不同页/版本、重复原文、多观察歧义、不同日期/精度、否定/不确定、零值/不同单位、OCR 失配、篡改文本哈希，以及恢复后的对账身份一致性。随后用保存的真实双读结果和正式隔离入口验证，再决定是否需要新的模型实测。

当前已实施未采信投影的唯一范围与相互链接，以及正式 Reconciler、任务冻结与 coverage 复核接线。来源关联先检查同一范围、对象与时间的观察唯一性，再比较数值和单位，不能将第三条矛盾观察隔离后采信其余两条。真实保存记录复放与临床效果尚待验证，不能据此宣称零采信问题已经解决。上述补充不改变主读组合、单阶段结构、采信临床标准或金标阈值。

## 9. 持久执行与恢复

权威元组从服务端活动节点派生：受试者/项目/节点修订/规则修订/证据快照/完整处理修订。客户端只发操作意图，不提交权威页清单或任意 coverage ID。

每页两个独立读步骤；成功读道通过 PreparedStepResult 将 PageReviewRecord、checkpoint、步骤成功与进度放在同一租约事务提交。网络调用在事务外，不持有 SQLite 写锁。两个读道成功后进入该页对账；手写已在两主读内读取，不另启动第三读。

最终覆盖步骤依赖全部页的终态处置。失败页也必须有明确失败类型和待复读状态；不能仅因依赖失败使覆盖缺席。运行级 coverage 与最终可采信 coverage 区分，后者禁止带未解决失败页进入发布。

取消、重启、超时均以持久状态为准；成功读道不重跑，失败读道按原模型恢复；新提示/新页/新条款包新建修订。租约过期返回结果不能提交。取消中旧作业不得直接当新任务续写。

并发按§6.1部署资源策略统一准入，覆盖多批次，不使用每批新semaphore冒充全局限制。MTPLX服务与OCR的生命周期由资源所有者协调，保留OCR原有8路准入，不因本地服务维护重启无关进程。

## 10. 正式 API 与下游接线

新增节点级“整理资料”持久命令，返回 job ID 和可恢复进度。正式路径为：原件处理修订 → R3 页任务 → 覆盖校验 → Normalizer → 事实发布 → Profile；不得自动退回旧 OCR 语义链。

R3 coverage 由服务端从该任务已冻结身份的完成结果选取并再次校验。规范化既有可选 coverage 参数只用于历史回放兼容；新路径必须显式 R3 身份。手工构造 coverage 的离线测试不算 API 整链证据。

GET 进度展示已完成主读/页数、失败页、未核实手写、最后实际活动、允许恢复操作。不得从文件数推估“已审核人数”。错误返回问题、影响与下一动作；维护详情不在临床页面直接展示。

## 11. 临床判断与 Profile

保留全部 R3 状态/缺口矩阵。沉默不是否认；既往病史转述在方案允许时可用并加强溯源；来源冲突不可自动择优。

无阈值异常仅报告单批注或对应节点病历分析可作为研究者书面判断。箭头/圈画不算判断；无判断记录 → professional_judgment 与研究者行动，不能输出满足/未触发。CS/NCS 本身须明确针对何项目，不能从一项传播到整张报告。

Profile 从最早可证明事件到当前节点截点，包含事实、事件、用药暴露、缺失证据与冲突。首屏优先异常、临界、趋势、入排相关内容；正常全量信息可展开，不丢失。用药起止/持续状态不明需明确显示，不填造日期或停药。

Assessor 只给语义候选；Evaluator 计算逻辑/时间/阈值/状态。Critic 条件触发，不能改写事实或绕过出处。Action 关闭不等于规则通过，须新 ReviewRun。报告与界面同源，不另跑“报告模型”制造第二套结论。

## 12. 桌面交互与视觉

遵循康哲 site 轨及现有 React 视觉体系，1920×1080、2560×1440、3840×2160 与缩放测试；不加移动替代布局。以可调整分栏与组件内滚动使用大屏，避免固定狭窄卡片和巨大空白。

证据工作台：问题/规则、结构化事实、原件连续滚动相互定位；有可靠坐标才红框，无坐标显示页级或摘录定位。保留原始图像，不能拿 OCR 重排文本冒充原件。

个例全景：节点与病程/用药/检验泳道，同一事件点击下钻原文；筛选到基线切换明确截点。项目看板从真实节点摘要派生，今日工作从真实行动派生，不启用试用 Repository 兜底。

中文文案用“待补资料”“待研究者判断”“资料有矛盾”“原件未能读取”，不用“门”“信号”“payload”“executor”等工程词。技术错误码仅维护详情可见。按钮图标/状态/弹窗一致，文案精简，强调与阴影辅助层次而非装饰堆积。

不优先新增桑基图、雷达图或复杂动效；只有真实工作问题需要才添加。视觉审阅与真实数据验收分别留证，截图美观不能替代工作流通过。

## 13. 评测与性能

既定金标门槛保留：双模型并集事实召回 ≥0.95，金标负判定静默漏判 0；但增加独立报告的“双源采信召回、单源待核对率、错误冲突率、手写采信召回、错误关联率”。并集高不等于采信高，不能互相代替。

负判定静默漏判必须通过下游组件判断或明确待核对问题的完整映射评估；页模型按设计不下判定，不应要求其输出排除结论来迎合评分。

金标按受试者/来源隔离校准与保留集，人工标准只事后对照；SAR/D001 不做两套业务分支。工程反例覆盖精度、零值、单位、日期、否定、重复读道、多位置手写、跨节点与缺失页。

性能记录 P50/P95、首个可见结果、总完成时间、每页调用次数、重试成本和手写占比；禁止用一页合成图像估算全库。优先精简重复输入、缓存稳定条款包、持久续跑和受控并发，不擅自降低指定 effort 或减少必读页。

## 14. 迁移、清理及发布

保持旧项目、原件、历史报告只读。新架构真实验证使用新项目/隔离副本；失败快照不激活。不重写已发布规则与旧事实，不将旧 key 直接变成新算法 key。

清理前分为：源码/未提交实现、权威原件、已接受证据、未决错误证据、可再生缓存。只清最后一类及已被替代且有清单的过程文件；任务/session数据库不在一般清理范围内。

打包检查 `uv sync --no-dev`、应用启动、前端预构建和双击入口。服务端语义模型不可用不应阻碍已有资料的只读浏览。端口先核对进程归属，8900 当前不应当作本项目固定端口。

## 15. 采纳、延后和不采纳

采纳：确定性精度修复、代码归一化、通用实体关联、读道级持久化、正式 API 接线、运行/采信覆盖分层、真实待办与恢复提示、证据同源报告。

延后至相邻阶段：巨型模块拆分、真实今日/项目看板、Action 闭环、报告美化、性能预算正式阈值、旧原型退役。

不采纳：未经授权自动换主读、追加第三票、当前引入DeepSeek、将页读固定拆为四次调用、模型自算规范化键、为病例硬编码修复、为了通过测试关闭验证。Qwen现为用户指定的完整第二主读，不再沿用“只手写”的旧限制。

## 2026-09-06 冲突针对性复核（辅助事实复核已接线，尚未临床验收）

用户后续已批准最多两轮的辅助机制。产品持久任务与提交/只读状态接口已接线；结果合同明确区分尚未采信的一致候选、仍待用户核对、读取失败及等待下一轮。辅助读记录仅在自身任务凭据中保存，不进入正式事实、对账或覆盖；也不能作为研究者判断缺失的条款报告依据。相同原对账始终使用同一复核任务，配置变化不能重新领取两轮。条款级书面判断缺失报告仍按§16单独实现，不能把当前事实复核接口说成该链已完成。

当前复核使用§6指定的两主读及其足额档位，不恢复历史MiniMax路线。仅有分歧时针对原件交叉核实，最多两轮，仍有冲突再交用户确认。初读仍为单阶段双主读，不将所有页面改成固定四读；不新增普通事实第三模型。

拟定边界：
- 第一轮各路独立回看源页及可定位区域，只提供中性的核查目标与必要上下文，不提供初读候选值或对方答案。目标无法可靠定位时看整页，不猜裁剪坐标。
- 第二轮仍各自依据原件作答；如评测引入匿名差异，必须标记已见候选，不再声称完全独立。不得以两路受提示后趋同自动替代盲读证据。模型允许“不清楚/原件自相矛盾/现有候选均不支持”，不能强迫二选一。
- 一路多次结果始终只算一路，GLM low与high不构成两票；不得把新旧轮次任意拼成多数票。每轮双方记录分别绑定源页、节点、冲突、提示、模型和强度。
- 对原件本身矛盾、缺文件或缺研究者书面判断，不用模型纠偏消除。跨页有明确来源时可以提供已有关联原件，不因跨页一律要求用户补资料；无来源关联则保持待核对。
- 原读不可修改；复核记录新增并指向原冲突。现有coverage已经有前驱链，未来应扩展既有受控关系，不另造平行选择器。不同版本不可冒充同一运行，失败保留原冲突与覆盖。

#### 17.1.1 绑定链修复规格（2026-09-13，待独立审阅与隔离评测）

当前实现的三种记录不能互相替代：normalizer的supported_requirement_ids仅证明模型声明了一个冻结范围内的资料要求编号；FactRuleLink是资料要求/组件索引；AssessmentCandidate.PredicateObservation目前必须逐字段复述Evaluator结果。这三者都不是已核实的原子条件语义对应。不得直接将其中任一个改名为“已验证绑定”后接入。

沿现有事实规范化、不可变任务和发布校验链扩展，不新增另一套调度器。按以下顺序形成可验证闭环：

1. **冻结输入**：当前authority、RuleSet修订、组件及原子条件原文/身份、已校正事实集合与原件摘录/定位哈希。触发与例外分别列出；跨章定义随对应要求提供，不把整份病例反复附加。不存在于冻结输入的事实、条件或摘录一律拒绝。

3. **独立验证**：代码核实完整身份、原文/事实版本、定位、实际值、单位、日期精度和允许来源；这些结构检查不能独自证明语义正确。语义对应仍须按批准的隔离双源核对评测验证，分歧不自动采信。旧FactRuleLink可缩小候选集，不能成为唯一证明。
4. **版本化输出**：保存绑定所对应的组件/谓词、事实及具体属性、来源、输入哈希、实际调用回执和校验状态；同一事实可支持多个条件，条件身份须含组件上下文，不能仅按subject.attribute全局合并。事实校正、规则修订或节点/快照变化后，旧绑定不得自动沿用。
