# 0.2.0 ACCEPTANCE：里程碑验收

每项检查写明"怎么做"和"什么算通过"。证据记入 `05_PROGRESS.md` 的里程碑段落：代码提交号、数据副本位置、操作步骤、截图路径（截图不入库则写本机路径）、读回结果。

## 1. 通用要求

- **证据等级分开写**：①单元／合同测试通过；②真实数据在真实界面中走通；③与人工 IE 表对照通过。三者不能互相替代，报告里分别标明。
- **真实性**：不得在真实病例中注入错误来制造测试类别；需要反例时用合成夹具，并在报告中标注"合成"。
- **截图**：写明页面、视口（CSS 像素）、浏览器缩放和操作步骤；同一里程碑中不同视口的截图哈希必须不同。
- **模型调用**：每次真实运行记录模型路由、调用次数、耗时、输入输出 token（上游未返回则写"未知"，不写 0）。

## 5. 不能算通过的情况

- 只有单元测试或零调用预检，没有真实界面操作。
- 工作稿中有资料的确定性条款仍全部是"证据不足"或"需研究者判断"。
- 结论无法追到原件页。
- 用手写 JSON、直接改数据库或开发脚本代替 MM 的界面操作。
- 拼接不同数据副本、不同代码版本的截图。
- 用比例或"基本完成"描述未通过的检查；未通过就写未通过，并写第一个阻断点。
