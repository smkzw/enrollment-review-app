## 1. 为什么有 0.2.1

0.2.0（10-11 至 10-17，204 次提交）做成了这些事：用户本人审定并发布了正式规则包；31001 与 26002 都有真实工作稿；界面上的真实更正与补证能自动出新稿并保留旧版；父项"无法判定"从 40 降到 9。

但最后两天结果停住了：最后一轮 183 项判断一项未变，系统问题 49→48，高置信结论 0 条（问题卡片等于全部条款），34 条用药项全部无法判定，不调模型的自动出稿仍要 8.4 分钟。四个原因：

| # | 原因 | 0.2.1 的处理 |
|---|---|---|
| H1 | **置信失效**：OCR 扫描把每个数字、日期、单位都标为阻断级风险，同页任何一个未核风险就让整页事实降级，没有一条结论能是高置信 | 取消置信轴；改为只挂在具体数值上的"核对标记"，且只来自真实信号（D33，§7–§8） |
| H2 | **抽取慢而贵，于是长出复用证明管道**：每页提示约 8.6 万字符、一次一页、单页 779 秒；为避免重读写了约 450 行"保留／复验／复用证明"代码，又让重算变慢 | 验证副本可重建＋简单缓存（D36）；设性能目标并精简抽取（D37，§10） |
| H3 | **没有评测基准**：计算逻辑 6 天升了 50 个版本，没有准确率度量；用户反馈变成逐个病例的裁定 | 先做评测脚本；可用标准＝场景门槛＋人工 IE 对照（D32，§9） |
| H4 | **"阻断"回潮**：至少 7 处又变成拦住结论，其中一处让读取失败的条款反而得到高置信"未触发" | 逐处改为降级；读取失败不得套用"本次资料未见记录"（R-C6） |

**0.2.1 的目标**：在不加新功能的前提下（D35），让 31001 与 26002 达到场景门槛，然后与中心 31 的人工 IE 表对照，最后在 D001 上验证换方案。

## 2. 产品定位（D1、D23）

面向医学经理／医学监查人员的**入排信息与风险展示**：受试者在预筛／筛选／导入／基线各节点，随资料到达显示每条要求的结论、需要核对的地方和需补的资料，并能简洁地回到原件。

平台不管理最终入组决定，不收集决定理由、评估意见或处理反馈，不做签发流程。后台保留真实出处与不可变旧版本，但不把内部留痕铺满界面。

用户：中文母语、有临床研究背景的医学经理。运行环境：本地单台 Mac、单用户、直接启动、无登录；最大化桌面宽屏（1080P／2K／4K 及合理缩放），沿用康哲视觉系统；不做移动端。与共享"医学经理工作台"的对接不在 0.2.1 范围。

## 3. 原则

| 编号 | 原则 | 判断标准 |
|---|---|---|
| P1 | 先收敛，再扩展 | 不推进验收门槛的工作一律后移（D35） |
| P2 | 人只在两处介入 | ① 规则包审定（每个方案版本一次）；② 问题卡片（每例少数几个） |
| P3 | 降级，不阻断 | 某一步失败或不确定时，相关条款显示"证据不足"并挂核对标记或系统问题，其余条款照常出结论。只有错受试者／错项目／方案版本不一致／文件哈希不符才整体停止 |
| P4 | 全出处 | 每个结论可回到方案原文与病例原件页；有可信坐标才画框，否则定位到页 |
| P5 | **正式记录只追加；开发数据可重建** | 只追加、不覆盖的对象：原件、OCR 原文、用户本人审定的规则包、用户决定、用户看过的工作稿及其报告。开发中需要重算时，在新的验证副本或新的处理修订中重算，靠缓存省调用，不写“旧结果仍可复用”的证明（D36） |
| P6 | 临床状态与系统问题分开 | 方法不支持、读取失败、模型输出不合法属于系统问题，不以临床结论词出现 |
| P7 | 展示，不管理最终决定 | 见 §2 |
| P8 | AI 起草与判读，程序核对与计算 | LLM 做语义（起草、抽取、语义判读）；逐字核对、单位换算、日期计算、逻辑组合、结论组装由确定性代码完成 |

## 4. 范围

### 4.1 方案范围：四块（D3、D31）

| 块 | 内容 | 在规则包中的形态 |
|---|---|---|
| S1 | 官方入选／排除标准全文，保留官方编号与父子逻辑 | `Rule`（IN/EX）及 `RuleComponent` |
| S2 | IN/EX 明确引用的章节、附录、表格 | 作为对应条款的定义依据，原文可展开 |
| S3 | 研究流程表中当前节点及之前应完成的检验检查 | REQ 条目：是否做了、结果是否齐全、是否在时间窗内 |
| S4 | 禁用药、合并用药、伴随治疗章节中**与入排有关**的限制 | 禁用药条目（药物或类别＋洗脱窗＋方向＋原文），**归入对应排除条款**（D34） |

不纳入：方案其余部分。仅适用于研究药物治疗期间的补救治疗许可不属于入排要求，也不豁免入组前洗脱（D31）。MM 审定时可手工把藏在其他章节的资格要求加入 S2。

### 4.2 审核节点与时间

节点沿用 `ReviewStage`（预筛、筛选、导入、基线），由方案决定。锚点日期取 `ReviewEpisode.anchor_dates`。

- 节点开始日与资料截至日分开保存：方案相对时间窗按节点开始日；明确纳入本节点的复查可用到资料截至日（D26）。
- 方案未写明起点的回溯期（如"6 个月内"），筛选按筛选日期、基线按基线日期分别回溯；日历月不折算固定天数（D21）。
- 当前节点汇总只看已到期子项；后续节点子项显示"未到期"，届时重新审核（D13）。

## 5. 主流程

```
F1 方案上线（每个方案版本一次）
   上传方案 → AI 起草 IN/EX、范围清单、REQ、禁用药条目 → MM 分类审定（疑点优先，可集中批准）→ 发布

F2 受试者节点审核
   选受试者与节点 → 上传资料（全量或增量）→ 自动：OCR → 定向抽取 → 逐字核对 → 判定
   → 问题卡片：只列需要处理的点；其余已自动判定的条款折叠

F3 处理问题
   卡片 → 条款列表＋判定详情 → 按需打开宽幅原件侧栏 → 更正数值／上传补证／标记已核
   → 自动重算受影响条款 → 新版工作稿（旧版保留）

F4 时间线、历史与报告
   个例时间图（病史、用药；检验只列异常）；版本列表与对比；打印版报告
```

### C. 判定

| 编号 | 需求 |
|---|---|
| R-C1 | 确定性条款：三值求值器 `expression.py` 计算，事实按 `variable_id` 选取 |
| R-C2 | REQ：已做且结果齐全→满足；有记录但缺必需结果→证据不足（"结果不完整：缺 X"）；资料提到但未见报告／未见记录→证据不足；检查日期超出时间窗→不满足；属后续节点→未到期 |
| R-C3 | **禁用药（D34）**：按类别归到对应排除条款下判定，不再单列成几十行。① 资料中完全未提及该类药→按 R-C6 判未触发（范围内没有用药史来源时挂 `NO_HISTORY_SOURCE`）；**只有该类别成员清单已经用户确认时才可使用①**，否则对应排除父项出一张“用药类别成员待确认”卡片；② 有使用记录但停药日期不清→每种药一张卡片“需确认停药时间”，该条为证据不足；③ 明确在洗脱窗内使用，或记录为持续使用→已触发；④ 明确在洗脱窗开始前已停药→未触发；⑤ 药名在类别表中找不到→一张卡片“未能归类的用药”列出药名；⑥ 限制带剂量、途径、适应证等限定而记录中没有该信息→证据不足；⑦ 依据只有处方／医嘱／购药记录→挂 `PRESCRIPTION_ONLY`（处方可作用药史，但不证明实际剂量、连续使用和停药，D19 与 2026-10-06 决定）。判断“未触发”只看与用药有关的问题（用药史页面读取失败、用药抽取失败、存在未归类药名），不受全例其他系统问题影响 |
| R-C4 | 语义条款：LLM 在本例资料中找支持或否定的原文并引用，程序逐字核对；资料矛盾须两处原文对同一完整条件作相反陈述；限定条件（严重程度、频次、因果）未明不等于成立 |
| R-C5 | 研究者判断条款（D14、D15）：对应节点原始病历中的相关诊断、疗效、意愿、明确否认可作依据，不另要求书面判断或签名。入选要求未见支持记录→证据不足。排除要求：检验未违反阈值且病历未记载相应排除依据→按 R-C6 判未触发；已有异常、冲突、时间不清或未读清时不套用 |
| R-C6 | **"本次资料未见记录"政策**：对已提供且已读取的范围，常规既往史类排除条款未见记录→未触发，原因写明资料范围；使用前先做确定性关键词扫描，有命中则改出卡片"资料中有相关字样，请核对"；按此政策得出的结论单独成组。**该条款的任何读取目标失败、缺失、被拦截或超出长度上限时，不得使用本政策**：已有正向发现（不满足／已触发）照常显示；否则该条显示为“系统问题（原文读取失败）”，不得为满足或未触发 |
| R-C7 | 入选要求不能从沉默推出满足（D15） |
| R-C8 | 结论组装与父规则汇总（D13）：入选＝全部已到期子项满足才满足，任一不满足即不满足；排除＝任一已触发即已触发，全部未触发才未触发；其余取需处理程度最高者（资料矛盾＞需研究者判断＞证据不足）。未结构化子项按系统问题处理 |
| R-C9 | 系统问题栏：写明影响哪些条款与替代路径（如"已列原文，请人工判断"）；受影响条款显示"系统问题"，不用临床结论词 |

## 7. 结论与核对标记（D33，替代 0.2.0 的"置信"）

### 7.1 六种结论（不变）

| 入选条款 | 排除条款 | 含义 |
|---|---|---|
| 满足 | 未触发 | 有依据表明条件成立／排除情形不存在 |
| 不满足 | 已触发 | 有依据表明条件不成立／排除情形存在 |
| 证据不足 | 证据不足 | 判定所需资料在本次范围内没有找到或没有读清 |
| 需研究者判断 | 需研究者判断 | 方案要求研究者判断，且病历中没有可用记载 |
| 资料矛盾 | 资料矛盾 | 同一变量同日／同一来源位置不同值，或两处原文对同一完整条件相反陈述 |
| 未到期 | 未到期 | 属于后续节点 |

另有"不适用"（确有依据不适用）与"系统问题"（不是临床结论，见 R-C9）两种显示状态。

### 7.2 核对标记

- **取消高／低置信。** 结论只显示上表状态。
- 需要人看一眼的地方用“核对标记”表示，分两类：
  - **事实级**：挂在具体数值、日期或用药记录上（§8.1）；
  - **结论级**：挂在结论上，说明这个结论本身的依据不完整（§8.2）。
- 标记只来自 §8 列出的信号。“这是一个数字／日期／单位”本身不是标记。
- MM 对某条结论“标记已核”后，该条的标记清除；所用事实的修订号与规则内容不变时，已核状态在新版工作稿中继续有效。

### 7.3 问题卡片规则

出现卡片的条款：不满足／已触发；证据不足；需研究者判断；资料矛盾；**或**该条带任何事实级或结论级核对标记；**或**按 R-C3 产生的用药卡片。受系统问题影响的条款放在卡片列表末尾单独一组，**也计入验收**（G1-1）。满足／未触发（无标记）、未到期、不适用折叠在“其余已自动判定”中；按“本次资料未见记录”判定的单独成组。

## 8. 核对标记清单（D33）

代码中的标记枚举沿用现有 `RiskFlag` 名称（`LOW_OCR_CONFIDENCE`、`SINGLE_WEAK_SOURCE` 等，已存事实按此序列化），只改变它们的产生条件；新增的标记追加新枚举值。

### 8.1 事实级

| 标记（枚举） | 产生条件（必须有代码真实产生） | 显示文案 |
|---|---|---|
| `LOW_OCR_CONFIDENCE` | 该页 OCR 输出出现重复（`OUTPUT_REPETITION`）；或 OCR 结果带有可用的低置信片段且与该数值位置重叠（现有扫描器不产生此类片段，C1a 须确认后才能启用这一来源） | 识别可能有误 |
| `DECIMAL_SENSITIVE` | 数值乘以或除以 10 会改变该条结论（防小数点、数量级误读） | 小数点敏感，请核对原件 |
| `IMPLAUSIBLE_VALUE` | 换算后超出变量字典的合理范围 | 数值不合理，请核对原件 |
| `NEAR_THRESHOLD` | 与方案阈值相对差 ≤5%（可按变量配置） | 临近阈值 |
| `ATTRIBUTION_UNCERTAIN` | 检验项名称与数值不在同一行／表格行，或可能取自参考范围 | 数值归属需核对 |
| `HANDWRITTEN` | 抽取输出 `handwritten=true` | 手写内容 |
| `DATE_ROLE_UNCLEAR` | 只有一个日期且无法判断采样／报告／就诊，而条款对日期敏感 | 日期含义不清 |
| `PARTIAL_DATE` | 日期只有年或年月，且影响时间窗判断 | 日期不完整 |
| `UNIT_INFERRED` | 原文无单位，单位为推定 | 单位为推定 |
| `PRESCRIPTION_ONLY` | 用药依据的记录类型只有处方／医嘱／购药 | 仅有处方记录 |
| `SINGLE_WEAK_SOURCE` | 唯一来源为邮件、口述记录 | 来源较弱 |
| `MULTI_RESULT_DISAGREE` | 窗内其他结果会导致不同结论（R-B7） | 窗内多次结果结论不一致 |
| `AGE_RECORDS_DIFFER` | 同日年龄记录不一致但结论相同（D28） | 年龄记录不一致 |

### 8.2 结论级

| 标记 | 产生条件 | 显示文案 |
|---|---|---|
| `NO_HISTORY_SOURCE` | 按 R-C6 判未触发，但资料范围内没有病历／既往史／用药史类文件 | 资料中无相关病史来源 |
| `PAGES_NOT_FULLY_READ` | 该条需要的变量所适用的页中，有页未读完 | 部分资料未读完 |
| `UNDATED_RECORDS_EXCLUDED` | 有相关记录因日期不清未被采用，而它们可能改变结论 | 有日期不清的相关记录 |
| `LLM_READING_ONLY` | 满足／未触发只由模型对原文的理解支持，没有确定性事实 | 依据为模型对原文的理解 |

**不作为标记**：OCR 扫描器为“数字、小数点、单位、日期、阴性／正常等极性词”打的类别风险。这些只说明“这类内容容易出错”，不是检测到的错误，继续用于 OCR 风险核对界面，不进入工作稿标记。

残余风险须如实告知用户：印刷体清晰页面上的个别误读，若未触发上述信号，会以无标记结论出现。缓解手段是 `DECIMAL_SENSITIVE`、合理范围、临近阈值与归属核对，以及 G1、G2 的抽查。

## 9. 可用标准（D32；细则见 `04_ACCEPTANCE.md`）

1. **G1 场景门槛**（31001 筛选、26002）：每个受试者节点临床卡片 ≤10 张、受系统问题影响的条款 ≤3 条；无标记的满足／未触发结论抽查零错误；更正后 2 分钟内出新结果；一个 25 页左右的受试者首次处理 ≤20 分钟；页面打开 ≤3 秒；用户本人完整操作一遍。
2. **G2 人工 IE 对照**（中心 31 其余受试者）：静默漏判＝0（人工判不合格的条款，系统给出无标记的满足／未触发）；不合格提示率 ≥95%；每例卡片中位数 ≤10；有资料时确定性条款可判率 ≥80%。差异逐条归因，用户确认。
3. **G3 留出**：D001 从上传方案走到工作稿一次，记录审定耗时、新增变量数与对照结果。
