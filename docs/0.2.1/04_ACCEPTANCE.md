# 0.2.1 ACCEPTANCE：验收门槛

证据记在 `05_STATUS.md`（结论＋文件名），原始证据在本机 `output/0.2.1/`。三种证据分开写：①单元／合成测试通过；②真实数据在真实界面走通；③用户验收或人工 IE 对照。前一种不能代替后一种。

## G1 场景门槛（31001 筛选；26002）

| ID | 检查 | 通过标准 |
|---|---|---|
| G1-1 | 卡片数 | 两个受试者节点各自的临床卡片 ≤10 张，且受系统问题影响的条款 ≤3 条（按 PRD §7.3 计数；每条系统问题写明替代路径） |
| G1-2 | 无标记结论的正确性 | 统筹者把两例全部"无标记的满足／未触发"逐条对照原件，错误数写入状态表；用户再随机抽 10 条。**任何一条错误都要找到原因并修正后重新抽查** |
| G1-3 | 重算速度 | 在界面上更正一个数值或标记已核，到新工作稿可看 ≤2 分钟（不调模型），记录 3 次 |
| G1-4 | 首次处理速度 | 31001（24 页）在新验证副本上、以新提示版本（缓存未命中）从资料启用到工作稿可看 ≤20 分钟；记录页数、调用数、缓存命中数、并发数 |
| G1-5 | 页面速度 | 工作台、原件侧栏打开 ≤3 秒（1080P 下实测 5 次取中位数） |
| G1-6 | 安全 | 合成测试：任何读取目标失败的条款（含病史类排除条款）不会出现满足／未触发；用药"未触发"只在类别成员已确认且无用药相关问题时出现；错受试者／方案版本不一致／文件哈希不符整体停止；单页读取失败只影响该页 |
| G1-7 | 用药 | 31001 的用药相关内容出现在对应排除条款下；无日期使用、未归类药名、成员未确认的类别各自形成卡片；没有几十行单列的"无法判定"用药项；用户已确认类别成员清单 |
| G1-8 | 规则包 | 当前工作稿使用的规则包由用户本人正式审定（`verification_only=false`），包含 S2–S4 |
| G1-9 | 回归 | 全量后端与前端测试相对 0.2.1 起点无新增失败 ID；新逻辑都有测试 |
| G1-10 | 用户现场验收 | 用户本人从受试者列表进入 31001 → 处理卡片 → 打开原件 → 做一次更正 → 看到新结果与旧版本，并给出"通过／不通过＋原因" |

G1 未通过时，状态表写"未通过"和第一个阻断点，不用比例描述。

## G2 人工 IE 对照（中心 31 其余受试者）

| ID | 检查 | 通过标准（G1 通过后由用户确认最终阈值） |
|---|---|---|
| G2-1 | 导入 | 受试者与条款编号对齐率 100%，对不上的逐条列出 |
| G2-2 | 静默漏判 | 人工判"不满足／已触发"的条款中，系统给出"无标记的满足／未触发"的次数＝0 |
| G2-3 | 不合格提示率 | 人工判"不满足／已触发"的条款中，系统给出不满足／已触发、证据不足、需研究者判断、资料矛盾或带标记结论的比例 ≥95% |
| G2-4 | 卡片负担 | 每例卡片中位数 ≤10 |
| G2-5 | 可判率 | 有资料时，确定性条款给出满足／不满足／未触发／已触发的比例 ≥80% |
| G2-6 | 差异归因 | 每条差异归入：系统错判／系统漏提示／人工遗漏／资料不足／方案解读分歧，附页码；用户确认归类 |
| G2-7 | "本次资料未见记录"组 | 单独统计该组与人工结论的一致率 |

## 不能算通过的情况

- 只有单元测试、零调用预检或合成数据，没有真实界面操作。
- 卡片数靠隐藏真实问题降下来（例如把证据不足改成未到期、把系统问题移出列表）。
- 无标记结论抽查中发现错误，未修正就交付。
- 用开发脚本或直接改数据库代替用户的界面操作。
- 拼接不同代码版本或不同数据副本的截图与结果。
