# Phase 4 最终回归复测报告（Pi / minimax-m3(high)）

## 概览
- 测试入口：`http://127.0.0.1:4234`，无登录直达工作台。
- 测试对象：受试者 `S-BARRIER`（01｜合成研究中心），审核节点「筛选」，方案 V1.0。
- 当前活动资料版本：1 个（"建立完整资料快照 · 1 份资料 ·2026-08-21"，标识"当前有效"），文件 `synthetic_screening_record.pdf` 第 1 版，标识"当前资料"。
- 视口：1366×768 / 1920×1080 / 3840×2160 三个分辨率均验证。
- 测试资料：`synthetic_screening_record.pdf`（68 KB，1 页）以及一个临时 25B TXT 文件（仅用于覆盖 `新增资料` 分支），均仅走到确认前并取消，未改变当前有效版本。

##关键能力（已验证通过）

1. **默认进入阅读态**：进入证据工作台时，顶部 band 直接显示"当前资料版本 当前有效"，左栏文件显示 `synthetic_screening_record.pdf 第 1 版 当前资料` chip，中栏默认显示识别文本与校对后文本对比、右栏默认仅 PDF 图片（无任何红框遮挡）。未发现"待发布/加工中"语义。
2. **上传区对称展开/收起**：默认显示一个 `补充或重建资料` CTA按钮；点击展开后显示 `暂不补充`（收拢）+ `补充资料` / `建立完整资料快照` 选项。`暂不补充` 点击后完全回到阅读态，无残留提示。
3. **重复文件不再诱导确认上传**：上传与当前快照内容哈希相同的 PDF 时，`确认前复核` 区只出现 `复用已有处理结果 / 内容重复 / 该文件内容与上一有效快照中已存在的资料完全相同`描述，并只显示单一按钮 `返回当前资料`。**不出现 `确认上传` 按钮**，从交互上消除误点路径。
4. **新文件 / 不支持文件分类精确**：上传 `test_text.txt`（25B）时显示 `本次将处理 / 新增资料`，明确告知"该文件内容与文件名均未出现在上一有效快照中，为本次新增资料"，并保留 `取消预览` / `确认上传`。上传 `fake.zip`（无法读取）时显示 `无法纳入处理 / 无法读取`，`确认上传` 按钮 `disabled`，红色提示"当前选择中没有可纳入的资料"。
5. **完整快照模式区分明显**：选 `建立完整资料快照` 上传相同文件显示 `需要重新识别` chip + "完整资料快照重新纳入了与基准内容相同的文件" 说明，保留 `取消预览` / `确认上传`。点击取消后回到阅读态，无持久信息条。
6. **撤销导航/未提交保护**：在校对工具（textarea）中输入未提交内容后，点击 `帮助` / `返回资料页` / 左侧 `受试者与资料` 都会触发原生 `confirm("当前页面有尚未提交的校对内容，确定离开吗？")`，选"取消"留在原页、文字保留；选"确定"放行。
7. **"原始识别"与"校对后文本"一眼可区分**：
   - "原始识别" 卡片：h5 + subtitle "原始记录"，bg `rgb(251, 251, 250)`，左 border `1px solid rgb(214, 220, 226)`，底部有"可在下方文字中直接拖选需要校对的内容"提示。
   - "校对后文本" 卡片：h5 + subtitle "审核使用"，bg `color(srgb 0.952941 0.973137 0.971569)`（淡绿白），左 border `3px solid rgb(15, 118, 110)`（深绿/蓝绿），无提示文字。
   - 两卡片在颜色、border宽度、标题副文三个维度均不同。
8. **快捷入口只到摘要、不展开整页工具**：中栏顶部 `evidence-review-nav` 含 `识别文本 / 文字校对 / 风险核对 / 原件定位` 四个按钮，点击后仅跳转至对应区段的标题位置：
   - 风险核对：区段仍折叠，显示 `查看 12 项核对记录`。
   - 原件定位：区段仍折叠，显示 `查看 12 处原件定位`。
   - 文字校对：区段仍折叠，显示 `需要修订识别文字`。
   - 识别文本：直达标题。
   - 用户必须主动展开才能看到完整内容，避免一次跳转展开所有长内容。
9. **原件定位逐项展开，单一红框**：点击 `查看 12 处原件定位` 展开后，每条仅一行 `"识别项" 原文位置 在原件中查看`；点击 `在原件中查看` 后右栏出现**唯一**红框（3px solid rgb(192,0,0)，bg透明），无遮字填充。`aria-label` 简洁为 `重点标注：U/L` / `重点标注：μmol/L` / `重点标注：.`，无 "区域坐标/文本范围" 工程话术。点击不同项时旧框消失、新框出现；同时右栏滚动到对应位置（实测12 项中每项都能进入可视区，scrollTop 在 0/15/62/92 之间精确切换）。
10. **红框位置真实、与 PDF文字对齐**：以 `重点标注：2026-08-21` 为例，CSS `left:19.9142%, top:23.1067%, width:10.2986%`，实际渲染 `left:19.91%, top:23.10%, width:10.30%`，与 PDF 顶部的日期栏文字位置匹配。
11. **"区域坐标 /文本范围 / 原生文本层" 工程话术已彻底清除**：整页 `document.body.innerText`扫描后只剩 `原文位置` 这一处展示性用语，其他工程术语全部消失。
12. **错误态可恢复**：访问不存在的 `?episode=invalid` 显示 "未找到这个审核节点" + `重试` 按钮，无残留工作区内容。
13. **受试者目录与证据页一致显示当前有效**：受试者 S-BARRIER 卡片下方显示 `筛选资料当前有效`文字 + `查看筛选资料` 按钮；进入证据页后顶部 band `当前资料版本 当前有效`，左栏快照 `当前有效` chip，三处语义一致，无历史/草稿混淆。
14. **右侧缩放/滚动保留**：右侧 PDF 缩放按 10% 步进（100→110→…→180），放大后滚动条出现、画布不溢出容器。`aria-label` 中文化（"放大原始资料"/"缩小原始资料"）。
15. **多视口兼容**：1366×768（三栏 249/456/332）、1920×1080（382/700/509）、3840×2160（843/1545/1124）均无布局错位；4K 右栏 PDF 渲染约1054×1490 px，肉眼可读。

## 问题（按严重度排序）

### P0 — 阻塞当前节点核对工作
1. **1366×768 视口下"原始识别 /校对后文本"文本被静默截断，且无可见滚动条**
   - 操作路径：1366×768 视口进入证据工作台。
   - 页面事实：两个 pane 宽 198 px、高 487 px；pre 内容高度 870 px。`getComputedStyle(pane).overflowY === 'visible'`，pre 自身 `overflow: auto` 但 macOS-style overlay-scrollbar 在未滚动时不可见。文字被截断在 384px 高度处（约一半内容），未显示任何"可滚动"提示。
   - 实际影响：在常见笔记本电脑/外接1366×768 显示器上，监查员只能看到一半识别文字（前半部分）；翻不到后面需依赖鼠标滚轮（不一定有效，因为 pre 内 scroll 不能用页面 wheel）。
   - 系统级建议：pane 自身 `overflow-y: auto`，或在窄视口时把两 pane改为上下堆叠；至少加入明显的滚动提示（"还可滚动查看7 行"）。

### P1 — 影响日常效率
2. **左侧"文件与页清单"在单一文件时仍分3 个 section，且文件名重复显示 3 次**
   - 操作路径：左栏。
   - 页面事实：`文件与页清单 → synthetic_screening_record.pdf 第 1 版 当前资料` → `资料页 → 识别页清单 1 → synthetic_screening_record.pdf 第 1 页 页面已就绪` → `资料快照 1 → 当前有效 → 建立完整资料快照 · 1 份资料 ·2026-08-21`。
   - 实际影响：左栏 382px（1080P）下滚动可见，1366 768 下左栏仅 249px，监查员要为这 1 份 PDF 看三段标题 +重复文件名。
   - 系统级建议：单一文件/页时把文件级与页级合并；或只显示"文件级摘要" + 点击展开页清单。
3. **左栏底部无"返回资料页"快捷入口**
   - 操作路径：左栏底部。
   - 页面事实：`返回资料页` 仅在顶部 band 出现，左栏底部无等价控件。
   - 实际影响：监查员把左栏滚到底部选完版本后，要滚回顶部才能点返回。
   - 系统级建议：在左栏底部加一个等价的"返回资料页"链接。
4. **顶部 band `当前资料版本 当前有效` 用纯文本，缺色彩 chip**
   - 操作路径：顶部 band。
   - 页面事实：`当前资料版本` 后接纯文字 `当前有效`，与左栏 `chip="当前有效"`重复但无视觉强调。
   - 实际影响：监查员不会第一眼识别"这是当前唯一可用版本"。
   - 系统级建议：把 `当前有效` 改为绿色 chip，历史/草稿用对应色彩 chip，与左栏一致。
5. **顶部 `帮助` 链接与左侧 `系统帮助` 入口重复**
   - 操作路径：顶部 / 左侧导航。
   - 页面事实：两条入口都跳转 `#/help`，但文案与目的无说明差异。
   - 实际影响：监查员会困惑哪个是入口。
   - 系统级建议：合并或在文案中说明"快速提示 / 完整文档"。
6. **风险核对区段展开后整段 1973+px 高，初始视口只看到 2 项**
   - 操作路径：点击 `风险核对` → 点击 `查看 12 项核对记录`。
   - 页面事实：12 项展开后中栏 scrollHeight 约 2275px，可视高度 633px，仅前 2 项可见。
   - 实际影响：监查员看到前 2 项后还需滚动才能看到其它10 项；与 `原件定位` 折叠方案不一致。
   - 系统级建议：与原件定位一致，风险项也默认折叠为一行（"日期：2026-08-21 已核对"），点击展开单条详情；或维持分组折叠。

### P2 — 文案 / 细节可改进
7. **快捷入口滚动是即时而非平滑**，监查员感觉突兀。
8. **左栏"页面已就绪"使用工程话术**，建议改为 `识别完成` 或 `原件可见`。
9. **顶部 band 中 `项目 / 受试者 / 审核节点 / 方案版本` 用纯文本，关键元数据视觉权重较弱**，建议至少"项目"与"受试者"加 chip 或粗体。
10. **4K 视口右栏 1124px 宽度过宽**，PDF 渲染 1054px 后两侧留白多，建议加 max-width 600-800px。

## 真实产品缺陷 vs 测试资料限制 vs 个人偏好

**真实产品缺陷**（影响生产用户）：
- 1366×768 视口下文本被截断、无可见滚动条（P0 项1）
- 风险核对区段展开后视口内只显示 2/12 项（P1 项6）

**测试资料限制**：
- 多页 PDF、跨页定位跳转、多受试者、跨项目、历史快照版本、失败文件重试链路均无法在本测试资料上验证（测试资料只有 1 页 1 个当前有效快照）。

**个人偏好**（不构成缺陷）：
- 顶部 `帮助` 与左侧 `系统帮助` 双入口——属 UX 取舍问题，合并更佳但单独存在也可接受。
- 4K 右栏过宽——属于大屏布局策略问题，并非阻断。

## 是否阻断 Phase 4

**P0 项 1（1366×768 视口文本截断）** 是真实阻断，需要在放行前修复。

P1 项 6（风险核对展开后视口内只显示 2/12 项）也建议在放行前修复，否则监查员日常操作需频繁滚动。

其余 P1/P2 项可在不阻塞真实使用的前提下于首个迭代内修复。

## 未验证范围
- 多页 PDF（>1 页）的连续滚动、跨页定位跳转。
- 多快照/历史版本切换（"历史版本"/"草稿"/"待发布" chip 行为）。
- 多受试者、跨项目选择。
- 真实大文件（>10MB）、批量上传、断点续传。
- 多 DPI / 高分屏 + 浏览器缩放联动。
- 不同方案版本下的同受试者节点切换。
- 资料追踪"登记一项被提及资料"的完整提交与持久化。
- 风险项 `重新核对` 流程（所有12 项默认 `确认原文无误`，未主动修改以避免误提交）。

## 整体结论

**条件性通过**：本轮 Phase 4 在阅读态默认进入、上传区对称展开/收起、纯重复文件不再诱导确认上传、"原始识别 / 校对后文本"一眼区分、快捷入口只到摘要不展开长内容、原件定位逐项展开单红框且不遮字、错误话术清除等多项上达到临床监查可演示状态。但 P0 项 1（1366×768 视口文本截断）仍属硬阻断，建议先解决再放行；P1 项 6（风险核对展开后视口内容不足）建议同步修复。
