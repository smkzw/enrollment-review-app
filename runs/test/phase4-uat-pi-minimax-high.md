## 关键能力（已验证通过）
1. **无登录直达工作台**，左侧导航仅有「方案工作台 / 受试者与资料 / 系统帮助」三项，无多账户或所有权切换，符合设计。
2. **三种工作台路由 + 上下文回链**：`#/subjects` 选择项目和受试者 → `查看与补充资料` 进入 `#/subjects/.../evidence?episode=...`，顶部 band 显示项目/受试者/节点/方案版本/当前资料版本，且 `返回资料页` 回到受试者列表并保持选中。
3. **三栏工作台**：左侧（文件与页清单/资料快照）、中栏（原始识别 + 校对后文本 + 追加校对 + 风险核对 + 证据定位 + 资料追踪）、右栏（原文件页图，连续滚动 + 缩放）。在 1080P、2K、4K 三个视口下布局均自适应，未见溢出或挤压。
4. **不可变快照语义**：左栏只有一个快照并显示 `chip="当前有效"`；右栏 PDF 仅展示唯一页，`aria-current="page"`，无"覆盖/替换"按钮，从交互上限制了"后续资料覆盖早期资料"的可能。
5. **资料上传方式明确**：选择「补充资料」时说明 "在上一有效快照的全部资料基础上，合并本次新选择的文件；上一快照保持完整，可随时回看"；选择「建立完整资料快照」时说明 "本次选择的文件构成新的完整资料集合，不继承上一快照；上一快照完整保留，用于差异比较"。两种语义都用受试者能直接读懂的中文说明。
6. **确认前复核（pre-commit）**：选完文件后必先进入 `evidence-review` 区，分组列出"复用已有处理结果 / 本次将处理"两类，并明确每行的"下一步"。重复上传相同 PDF 时显示 `chip="内容重复"` 与说明"系统将复用已有处理结果，不会重复保存或重复识别"。完整快照模式相同文件则提示 `chip="需要重新识别"` 并说明"系统将按本次快照重新处理该文件"。
7. **不可用文件处理**：`/tmp/fake.zip` 上传后归类为"无法纳入处理"，`确认上传` 按钮自动 `disabled`，并出现红字"当前选择中没有可纳入的资料，请移除无法读取或不支持的文件后重新选择"。
8. **取消预览**：点 `取消预览` 后审查区消失、`disabled` 的上传方式恢复可选，并出现信息条"已取消预览，未建立任何资料快照"——用户能立刻知道没有副作用。
9. **原件红框 + 跳转 + 高亮联动**：右栏 PDF 在 12 个风险识别项上画红色矩形框（`原文重点位置`），位置以 `left/top/width/height%` 相对画布锁定。中栏每个风险项旁的 `在原件中查看` 按钮点击后，对应红框背景透明度从 0.08 升到 0.14，明显高亮当前定位。缩放 100%→180% 时框位按比例同步，未错位。
10. **版本/页索引**：左栏分别用 `文件与页清单`、`资料页/识别页清单`、`资料快照` 三段，文件级显示"第 1 版"标识（"本次新增"），可清楚区分文件版本与资料快照。
11. **错误态可恢复**：访问不存在的 episode（如 `?episode=does-not-exist`）会显示"未找到这个审核节点"+ 重试按钮；导航至有效 URL 后内容恢复。
12. **系统帮助使用临床语言**：界面版本号显式标注；五步指南按工作流顺序解释首次解构、重新解构、受试者入口、资料上传、问题处理；特别强调"否定与肯定、数值、小数点、单位、日期和逻辑连接词的变化需要再次确认；原始识别文字始终保留"。
13. **缩放控件行为合理**：右栏 PDF 缩放按 10% 步进（100→110→120→…→180），放大后出现滚动条、画布不溢出容器；`aria-label` 中文化（"放大原始资料" / "缩小原始资料"）。

## 问题（按严重度排序）

### P0 — 阻塞当前节点核对工作
1. **中栏单列垂直堆叠且无锚点导航，工作量越大越难用**
   - 操作路径：进入证据工作台 → 中栏滚动查看。
   - 页面事实：`.evidence-center-content` 在 1920×1080 下可见高度仅约 633px，scrollHeight ≈ 6841px；同一面板内依次是"原始识别 / 校对后文本（~6398px）"+"资料追踪（~430px）"。风险核对与证据定位都在原始识别块的中间，单页 12 项风险时用户需大量滚动；分页、Tab、锚点目录或折叠分组均缺失。
   - 实际影响：临床监查员一次只能看 2-3 个风险项；反复滚动容易丢上下文，也降低"原文、识别、风险、定位"四元对照的效率。
   - 系统级建议：把"识别文本 / 风险核对 / 证据定位 / 资料追踪"做成可锚定 Tab 或可折叠分组；每页右侧或顶部加入快速跳转到第 N 项的目录。

2. **风险核对显示"已核对"但按钮 disabled、select 默认值与必填说明互相矛盾**
   - 操作路径：中栏 → 风险核对区任一项。
   - 页面事实：每项显示 `已核对：确认与原文一致。已逐字对照原始资料，确认识别内容无误`；select 默认 `确认原文无误`；`核对说明` 输入框 `placeholder="核对说明（必填）"`；`重新核对` 按钮 `disabled`。
   - 实际影响：监查员看到"已核对"会以为"系统已确认、不用再处理"，但右下又要求"填写核对说明后可保存"，两个语义相反。select 选项只有"确认原文无误 / 与本页无关"，没有"我要修正"，与"追加校对"分离后又让监查员要在两个面板间切换才能真正改文字。
   - 系统级建议：把"已核对"改为中性表述（如"本次核对记录：…"）或拆为可点击的折叠；select 增加"需要修改" 选项并在选中时联动到"追加校对"；统一让"必填说明"语义只出现在用户主动"重新核对"或选择"需要修改"时。

3. **红框定位精度与可读性不一致：通用 `aria-label` 与极窄红框**
   - 操作路径：右栏 PDF 任意一处。
   - 页面事实：所有 12 个红框 `aria-label` 都是 `原文重点位置`，没有对应文本内容（如 `μmol/L`、`2026-08-21`），对屏幕阅读器或键盘焦点用户完全无法区分；其中宽度仅 `0.56%`（实测 6px）的小红框对应的是小数点 `"."`，肉眼几乎看不见。
   - 实际影响：定位密集区（如 "ALT 39 U/L，AST 32 U/L，总胆红素 12.0 μmol/L"）出现 5 个红框且 `top` 都为 `63.7711%`，在合成 PDF 上彼此相邻几像素，肉眼无法区分；小数点和单位完全被同一行字遮挡。监查员无法快速知道每个框代表哪段文字。
   - 系统级建议：红框 `aria-label` 写入识别项原文（"μmol/L" 等）；过窄框加 hover tooltip；同一行多框合并或分层高亮（悬停/选中态加粗边框 + 角标数字）。

### P1 — 影响日常效率
4. **"校对后文本" 与 "原始识别" 标题样式几乎相同，容易混淆**
   - 操作路径：中栏顶部。
   - 页面事实：`原始识别` 是淡灰白卡，"校对后文本" 是白卡，两者字号、字重、颜色、边框非常接近，且没有 chip 或"已校对 / 未校对" 等状态标识。
   - 实际影响：监查员在分辨"系统识别"还是"已校对定稿"上需要多看一眼。
   - 系统级建议：左侧加 `原始识别 / 未校对` chip、右侧加 `校对后文本 / 当前有效` chip，或用色块/左边竖线区分。

5. **"校对后文本"和"原始识别"在所有 12 项都"已核对"时内容几乎完全相同，但顶部 banner 只写"文字已识别 · 风险已核对"，不显示差异数量**
   - 操作路径：中栏顶部。
   - 页面事实：`本页识别风险已核对 12` 仅展示总数；没有"已校对 / 待校对 / 已修正"分项计数。
   - 实际影响：监查员无法快速判断当前页是否还有未完成项；只能滚到风险区逐项看。
   - 系统级建议：在 panel heading 增加 `已校对 12 / 待核对 0 / 待发布` 等三段计数。

6. **上传审查"复用已有处理结果"分组命名会让监查员以为没做事**
   - 操作路径：上传 → 补充资料 → 选相同 PDF。
   - 页面事实：分组标题 `复用已有处理结果`，内容重复 PDF 出现 `chip="内容重复"` + 解释。该分组放在"确认前复核"的最上方，覆盖整个"本次将处理"分组之前的全部视野。
   - 实际影响：监查员第一眼会以为"我没添加新东西"，可能误以为操作未生效而重复点确认。
   - 系统级建议：把 `复用已有处理结果` 改成 `与上次相同的文件（将复用处理）` 并配 dimmed 视觉，明确这是"系统自动做的"，不是"没动作"。

7. **取消预览后"信息条"常驻显示，与后续操作混淆**
   - 操作路径：上传 → 取消预览 → 留在页面。
   - 页面事实：`.evidence-notice--info` 始终显示 `已取消预览，未建立任何资料快照。`；即便监查员已经在做风险核对、翻页等不相关操作，这条信息也留在证据 band 下方。
   - 实际影响：监查员在风险核对中段会被该提示分散注意力，且与"当前有效"标识同时存在容易让人误以为"没有任何有效快照"。
   - 系统级建议：把这类提示降为可关闭的临时 toast（3-5s 自动消失或显式关闭按钮），不要用持久条。

8. **左栏"文件与页清单"只有一份文件时仍展示完整层级，未做省位折叠**
   - 操作路径：左栏。
   - 页面事实：`文件与页清单 → synthetic_screening_record.pdf 第 1 版 本次新增`，`资料页 → 识别页清单 1 → 第 1 页 页面已就绪`，`资料快照 1 当前有效` 三个 section 同时展开；每个 section 都重复显示 `synthetic_screening_record.pdf`。
   - 实际影响：监查员在窄左栏（1080P 时仅 ~248px）中要为这 1 份 PDF 滚动看三个标题。
   - 系统级建议：单一文件时把 `文件` 和 `页` 合并显示，多文件时再分层。

### P2 — 文案 / 细节可改进
9. **`aria-label` 中"原文重点位置"是英文工程话术，不是临床话术**（如上文），同上。
10. **风险项类别命名混入英文**：`关键识别项` chip 是中文，`class` 名 `evidence-risk-item--blocking` 出现英文 "blocking"；受试者不可见但开发语义暴露。
11. **左栏底部"返回资料页"是页面顶部 band 里的链接**，但左栏本身没有等价控件；如果监查员已经把左栏滚到底部找版本，需要回到顶部才能返回。
12. **`帮助` 顶栏链接与左侧 `系统帮助` 同时存在，监查员会困惑哪个是入口**；建议合并或明确区分"快速帮助 vs 完整文档"。
13. **页面 PDF 缩放没有 URL 状态同步**：刷新或回退后缩放回 100%，但右侧页索引、滚动位置也丢失。
14. **缩放 100% 下大屏（4K）右栏空白太多**：右栏 1098px 宽，PDF 仅 1054px，靠右贴边；左、中、右三栏在 4K 下没有 max-width 限制，过宽反而让眼睛在长距离上来回扫，建议加栏宽上限。
15. **右栏 PDF 标签 `1 页连续查看` 不够语义化**：建议改为 `1 页 · 连续滚动查看`，并标注当前可见页范围（如 `当前显示：第 1 页`）。
16. **`当前资料版本 当前有效` 在 band 中靠文字呈现，没有用 chip**：监查员一晃过去不易识别；建议改用色彩 chip（"当前有效"绿色、"历史版本"灰色、"草稿"橙色）。
17. **风险核对 12 项全部显示"已核对"，但 `证据定位` 段中"区域坐标" 仍以 `原生文本层` chip 显示**：区分不明显，受试者难以分辨这两层定位精度的不同含义；建议在 chip 加解释 tooltip。

## 无法验证的内容

- 多快照/历史版本切换（"历史版本"/"草稿"chip 行为）——当前只有 1 个当前有效快照。
- 多受试者切换、跨项目选择——本项目只有 1 个受试者 `S-BARRIER`。
- 真实大文件（>10MB）、批量上传、断点续传、未读 / 失败文件的恢复链路——本测试只用了 1 个 68KB 文件和 1 个 3B 伪 zip。
- 多 DPI / 高分屏 + 浏览器缩放联动——本次使用 DPR=1.25，未覆盖 Retina/200% 缩放组合。

- 资料追踪"登记一项被提及资料"的完整提交与持久化——未触发以避免改变活动数据。
