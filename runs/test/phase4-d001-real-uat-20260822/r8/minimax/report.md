## 四、真实监查影响（医学视角）

- **可用性**：受试者级资料工作台端到端可用，"上传 → 识别 → 风险核对 → 文字校对 → 生成版本 → 启用"全过程顺畅，且每一步都有可恢复的取消/重试/重新核对。
- **可信度**：定位诚实性是真实监查的生命线。本次明确看到 `证据定位 / 实际定位精度仅展示已核验的真实定位 / 当前文字识别仅提供文本，未返回经验证的页面坐标，因此不显示区域标注 / 在原件中查看` —— 系统在缺乏坐标时拒绝画推测红框，符合监查人员对"宁可少画，不可错画"的要求。
- **OCR 风险**：本案 file 02 第 1 页（OCR 出"李军"）与 file 01 姓名字段空白之间的姓名不一致、以及 file 03 为不同试验不同代号——这是 OCR 把原始扫描如实呈现的结果。系统在 风险核对 只把"否定/肯定、关键数值、小数点、单位、日期"结构化标记，**不替监查员做受试者身份/既往试验归属这类跨文档语义判断**，是正确的边界。
- **去重**：对监查而言，避免重复存储和重复识别时间是重要保证；本次"内容重复 → 复用已有处理结果"行为完全符合监查对完整证据链不可被"再加一份相同资料"破坏的预期。
- **不可逆性**：所有阶段都有显式的二次确认；激活后才"启用并固定"，启用前可改校对、可换文件、无副作用。
- **不可补做**：Patient Journey、完整入排判决属于下一阶段（帮助页明确说明），本次按要求**不自行补做**，作为阶段边界如实记录。

## 五、系统级建议（仅给产品工程，非验收决定）

1. 中间面板在启用后的 `校对后文本` 与 `原始识别` 用 Tab 切换，2K 屏下大量空白居中。建议启用后的页面可默认并排双栏（原始 / 校对后），让监查一眼对比。
2. 风险核对数量在不同视角下出现轻微不一致：例如 file 02 第 4 页风险核对标记 5 项，但加载时 tab 徽章 `风险核对（5 项待处理）` 与"还有 N 项待核对"在不同时点读数跳动。建议明确"全节点待处理 = 全部页面 OCR 项之和"，避免监查误以为漏了页面。
3. 同一 file 02 第 4 页风险核对里，`已核对：确认与原文一致。报告时间2026.05.11 15:58原文无误` 这条说明文字出现在了 "日期 2026.05.11 11:11" 项下（说明文字串错位）。可能是连续 type 操作时序问题，但说明文字与项的对应必须 1:1，因为监查会逐项取证。
4. 校对流程的"校对方式"使用 button toggle (修正已识别文字 / 补入漏识别文字)，但表单内部 select 又存在 `原文范围` 与 `变化类别`；帮助页提到"系统会根据校对前后的实际文字识别否定与肯定、数值、小数点、单位、日期和逻辑连接词变化"——可以理解"变化类别"是监查意图标签；但建议系统能根据实际文本差异自动提示建议类别（弱提示），让"补入漏识别文字"路径更轻。
5. 启用后页面的"本页识别风险已核对16"与"查看 14 处原件定位"分别对应风险项数和定位条目数，这两个计数差异（16 vs 14）应一致或对监查明示原因（哪些项没有可定位坐标）。
6. 资料快照 1 的 `2026/08/22` 启用日期格式只到日。建议同时给出"启用时刻"或与原始文件上传顺序的时间戳，便于多快照差异比较。
7. 中栏在重新加载后曾出现"这部分资料暂时打不开"的占位；建议占位里同时显示当前快照的关键标识（启用日期/快照序号），监查刷新页面看到该占位时不会以为数据丢失。
8. 受试者详情页"筛选资料 当前有效 / 查看筛选资料"是绿色状态，但其他节点的"尚未建立资料版本"没有明显的颜色差异。建议给未开始节点用更克制的灰色，避免误导。
9. camofox MCP 当前不能直接驱动 `<input type=file>` 的原生选择器，自动化测试需要切到 OMP browser。长期建议在 camofox MCP 暴露 `setFileInputFiles` 接口，让 CI/UAT 不需要切换 driver。
10. 内容哈希去重目前按字节级完全一致判定；建议为真实监查场景也提供"视觉/版式一致即视为同一文件"的可选二档（标注但允许突破），便于扫描仪重扫但内容相同的资料。

- Findings（非阻断，但需产品在下一迭代考虑）：
