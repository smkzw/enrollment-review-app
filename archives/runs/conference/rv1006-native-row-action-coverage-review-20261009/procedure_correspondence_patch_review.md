No adoption occurs either way (unit non-executable, `fact_refs=()`), so this is a type/message fidelity defect, not a safety hole. *Smallest correction:* derive the correspondence label and dimension per statement from that statement's own review decision (`reviewed[index].decision == "unresolved"`) instead of the unit-wide `all(not ...unresolved)`, leaving the sibling to the existing independence message; the blunter alternative — accepting the procedure branch only when every statement's decision is `unresolved` — would refuse the mixed unit rather than mislabel it.
