### Highest-impact defects / challenges

1. **D2 (write path) is missing entirely.** The single highest-leverage item is not binding adjudication but the run-creation transaction + endpoint: assemble context → calculate → derive decision/gaps → persist FinalAssessment + ActionRequests → complete run (allowed with unresolved items, `claims_complete=false`; doc §16 line 282, §17.6 line 397). The history read-side (`app/services/review_history_service.py:302-367` predicate_observations completeness, lineage triple at lines 184-192) is already the acceptance mirror for it. Building it in alias mode first preserves today's behavior and gives bindings a real consumer to plug into — this is construction, not activation.
2. **Alias/binding coexistence is unspecified.** If bindings cover some predicates of a component, mixed evaluation (binding for some, category alias for others) would silently keep the defective matching the redesign exists to remove. Recommendation: in binding mode, per-predicate coverage is required; uncovered predicates → UNKNOWN `semantic_correspondence_unverified`. Alias mode remains the default until activation, gated by an `EVALUATOR_VERSION` bump (the guard already exists at `frozen_review_calculation.py:31-35`).
3. **No persisted adjudication entity.** Nothing records cross-lane concordance, disagreement, or user adjudication. Two identical lane outputs are necessary-but-insufficient (objective's own rule; doc §16 line 272 "两个模型给出相同但未经来源语义验证的值，仍不得自动采信"): concordance may gate *candidacy* for autoacceptance only; activation of any concordance threshold requires the approved isolated evaluation and user sign-off. Until then the only route to a verified binding is explicit local-user adjudication.
4. **Controls have no assessment record shape.** History validation asserts `predicate_observations` against official clause predicate IDs (`review_history_service.py:356`, `323-328`); control atoms have `atom_identity_sha256`, not `predicate_id`. Reusing FinalAssessment verbatim would break the report; a parallel control-assessment record consumed by the same history service is needed (doc §17.4: controls keep their own stable IDs).

**(c) Immutable verified binding output** — one frozen ContractModel (fields per doc §17.1.1 step 4): authority tuple, predicate/atom identity, `fact_id`+`fact_attribute`+`locator_id`, adjudication state, `frozen_input_sha256`, receipt refs (`artifacts/raw_response/...`), structural-check results, revision.
