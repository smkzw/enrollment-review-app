### 阻断 Phase 1.5

**B1. 入排工作台判断区出现 `时间窗：undefined undefined undefined 天`（所有 episode 的 EX-01a）**

- 复现：1440 视口 → `#/workbench?episode=episode-uat-03-screening-gap_conflict` → 展开 EX-01 → 选中 EX-01a → 判断条件区"用药·禁用用药暴露为 等于 是"下方显示 `时间窗：undefined undefined undefined 天`。
- 根因（只读源码定位）：`frontend/src/domain/mappers.ts:463` 拼接 `${relation} ${reference} ${window_days} 天`，但 fixture wire 实际结构为 `{anchor_type:"randomization_date", direction:"before", upper_bound_days:28, lower_bound_days:null, half_life_multiplier:null, allow_partial_date:false}`——三个字段均不存在。对 `uat-phase1-workspace.json` 全量扫描确认该结构出现在全部 14 个 episode 及方案差异草稿中，即**每个受试者每个节点的 EX-01a 都显示此坏串**。
- 影响：核心审核屏幕出现裸露 `undefined`，直接违反"可见文字为中文原生医学监查表达"；更严重的是它**吞掉了有临床意义的信息**——方案要求"随机前 28 天内禁用用药"，界面完全不呈现 28 天窗口，监查员无法核对时间窗。用户试用第一天就会撞上。
- 修复建议：mapper 按 wire 实际字段生成中文短语，如 `direction=before + anchor_type=randomization_date + upper_bound_days=28` → "随机前 28 天内"；`half_life_multiplier` 非空时给"约 N 个半衰期"表述；并在 ViewModel 单测断言渲染串不含 "undefined"/"null"。

### 重要但不阻断

1. **`大于等于 18 year`（所有 IN-01）**：fixture 单位 `year` 未经本地化直渲染（ExpressionView formatValue 透传 `unit`）。属性名已是"人口学·年龄（岁）"，单位冗余且英文。建议单位映射 `year→岁` 或在属性已含单位时省略。`xULN` 属临床可懂缩写，但"≥正常上限 1.5 倍"更贴近中文监查表达，可同轮处理。与 B1 同一组件，建议同一修复轮。
2. **今日工作待处理事项卡片无法区分**：6 张卡全部为"UAT-03 筛选期 阻断 + 通用行动文案"，**无关联规则编号**，用户必须逐一点开才知道是哪条要求。行动中心列表已有"关联规则：IN-01"字段——同步到今日工作卡片即可，一行字段的事。对"不愿多点"的目标用户这是最高频摩擦点。
3. **冲突场景深链落点错误，实测 4 次操作才到证据弹窗**：今日工作"存在冲突"卡的 `打开审核`（`#/workbench?episode=episode-uat-03-screening-gap_conflict`）落在 IN-01（记录不完整、与冲突无关、且无证据）。实际路径：打开审核（1)→展开EX-01(2)→选EX-01a(3)→打开证据（4)。路由已支持 `component` 参数（我选中 EX-01a 后 hash 自动变为 `&component=component-ex-01`），修复只需在冲突类卡片的 href 带上 component。修复后 ≤3 合同在该场景稳固成立（当前 profile 路径 1 次直达已合规）。
4. **证据文件名携带夹具场景标签**：`合成筛选资料-clear.pdf`、`合成筛选资料-gap_conflict.pdf`——"clear/gap_conflict"是测试场景词，医学监查员会误读为文件属性。改中性命名（如"合成筛选资料-01.pdf"）。
5. **规则树父级无风险汇总**：折叠的"EX-01 排除条件 1 项"不提示子项存在"存在冲突/阻断"，风险发现依赖逐个展开。建议父级聚合最严重子状态徽标。
6. **工作台默认落点是最干净对象**：侧栏进入默认 UAT-01·IN-01（满足）。建议默认定位首个阻断/冲突子项，与今日工作的风险优先序一致。
7. **缩放测试方法与覆盖缺口（流程发现）**：e2e `setZoom` 用 CSS `zoom`，且 150/200% 断言只跑工作台一页。我用同方法实测**受试者与资料页在 CSS zoom=2 时页面级溢出（1650>1440）**，溢出点为 `.expectation-cover__gap`/`__note` 两个不换行 span；但用原生缩放等效视口（720/960px）复测**无溢出**——即真实浏览器缩放用户不受影响，属潜在脆弱性而非用户可见缺陷。建议：a) 防御性修复两个 span 的换行/min-width:0；b) 把缩放溢出断言扩展到全部一级页面；c) 由 Codex 定口径：验收以真实浏览器缩放为准。
