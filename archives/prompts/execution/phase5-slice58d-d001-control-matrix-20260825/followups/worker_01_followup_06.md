# Worker 01 同会话返修：审核节点允许引用流程表依据行

v3 的节点来源要求在真实方案中产生不可接受的矛盾：官方条款可能不写“筛选/基线”，但研究流程表的“入排标准审核”明确规定审核节点。不能把流程表锚点塞进官方行并伪装为官方条款来源，也不能无来源地默认节点。

请仅修改已授权矩阵合同/测试路径，建立跨来源节点依据，不修改 D001 工件。

## 设计要求

1. `MatrixReviewNode` 支持两类依据：
   - 本行直接来源锚点明确命名该节点；
   - 同一矩阵中的流程必做行作为节点依据（字段名可为 `workflow_basis_row_id`）。
2. 节点至少有一种依据；允许同时有直接来源和流程依据。直接来源数组可为空，但若提供仍须按序唯一且不越界。
3. 流程依据行必须：
   - 存在于同一矩阵；
   - `source_kind=REQUIRED_PROCEDURE`；
   - 其节点中包含相同 `review_stage`，且来源锚点支持该阶段；
   - 不得引用自身，不得引用官方行或其他章节控制行。
4. 如果本行直接来源不支持节点阶段，但提供了合法流程依据，可通过；如果两类依据都不能支持，拒绝。
5. 这只是审核节点依据，不改变官方规则来源身份、流程目录身份或跨章节重复/补充关系；不得把流程锚点并入官方行 `source_anchors`。
6. 可见 Markdown 用医学监查人员可理解的中文说明，例如“节点依据：研究流程中的入排标准审核”，不要暴露矩阵 row ID；通过被引用流程行的可见标签和标题呈现。JSON/注释保留稳定 ID。
7. 序列化一致性校验覆盖节点依据，内部 ID 不得泄露到可见层。
8. 升级矩阵合同/校验器版本，并增加反例：未知行、引用自身、引用非流程行、流程行不含相同阶段、无任何依据；增加正例：官方条款无阶段字样但引用同矩阵流程审核行。
9. 保持 v3 原子性、DNF、时间、证据与候选/正式身份约束不退化。

运行矩阵聚焦和相关 5.8a-c 回归，报告迁移字段与测试结果。
