# Phase 1 真实前端壳可交互原型

## Goal

基于 Phase 0.5 已冻结的 `fixture/v1`、OpenAPI 草案和交互合同，构建可直接接入后续真实 API 的无登录 React 产品壳，让不熟悉电脑和 AI 的资深医学监查员无需理解模型或运行机制即可查看工作、识别风险、定位原始证据并进入下一步行动。

## Requirements

- 不读取 legacy Markdown 或旧 SPA 状态；所有页面只消费版本化 stub API/ViewModel。
- 全局一级入口使用中文临床工作语言：首页候选“今日工作”“项目看板”，以及方案解构、受试者、行动、报告、任务与系统、帮助。
- 项目看板直接展示受试者×审核节点，节点状态、分类计数、筛选、排序和直达均在表内完成。
- Patient Profile 首屏默认只突出入排相关、异常、临界、趋势、冲突和待办；提供完整明细与应备证据覆盖。
- 入排工作台保持规则树、判断/行动/差异、识别文本/原文件证据同步选择；父子规则层级和定位精度必须可见。
- 行动中心显示责任方、原因、需补内容、可关闭证据、到期节点和不可变变化记录。
- 任务详情覆盖排队、运行、部分失败、暂停、恢复、stale 和取消边界；不得伪装真实 OCR/LLM 已运行。
- 桌面无页面级横向滚动；窄屏改为标签/抽屉；主要布局用 Grid/Flex、`minmax()`、容器查询和相对尺寸。
- 可见文字为中文原生医学监查表达，不显示 Gate、hash、Agent、schema、log 等实现词。
- 关键状态不只依赖颜色；熟悉图标带中文可访问名称和悬停提示；键盘可完成核心选择与证据打开。
- 至少覆盖 UAT 合同中的 10 类风险/恢复场景，并可从风险在 3 次操作内到达证据。

## Acceptance Criteria

- [x] `npm run build` 与前端自动化测试通过，前端不导入 legacy 模块或 Markdown 数据。
- [x] “今日工作”和“项目看板”均为真实可交互一级页面，可供 Phase 1.5 比较默认首屏。
- [x] 项目看板、Patient Profile、入排工作台、行动中心、任务详情、报告和帮助入口均可操作。
- [x] 三个 Phase 0.5 受试者 fixture 及不少于 10 个状态场景被 UI 消费且语义一致。
- [x] 1280/1440/1920 桌面与代表性窄屏在 100%/150%/200% 等效布局缩放完成截图和交互检查。
- [x] 页面级无横向滚动；窄屏关键内容可读；按钮、标签和表格文字无无意义断行或遮挡。
- [x] 关键风险到原始证据不超过 3 次操作；定位降级、冲突、资料需重新核对、失败和恢复均有明确中文界面。
- [x] axe-core 无 serious/critical 问题，核心键盘路径通过。
- [x] 独立检查者无阻断问题后归档 Phase 1；Phase 1.5 前不建设数据库或真实后台。
