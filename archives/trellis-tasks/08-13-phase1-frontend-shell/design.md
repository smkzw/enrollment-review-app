# Phase 1 前端壳设计

## 数据边界

1. `frontend/src/api/` 只暴露版本化异步接口；Phase 1 实现从 `contracts/v1/fixtures` 读取并转换为只读 ViewModel。
2. 页面不直接解析领域 Fixture，不读取旧 Markdown；转换逻辑集中并有测试。
3. 路由选择、筛选、排序、面板宽度和当前证据为 UI 状态，不回写临床合同。

## 信息架构

- 固定侧栏：今日工作、项目看板、方案解构、受试者、行动中心、报告导出、任务与系统、系统帮助。
- 顶栏：当前项目/方案版本、全局搜索、帮助；不显示登录、模型或开发信息。
- 宽屏内容采用全宽工作区；窄屏侧栏收起，工作台三栏改为保持选择状态的标签页。

## 核心页面

1. 今日工作：到期行动、明确障碍、冲突、进行中任务和近期变化，支持直达对象。
2. 项目看板：受试者×节点矩阵、各列筛选/排序、节点状态与分类计数、直接进入 ReviewEpisode。
3. Patient Profile：概况、主题泳道、应备证据覆盖、风险过滤、事件/规则/证据联动。
4. 入排工作台：分层规则树、组件判断与行动、识别文本及模拟原文件；显示定位精度。
5. 行动/任务/报告/方案：提供 Phase 1 所需交互和异常场景，不宣称已连接真实后台。

## 视觉与交互

- 使用中性白/灰工作底色，绿色用于明确可继续，红色仅用于明确障碍，琥珀用于需处理，蓝色用于选择和导航；状态同时带图标和文字。
- 紧凑但可扫读，避免嵌套卡片、超大标题、装饰渐变和固定像素主布局。
- EvidenceSpan 定位精度始终显示为“精确区域/文本范围/原文片段/仅页码”，不伪造高亮。
- 所有批量、关闭、override 等动作在 Phase 1 只更新本地演示状态并明确“原型数据”，不得展示成功调用后台的假消息。

## 验证

- Vitest/React Testing Library 验证 ViewModel、状态汇总和关键交互。
- Playwright 覆盖路由、筛选、排序、三栏联动、窄屏标签、键盘和无页面横向滚动。
- axe-core、截图和浏览器控制台共同作为真实受众界面证据。
