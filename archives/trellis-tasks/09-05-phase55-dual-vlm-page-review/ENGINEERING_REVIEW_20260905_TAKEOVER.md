1. 系统自有 harness 直连独立模型 API。开发者或测试者不能替系统解读方案；不得把本机 Hermes/OMP/ZCode 的执行状态或配置当成产品运行依赖。外部测试角色与产品判读模型是两回事；本轮用户进一步取消外部会商机制。
2. R3 逐页单阶段双主读：GLM-5.3-Flash high（Coding Plan）与 MiniMax-M3 high（cms-smk）。Flash-Next low 仅补充手写，不读事实、不替代主读；DeepSeek 不进受试者读道；OCR 仅侧车。
3. 协议语义路由与受试者逐页读道分开，不能把早期 MTPLX/DeepSeek 回退要求横套到 R3 读道。
4. 方案理解覆盖入排相关章节及跨章节约束，但无需完整重做无关章节 OCR；不能按 D001/SAR 名称、疾病、药物、评分、阈值硬编码。

6. 筛选/基线等节点保留各自证据截点；方案明确回溯锚点优先。无明确锚点时分别按审核节点回溯，不能拿基线新资料改写筛选旧结论。
7. 原始文件不预处理上传；以当前修订设计的格式契约为准，不把早期所有格式承诺误认为现已实现。当前方案导入限定 DOCX，受试者资料支持 PDF/图像。
8. 原始证据、版本、页码、摘录和位置必须可回溯；没有坐标不假画红框。目标为滚动原件与真实重点标注。
9. 桌面 1080P/2K/4K，原生中文、少操作、分层明细，不做移动端。数据缺口、冲突、检查未做、研究者判断分别呈现并指向具体行动。
10. 金标、日志、测试数量不是产品验收。事实召回、负判定静默漏判、手写对账、真实浏览器和临床 QC 均须有相应证据。

## 4. 已证实问题（按优先级）

### P1：正式入口不走 R3

`app/api/v2/fact_normalization_schemas.py` 请求仅有幂等意图；`fact_normalization_command_service.py` 调用底层时未传 `page_review_coverage_id`。正式 API/frontend 无页判读发起与覆盖接续调用。已有离线接线测试不能证明用户点击走新链。

处理：先建立持久页判读作业与权威作用域解析，完成后由服务端绑定 coverage 至规范化命令。不得简单接受客户端任意 coverage 或静默回落旧 OCR 链。补 HTTP→作业→页记录→coverage→规范化集成测试，再做真实试跑。

### P1：同一模型重复项被当成双模型一致（已修复并反例验证）

`app/domain/page_reconciliation.py` 原先仅比较两条相同信号，没有验证两个来源读道。构造 A 返回两条相同项、B 不返回，旧代码误采信。已加不同主读道条件；重复项保留为冲突，不伪造独立证据。

### P1：规范化损失精度及零值（已修复并反例验证）

`app/domain/page_normalization.py` 原 `float(...):g` 默认六位有效数字，使 1.234567 与 1.234568 同归为 1.23457；`value or ''` 将数字 0 清空。已改 Decimal 精确保留数值和显式 None 判别，不引入临床容差。

兼容注意：高精度及大数的规范化键改变。不得重算覆盖历史已接受记录；真实 R3 首跑前确认库中旧记录/键及内容寻址版本策略。这是存储验收的一部分，不能只更新模型提示版本掩盖历史语义。

### P1：整批返回后才持久化（待修复）

`review_pages` gather 全批结果，`persist_page_review_results` 是独立的末尾调用。若批处理中止，已返回但未持久化结果无恢复凭据。每次调用新建 semaphore，也不能限制两个并发批次的模型总并发。

处理：复用现有作业/租约；逐页或逐读道提交不可变记录，绑定输入页哈希与版本；恢复只补缺失项；覆盖最终封口必须来自权威预期页清单。并发准入由统一执行所有者管理。

### P1：要求模型自行计算规范化键（已修复，需真实复跑）

原 harness 直接校验模型返回的规范化值/键，没有预先调用代码规范化。现在提示 Schema 不再要求这些派生字段；代码根据原始字段/值和手写摘录生成，再用严格合同校验。原始响应哈希在转换前计算，提示版本升级 v2 区分输入契约。未知条款引用显式拒绝，避免错误编号流入对账。

### P2：可选手写预检反而阻断主读（已修复，需真实验证）

原 preflight 三端点 gather 任一异常即整体失败，违背条件手写第三读裁决。现在主读身份预检仍必须成功；手写不可用不进入可用路由，真正遇到手写时记录缺失读道与 configuration 原因。未静默用其他模型替代。

尚需补预检诊断产物保留具体端点失败原因与 GUI 生命周期的正式编排，不能只留下通用分类就声称根因已解决。

### P2：生产上传依赖放在 dev（已调整）

FastAPI 上传端点依赖 python-multipart，但原声明仅在 dev 组。已移动到运行依赖，离线更新 uv.lock。仍需验证干净生产安装和应用启动。

### P2：对账缺少位置/时间关联的显式合同（待细化）

事实键目前只由字段、值、单位构成，手写键只由类型、文本构成。同页多时间点或多个检测项目的相同 NCS 不能因此自动证明所指对象一致。别名参数存在，但实际调用未配置字段同义来源。

处理：先建立同页多记录反例；定义 observation 的目标、日期、来源区域关联，再决定归一化键与对账策略。不硬编码临床字段清单；不能将不同位置机械当不同事实，也不能将同文批注机械当同一判断。

### P2：进度文档过度概括（正在纠正）

Plan 与 task design 存在“harness 完成/仍无迁移”等交错状态。API 未接入且临床资料尚未验收时不能写产品完成。保留历史阶段归档，新增当前三层证据：原型、模块、真实链路。
