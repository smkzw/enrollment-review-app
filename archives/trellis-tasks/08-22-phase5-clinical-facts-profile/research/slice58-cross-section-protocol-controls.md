# Slice 5.8 全方案入排控制点审计与裁决

## 问题定性

当前解构输入只冻结官方 IN/EX 父规则和研究流程表中基线及以前的必做项。`build_required_procedure_catalog()` 只遍历表格根，且依赖访视表头和 `X/(X)` 标记；`ProtocolDeconstructionInput.allowed_source_span_ids` 又只等于两份目录的来源并集。因此，合并用药/治疗、禁限用药、洗脱期、检查结果有效期、复测规则、评分操作要求和正文例外等非流程表来源不可能进入 Agent 当前输入。

## 真实 D001 II 方案证据

- 方案 SHA256：`362443131f0d384c82c80f6a37396084f7d3301b51162201749c0488b0f2dd98`。
- “禁止的合并用药/治疗”明确规定基线前指定时间内至试验结束不得接受表 5 药物/治疗。
- 表 5 有 12 条结构行，时间窗从首次给药前 7 天至 24 个月；包含“3 个月或 5 个半衰期，取较长者”和来氟米特清除剂洗脱例外。
- 表 5 与官方排除标准的用药限制有重复和补充，但还增加“至试验结束”的持续性范围；不能直接再计为新 EX。
- 正文另有筛选检查可复测一次、CT/病毒学结果有效期、结核阳性后的进一步检查与预防治疗、妊娠检查及 FSH 适用人群等基线前控制。
- r6 真实运行对 IN-01~IN-03 的仅发送来源证明 Agent 不会自然获取表 5；这是输入闭包缺陷，不是提示词缺陷。

## 会商与 Codex 裁决

两名独立参与者均否定“流程表 = 全部额外入排控制”，并建议第三类一等对象。Codex 采纳三来源边界，但作以下修正：

1. **不制造伪官方编号。** IN/EX 编号和数量只属于方案官方父条款。其他方案控制使用稳定 `protocol_control_id`，界面显示“方案控制 01”等顺序标签，不伪装为 `CTRL-xx` 官方条款。
2. **不把真实控制压成三选一类型。** 一个控制可同时包含适用条件、必做操作、必须达到的状态、禁止事件/暴露、例外和专业判断。正式合同使用多个类型化义务原子及明确组合逻辑。
3. **不以关键词命中充当完整性。** 对选定期别的全文结构单元建立覆盖清单，每个段落、列表项、表格行、表头和注释都必须有处置结果。关键词只用于优先级和候选提示。
4. **候选与发布控制分离。** 先冻结全文结构单元及候选身份，Agent 只能对冻结身份结构化、拆分或明确排除；发布后的控制是另一份不可变目录。
5. **跨来源只建关系，不模糊合并。** 关系包括“重复表述、补充要求、进一步解释、实质冲突”。只有完全等价且经确认的重复可共享评估身份；未解决冲突阻断发布。

## 目标合同

`ProtocolSectionCoverageManifest` 覆盖选定期别的全部正文和正式修订案结构单元，保留标题路径、表头/行/列语境、脚注/注释、期别适用性、来源定位和原文顺序。每个单元必须归入官方入排、流程必做、其他控制候选、支撑/补充、治疗后执行要求、管理/统计/背景说明、期别排除或待确认。任一单元未处置，不得宣称全方案解构完整。

`ProtocolReviewControl` 至少包含：适用人群/触发条件；完成/核对、达到条件、不得发生事件、不得暴露于药物/治疗、必须记录、必须专业评估等多个类型化义务原子；义务组合逻辑；时间窗/锚点/方向/半衰期/持续期间/例外；审核节点及“提前关注/本节点判定/后续节点复核”作用；最低证据要求；正式来源闭包；与已有规则/流程/控制的关系。

例如“首次给药前 4 周内不得使用 X”应在筛选节点生成“洗脱期可能不足，基线/随机时重点复核”的提前关注，而不在筛选时直接做最终否定；到首次给药/随机锚点所属节点再做决定性判定。

## 权威、停止条件与实施顺序

- 方案和现行修订案可创建/改变正式控制。Q&A、澄清函、邮件和医学解释只能解释模糊点；与方案/修订案冲突时停止发布。
- 未命名时间锚点、未解期别、未处置单元、来源越界、未解冲突、官方编号漂移或义务逻辑不完整均阻断整份 `RuleModelRevision` 发布。
- 顺序为：合同 -> 全文清单/分章切片 -> Agent 处置 -> 跨来源关系/门禁 -> D001 II 人工对照 -> MG-K10-SAR III 泛化 -> 代表受试者和三路独立测试者。
