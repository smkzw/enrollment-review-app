# 1006V1｜交付窗口与最小实现边界

本文件是已批准交付方向的实施细化，不是新的产品Phase，也不是新一轮全仓重构计划。

## 1. 窗口“冻结”什么

冻结用户结果：同一完整要求范围下的真实隔离工作稿、一次更正/补证、新结果和历史。
冻结范围准入：只接直接阻断和错误采用风险；不预先实现未来所有语义/恢复类型。
不冻结事实：新证据、更正和真实失败必须进入新版本；不能因为窗口而压下反例。
不承诺时间：无固定天数、耗时或通过率承诺；“交付窗口”不是到时降低标准。

范围较窄不等于产品精简成演示。最终节点必须覆盖全部官方和当前相关跨章要求及其定义依赖；正常结果可用，未决可见，来源完整可达。尚未完成全产品留出、全屏规格和运维验收时，只能声称本窗口通过。

## 2. 一条交付、两条并行工作线

| 节点 | 要交付的实际产物 | 必须先具备 | 不可替代的验收证据 |
|---|---|---|---|
| D0 | 当前源码/病例/节点/要求范围与授权状态的简短冻结记录 | 只读接管 | 实际Git和运行态，不从旧标题推定 |
| D1 | 同源完整要求快照及可执行/受限项、真实依赖 | 正确来源与合法采用合同 | 仓储读回、消费者识别限制；不是只看PRD |
| D2 | 完整已提供资料范围的观察、候选、资格和事实/Profile结果 | 对本例来源的访问和调用/写入授权 | 每组处置、保存、读回；坏项与未读明确 |
| D3 | 当前节点实际工作稿 | D1+D2相应消费者成立 | 正常结果、必要风险/未决、全范围及原件导航 |
| D4 | 一次有源更正/补证后的新审核结果 | D3、既有更正入口 | 受影响重算、独立项不误变、历史仍读旧源 |
| D5 | 阶段交接和有限冻结诊断 | 对应代码冻结 | 验收与未运行清楚，非全产品成功声明 |

D1由P1负责，D2由P2负责，可以并行。P2可先做隔离资料与消费者验证，不使用未发布规则作正式入排判断。D3之后由同一所有者集成。不得把表中六个节点做成六个新平台或六套顺序会商。

当前病例优先复用已有真实材料；不得因为难而静默换成容易的病例或减少到成功几页。确有无法恢复的来源、权限或身份问题，记录原因和影响范围；替换病例需要显式说明，不得冒称原病例已完成。

## 3. 开发事项准入

进入窗口前，用现有implement一行记录：`问题 → D节点 → 首因证据 → 最小改动 → 退出例`。

| 情形 | 处理 |
|---|---|
| 当前UI/保存接口实际崩溃、被正确结果卡住 | 直接修生产者与消费者，不仅吞异常 |
| 可能错患者/错源/错义/错误采用，或者破坏历史 | 必须隔离风险并修必要边界；不降低安全要求 |
| 当前普通判断缺少必要的通用消费者 | 接当前实际需要的最小类型，具备正反例和真实消费 |
| 尚未影响本例的性能潜力、更多供应商/历史别名、泛化架构 | 记录后移，不开展实现 |
| 只有某一次回答不合格且无新信息 | 不追加同形重试；定位原因或严格保留未决 |
| 已有测试失败且不知影响 | 查实际范围；不统称旧夹具，不借此重开全部功能 |

延后问题保留证据与影响，不删除历史、不伪报全库绿色。为安全采取隔离后若仍不能证明本例不受影响，相关验收不得通过。

## 4. P2：把现成恢复能力用到真实保存和消费

交接报告前6组成功，第7组失败，余7组未读；首次原答只读再核验已有候选但未发布。具体记录以接续时原始工件为准，不能以这些数量当作新的完成状态。[来源：06_SOURCE_BASELINE.md H1]

先检查实际输入、请求、原答、当前解析/来源与任务作用域。现有`revalidate_saved_response`和持久恢复服务是首选；不新建恢复引擎，不扩展到自动搜历史最好答案。

新受控副本保留祖先身份、既有失败、成功工件和累计预算。副本位置变化不自动许可复用，复用仍须证明依赖相容；复制时使用现有SQLite一致性/恢复工具，不能在WAL活跃时直接复制主文件，也不能打开不存在路径生成空库。

先完成第7组实际恢复与读回，再仅读取尚未处理范围。模型提出的候选还要经过现行完整来源和采用合同；可定位/有引文不等于临床值正确。确需人工原件核对的少数风险走现有产品入口，不能要求医学经理代开发者逐字段确认全部候选。

局部隔离必须保留原候选和依赖、缺口范围及不能证明的内容。若该范围可能包含否定检索所需信息，不得把“其他候选已保留”解释成该类病史已完整检索。原件不可读与输出项错误分别报告。

## 5. P1：完整采用与完整自动化分离

官方编号、父子逻辑、跨章要求和支持性定义保持一个同源、同修订真相；不能只拿方便的子集为该例出报告，也不能用D001规则审核SAR病例。

模型主责任务可以提议可执行要求或严格的非可执行记录。来源/含义已知正确而缺消费者，是能力缺口；真实原文歧义，是解释未决；文件未读、JSON破损、引用越界或已知错义不能包装为这两类。

优先使已批准R1由正常生产路径进入保存/消费，不要求先成功生成完整难结构，再恰好触发某个特定错误码才能记未决。这项改变仅针对实际阻断的记录类型和消费者，不全面替换既有规则模型。

未决传播基于真实定义、量词、例外、时间、输入选择和来源范围；关系未知时保守限制潜在依赖。独立正确结果继续，明确风险不被总“未知”掩盖；必要条件仍未核清时不得显示整体已确认合格。

## 6. 最小局部修订原则

只有整包重答确为当前首阻断才修改该路径：

1. 冻结目标身份、待改字段、来源范围、基线版本及相关依赖。
2. 模型只返回该范围的修订提案，不重新生成未授权兄弟。
3. 程序按前置版本合并；过期、越权和不存在引用拒绝。
4. 对合并结果运行原有完整合同及相关语义核查，不以patch格式合法代替正确。

上下文可按需扩大，写入范围不因此扩大。未来/过去、阴性/阳性、数值/单位、日期、处方记录/实际暴露这些语义不能由格式修复悄悄改变。局部更正也不能把一段共享限定误分配给其他项。

## 7. 已批准政策不得被本窗口悄悄改写

- 处方、医嘱、购药记录可按真实来源支持既往用药史；不能进一步推断实际连续服用、剂量、停药和洗脱完成。
- 对本次已提供且已核对范围，常规既往事件未见记录按现行PRD的“本次未记录”审核政策处理；报告说明范围，不伪造原文明确否认。未读/不可读、已知缺件、必需数值与方案要求的书面判断继续单列。
- 上传归属由上传者负责，不因姓名遮挡一律停机；这不证明读数、日期或批注归属正确。
- 数字自动核实当前只获隔离验证授权；不得因窗口交付删除正式采用门禁，也不得重新对已批准规则逐条提问。
- 无新增高质量API模型；现有角色配置的实际身份和参数记录清楚。同模型独立会话非独立临床证据，不用投票消除真歧义。

## 8. 循环、检查与结束

沿现有持久任务实行一个逻辑任务的累计预算。断流不自动扩大原文重读；格式错误不改医学含义；身份问题不猜；能力缺口不转研究者。继承耗尽预算不因新包、提示版本或副本重置。

对同一无新证据失败最多重复到明确停滞信号（两次），随后做首因定位或停止该分支。这不是允许额外调用两次；现有更严格预算继续适用。

用正确的隔离中间材料诊断“结构→解释→装配→消费者”哪层先错；这些材料不得注入正式病例当作模型已读事实。正常开发采用快速局部反馈与功能包集中回归，危险写入前保留必要检查；不每改一行全库跑，也不取消测试以追求快。

窗口成功：03验收中的主流程成立，已知限制明确，先回交。窗口未成功：说明仍卡哪个D节点、首因证据及可独立继续的工作，不给完成率，不自动增加新工作线。后续完整留出、全部屏幕规格及部署恢复属于全产品退出要求，未运行不能声称已交付全产品。
