# 1006V1｜验收：一个完整工作稿，一次更正后的新结果

本文件是待执行验收，不是测试结果。它整合本窗口需要的证据，不另加每次修改必跑的新门禁。按受影响范围检查；已有证据在代码/输入/消费者仍相容时可引用，不能跨版本照搬“通过”。

## 1. 三个等级分开

**代码/合同通过：** 合成输入或原模块测试能证明某条行为。
**窗口通过：** 下表完整主流程在获准的真实隔离病例中成立，且必要反例阻止错误采用。
**全产品交付：** 还须现行R1的留出、全部宽屏与运维等最终要求成立。

不得用第一个代替第二个，也不能把第二个直接叫第三个。真实数据未授权时可继续离线工作，但主流程只能标未验证。

## 2. 主流程检查表

| ID | 要检验什么 | 成功证据 | 必须防止的假通过 |
|---|---|---|---|
| C1 | 正确的项目/方案修订/受试者/审核节点/资料快照 | 持久身份和实际入口一致；完整官方、当前相关跨章及依赖有去向 | 借旧规则、错病例或只取成功子集 |
| C2 | 完整已提供资料范围 | 每文件/页/实际调用组有处置；成功、未读、不可读、待核分开 | 6组成功或第7组预检代表全部完成 |
| C3 | 实际恢复并保存/消费 | 新受控运行、正常持久调用/汇总/读回与现行资格相符 | 仅复验JSON/0写库就声称事实已发布 |
| C4 | 已有充分依据的正常结果可用 | 从原件经当前规则和消费者得出正确工作稿结果 | 只展示候选、全未知或手填verified |
| C5 | 风险、解释未决、能力缺口、缺证各自正确 | 有源限制沿真实依赖生效，独立项不误封锁；真实病例缺类别则另测合成例 | 把错义改成未决，把技术失败写成患者未做 |
| C6 | 实际UI可连续导航 | 队列→正确受试者/节点→要求→方案/病例原件→返回状态保留 | 组件测试或空页面代替真实导航；原文/系统解释混同 |
| C7 | 一次真实有源更正或补证 | 操作者及理由、目标及来源明确；无需JSON/内部ID；形成新修订 | 为演示随意改临床值或直接改数据库 |
| C8 | 新结果及旧历史 | 受影响结果重算，真实独立项不误变；新旧报告分别引用自己的来源 | 只写库没有新结果；覆盖旧报告；要求结论必定翻转 |
| C9 | 错误采用及故障边界 | 同族正反例：坏来源/越权拒绝，失败不显示成功，局部错误不扩大删除 | 仅证明会拒绝、旧failed/预算被重置 |

C1–C8按同一个冻结场景相连，不能拼接不同旧库的成功截图。C9优先使用既有合成反例，不在真实病例中注入错误。窗口中至少有实际产品UI操作证据；全1080P/2K/4K等覆盖未做就列未完成，不伪称Q3通过。

## 3. 原件质量核对不变成逐字段人工批准工程

在所用证据与决定性关系上核对项目、结果、单位、参考范围、日期角色、对象和批注指向。范围清楚的书面CS/NCS可以使用其真实记录；不要求重新诊断波形、影像或猜遮盖内容。

并非所有字段都必须再点一次人工“确认”；系统应先履行已有方法资格，医学经理处理少数真正的歧义和风险。无法精确定位时允许真实页级定位并标明限制，但不能因此宣称像素框/字段对应已核。正常值及阴性记录若承担决定性作用也不能免于来源资格。

数字自动采用权限不足时，不删除标记或伪造批准；使用已允许的人工有源核对路径，或如实标记该段未验证。不得将上传者身份责任扩张成数值真实保证。

## 4. 只做一次小型冻结诊断

使用现有合成和回归资产，不新增模型排行榜或要求一轮完整24×4套件。先冻结代码、模型/请求配置、输入与预期含义，再做以下配对：

| 检查维度 | 需要观察的变化 |
|---|---|
| 正常结果 | 证据充分时确实通过当前消费者，不只是没有异常 |
| 等义/版式变化 | 含义相同，关系和结果稳定，来源位置按新输入正确更新 |
| 单维反事实 | 且/或、否定、比较符、时间锚点或缺失政策真实变化时结果相应变化 |
| 局部故障与恢复 | 一项失败不改好兄弟、不丢真实依赖，不把未读当未记录 |

已有未参与调试的独立资料时，加入少量适当片段；没有则标为变体回归，不能声称独立泛化通过。SAR、D001和当前病例均是开发材料。

先记录一整轮结果，不边测边改。新发现只有直接影响本窗口或错误采用风险时才进入；其他后移。若据此调了提示或代码，这份材料从此是回归，不再称留出。没有独立留出不证明无过拟合，也不自动阻止其他工程工作；全产品泛化声明仍受限制。

## 5. 每项证据的最低记录

沿现有日志记录：实际代码快照、合成/授权真实输入类别与版本、实际入口/命令、预期/实际、终态、证据可访问性。模型有实报时记请求/响应模型、输入输出/推理用量与耗时；缺失记null，不填0。缓存/旧回答重核不计新调用，也不把历史费用改零。

修复前后结果分别绑定快照；重叠测试总数不相加。截图要写页面、CSS视口、缩放和动作，不为证明窗口而另造多页设计报告。

## 6. 终点判定

**允许通过：** 同一完整规则/资料范围下，必要的正常结果已真实可用；风险及合法未决忠实保留；完成UI回源和一次更正/补证后的新结果，旧历史保持；相应危险反例没有错误采用。

**不得通过：** 只有只读预检、全部未知、未读范围被遮蔽、错误表达式改标签、靠手写JSON推动用户操作、旧病例/旧规则截图拼接、只完成修订保存而没有新审核结果。

“未达”就写未达，不用比例粉饰，也不自动增加恢复类型。授权确实不足写授权阻塞；技术欠缺写技术阻塞；原件真歧义写具体影响，不混成一个“需要研究者确认”。
