# 产品内置 Harness 与数据合同设计

本文是基于用户已决要求的工程方案；字段名为逻辑合同，落地应尽量映射现有 Pydantic/存储/API，而不是机械增加同名重复模型。源码依据参见 S02/S03/S07/S11/S18/S20/S26。

## 1. 三条图，共享事实而不共享无限聊天历史

A 方案图：文档/修订 → 官方条款 + 跨章依赖 → 双向覆盖审查 → 局部修订 → 编译/共同发布。方案首次成本单列。所有官方编号、父子 AND/OR/NOT、例外、时间锚、复查、检查方法和研究者判断保留来源。不得因当前病例没有某种资料而删规则。

B 资料图：上传 manifest → 页/报告区域识别 → 主读取 → 区域覆盖及风险路由 → 有界核实 → 结构化观察 → 事实与病程 → 事实发布。任务按页/报告/区域分配；跨页表头和病程上下文在归一化时显式连接。

C 审核图：冻结规则/节点/证据 → 各条件的正反候选 → 来源/对象/时间/专业判断资格 → 确定性计算 → 证据/矛盾 Critic → 条款结果 + 根因问题工作集 → 报告。只有新资料、新有效观察、明确修订或可修复错误才触发局部循环。

已有 JobStore、runner、checkpoint、lease、PreparedReviewContinuation 应复用；本方案不要求使用 LangGraph 库，也不把图节点状态当临床事实。[S20; X02]

## 2. 页面与区域的覆盖，不依赖模型自称“看完”

`PageManifest` 是不变分母：原件版本/页码/页图 hash、转换版本、拆分报告区域。处理状态包括未开始、已读取、部分不可读、失败、确认空白/非临床、重复引用；每种都必须有原因。它只证明处理处置，不能证明语义正确。

原生文字路径要核查可见区域与文字层覆盖：仅页码可复制、隐藏错误 OCR 层、打印正文叠加手写不能凭 `text.strip()` 非空就宣告完整。确有完整可靠原生文字时不强制 OCR；扫描默认主 OCR；疑难区域允许直接 VLM 主读。不得把 OCR 成功作为所有材料上传/保存的硬门槛。[S18]

所有扫描/照片进入可见内容覆盖检查。优先复用 OCR 自带版面/笔迹/质量信号和确定性图像检测；信号缺失或覆盖可疑时用一个轻量视觉布局/笔迹巡检任务，必要时全页高质量读取。巡检不复述全部检验值、不看整套方案，也不能单凭“没有风险”的短输出作正式临床阴性证据。

页级巡检、行/表区域清单与未处理区域合并形成覆盖账本；人工或独立审阅 gold 仅用于评估，不混入产品读取 prompt。手写探测未命中不能永久免除抽样/遗漏检查。

## 3. 低清、翻拍与多报告页

保留原字节及原图。旋转/裁切/透视校正/对比度调整是派生阅读视图，记录原图 hash、变换参数、坐标映射和版本；原图永远可打开。方向不确定不得凭纵横比猜。局部框保留表头、单位列、日期、相邻行和批注箭头；过窄裁切不允许用于对象归属。

局部小字优先在原始分辨率裁切；增加渲染 DPI 不能恢复已丢失的扫描信息。禁止生成式补字、数字/签名重建或把增强后的“清晰”当新证据。无法可靠逆映射的位置降级为 page-only/region-unverified，不显示伪精确框。

一页含多份报告时建立多个 source_report_region；不同日期的相同项目分别记录。混入不同受试者的可见线索生成隔离/身份冲突；遮盖姓名本身不构成排除或资料失效。仅能确认所提供资料的范围，不猜被遮内容。

外部 OCR 文档提供印刷/手写、版面和质量标记能力，同时注明图像质量评估可能误报且增加延迟。因此质量分仅是调度信号，不是资料或临床结论的合格证；不得据品牌默认准确。[X01]

## 4. 观察、核实与事实分层

`SourceObservation`：原文件/报告区域/页/locator、原文字面值和单位、比较符号、参考范围独立字段、可见日期类型、对象上下文、否定范围、打印/手写类别、可辨程度。报告日、采样日、病史发生日分别保存；处方与实际服药不合并。

`VerificationRecord`：被核实的 observation/field scope、源图与视图、核实方法、读取记录 ID、实际模型身份、是否看到先前候选、结果 agreed/disagreed/unreadable/not_checked、对应原文与位置。单模型、OCR、原生文本、人核均真实标记；不补虚构第二票。

`ClinicalFact`：标准概念、标准值/单位及原值、事件/记录时间及精度、来源集合、适用性/资格状态、修订和更正关系。重复来源可保留在证据链，但相同原件重复上传/转述不能算新的独立证据；同一句话在不同表格行不能只按文本相同去重。

事实存在与是否足以满足当前条款分别表达：清楚读到异常值可成为事实，若日期/对象/要求的研究者判断未解决，不能因此获得满足/不满足的最终资格。

## 5. 风险路由：不是“只核查异常值”

需要额外核实的场景包括：小数点/比较号/单位/阴阳性可能改变判定；手写覆盖与箭头对象；多日期/多报告归属；图像裁边、反光、小字或错行；与其他来源矛盾；关键未见证据；混合文字层疑点；原始判读和规则需求的字段缺失。正常但可能决定入选/未触发排除的字段同样进入核实。

选择最小可充分核实的区域，一次核实可覆盖同一报告的一组相关字段。首轮原图核实对 OCR 候选答案和阈值保持盲态；合并时再比较。进一步争议裁决可看到双方候选，但必须记录 candidates_visible=true，不能声称独立盲读；允许双方均错或无法判读。

必要时整页双读仍可作为显式升级策略，而非所有页面必经。需双模型时检查实际部署身份；同模型不同角色/请求可执行不同任务，但不称独立模型印证。

## 6. 候选关联与否定证据

完整事实库不截断。组合概念/词法/日期/事件/引用关系生成候选，可选语义召回但不以 top-k 为最终完整性保证。每个原子条件保存检索范围、版本、候选、关键反证、尚未覆盖范围和状态。

要求 `CandidateEdge` 只表达对象/属性对应与依据，不让 LLM 算阈值或决定最终入组。字段/类别匹配只能筛候选，不证明临床命题。未对应返回 unresolved；宽泛排除条件、否认史、用药洗脱和跨文档归属必须走补查。

消除 O(P×F) 长解释：使用输入 manifest、packet 内短别名及 hash、候选/反证边、未决原因码。若小规模仍需逐事实考虑，返回紧凑编码而非重复长理由；提供记录不等于模型已正确阅读。保留检索召回 gold 测试，不能以降 token 为由降低规则覆盖。

“所给资料未见”不能推导“确无该病/确无用药/检查未做”。明确否认也需核查范围、对象、时间与方案证据资格。

## 7. 角色配置与调用回执

角色与 provider/model 解耦：`protocol_deconstructor`、`protocol_critic`、`evidence_primary_reader`、`visual_verifier`、`fact_normalizer`、`evidence_matcher`、`evidence_critic`。OCR/算术/版本校验不为凑 Agent 数量包装成大模型。

每次冻结 role_id、task kind、prompt/schema/policy versions、source/packet hashes、requested/resolved/observed model identity、provider/deployment、能力/参数、usage、排队/服务耗时、retry reason、输出完整性。不存密钥进回执，不让错误提示泄露原始请求。敏感原始调用工件在用户控制的本地工件区留存，不上传公开仓库。

请求前区分输入+图像占用、输出上限和总 context。准确 token 不可得时使用保守容量管理并标记估计，不能把字符数当 token。模型升级/别名只通过显式规则；流中多种模型名按声明的网关 envelope/upstream 合同验证，不能无条件拒绝合法 envelope，也不能用“最后一个名”抹掉意外切换。

预算按任务输出规模和实测调整。示例 2K/4K/8K 是起始测量值，不是固定全文截断；单包装不下则语义切片/完整保留续片。不得所有任务 65K 起步。429 按 Retry-After/退避排程，释放 worker，不在全部并发槽内各 sleep 60 秒 12 次。

## 8. 有界 Loop

把传输重试、格式修复、内容复核和补证分开。建议起步为一次格式修复、一次针对性核实、必要时一次不同视图/路由裁决；这是可调工程预算，不是临床质量保证。没有新信息仍不确定就形成有源未决，不继续强迫模型同意。

同义争论/相同输入重复生成不算进展；以新来源、新可靠观察、解决的歧义和结构修正作为 progress delta。每个循环记录输入变化与终止原因。任何预算耗尽都不能改变 unknown 为 negative/clear。

共享 provider/凭据限流池、任务公平性和可取消队列；本地处理队列与云推理队列分离。并发由测得的 RPM/TPM/并发限制调节，不硬编码只可 2 或 3，也不把无限云端许可变成无限并发。

## 9. 元数据与例外驱动 UI

当前 `is_auto_suggestion` 拦截是旧合同边界，不应简单删除。新 metadata evidence policy 使用 origin=extracted/manual、source locators、validation、unresolved_fields、policy version；可靠识别可自动采用，不能写成 user_confirmed。来源方/类型模糊但不影响某些事实读取时可先处理这些事实；影响关键证据资格时生成具体未决。[S26]

问题聚合按真正共同根因、原件与对象/时点，不只按同一状态合并。一个报告日缺失影响多个要求，可以一个问题多条关联；不同日期/不同对象的 NCS 不合并。所有子问题可展开、计数真实、优先级原因可解释。原则是减少重复操作，不是保证只有几个 issue。

UI 状态至少区分技术运行状态、资料覆盖/可读状态、单条判断和整例审核意见；根因 issues 中含 source locator、影响的要求、建议动作/责任方、当前或后续节点及所需证据。模型自称 confidence 不能作为自动入组开关。

## 10. 增量、兼容与发布

L0 原件/页面缓存；L1 与方案无关的观察+核实；L2 事实、对象/时间归一化；L3 规则/节点/范围相关的绑定和计算；L4 报告。真实依赖必须显式；语义上下文变化时只重用仍成立的层。

补证触发新增图节点和受影响闭包。特别是 negative search/absence conclusion 依赖证据集合，而非只有其已链接 fact_id，新增资料时需失效。元数据更正可重跑上下文/资格但通常无需重 OCR；实际对象归属变化时，复用必须重新授权映射。历史原件/报告不改，旧版本可回放。

合同迁移采用增加式与显式 schema/policy version，旧双读 record 保留旧语义。不把旧记录伪装成新验证记录。事实部分成功可保存，但所有失败/不可读范围可见，依赖其阴性/完备判断的条件不得自动 clear。正式系统审核意见不是最终入组决策。
