# 验收与性能：先证明没有漏，再证明更快

## 1. 三种完成程度分别交付

**单例闭环：**已发布规则、一例当前节点全部所给资料有处置，正常事实与关键风险可用，逐条结果不是全unknown，原件可回看，一次补证/更正后产生新报告，旧结果不变。

**规模与迁移验证：**几十页至百余页混合低清资料、新来源政策四层接通、正常项核实和遗漏检查、技术恢复及宽屏操作均有证据。

**全系统/跨方案验证：**另一结构的方案与另一个资料组合通过同一产品链；未完成则明确剩余范围。不把一个演示病例成功称为普遍临床准确或法规认证。

## 2. 代表数据与 gold

工程规模建议为30/60/120/150页，另可200页压力；数字是测试分层，不是用户新增限制。使用扫描打印、手写、手机拍照、反光/斜拍/屏幕摩尔纹、裁边、多报告同页、跨页表头、病史时间线的真实代表分布，记录实际比例，不随意声称真实占比。

脱敏/合成负例可检逻辑，真实图像集才检读取质量。gold保存在私有测试区：页/行清单、值+单位+符号+对象+日期、手写及归属、规则相关正反证据、预期未决。独立标注后裁决；gold不输入生产Agent、不通过产品代码特判。

## 3. 必要场景矩阵

| ID | 场景 | 必须成立 |
|---|---|---|
| A01 | 只有页码文字层、正文扫描 | 不把非空native文本当全文读取成功 |
| A02 | 隐藏错误OCR层/旋转/翻拍 | 以原件核实；派生视图映射和原图保留 |
| A03 | 两行相同“阴性”、同项目不同日期 | 保留每次出现及对象定位，不按文本去重 |
| A04 | 同页两份检验单，日期/单位不同 | 报告区域隔离，不借邻表日期/单位 |
| A05 | 手写NCS、箭头、签字、便签 | 识别覆盖不依赖OCR命中；对象/时点准确，未知不扩大 |
| A06 | 0.8/8、<与≤、百分比与绝对数、正常值 | 原始符号值单位分别保留，关键正常项也核实 |
| A07 | 参考范围与结果邻列，单位只在表头 | 不错列；无单位不猜；无法确认转具体未决 |
| A08 | 反光、涂改、遮盖、裁边 | 不生成补字；无关遮盖不使整个病例失效 |
| A09 | 跨页表头、跨页病史、断续时间 | 来源关联可追溯，缺页明确，不把记录日期当事件日期 |
| A10 | 缺用药记录 vs 明确否认 vs 药名提及 | 未找到≠无；处方≠实际服药；否认范围不扩大 |
| A11 | 第一次异常、允许复查、复查未做/多次 | 方案条件、允许/次数/时间/采用逻辑来自原文，不挑有利值 |
| A12 | 新单主读/针对核实/人工更正 | 真正保存与消费新policy；不得伪造双读 |
| A13 | 普通要求+跨章control，当前/后续节点 | 每项有处置；未接入也可见，不只warning |
| A14 | 同一记录多个互斥解释或证据冲突 | 记录冲突，不能靠main-A优先证明医学正确 |
| A15 | 旧双读/旧prompt历史，规则修订 | 旧可读；不改标签冒充新来源；依赖校验仍有效 |
| A16 | 日期部分精度、单位转换、阈值相等 | 代码计算；无法证明精度时不强行归入窗内 |
| A17 | 合法别名、未知模型名、流中上游切换 | requested/resolved/observed可追；未知变化不静默接受 |
| A18 | length、缺finish、格式修复丢观察 | 不完整输出不能发布；修复不能删已有效事实 |
| A19 | 429/5xx、一个分支长期失败 | 释放资源，有界退避，兄弟结果不丢；可取消 |
| A20 | 同一任务重复点击、崩溃后重启 | 幂等，已持久结果不重复提交；晚到响应不能覆盖新版本 |
| A21 | 所有云端槽繁忙/单请求卡住 | 公平调度，任务进度与真正时间一致 |
| A22 | 问题数量多、共用根因 | 不截top-N、不伪造少数；聚合后全部子条款可查 |
| A23 | 自动文档类型可靠/歧义来源 | 可靠自动有据采用，歧义按影响提出；不全量人工门禁 |
| A24 | 规则/节点/资料/处理/档案版本均不同 | 界面显示各自真实identity，不混revision |
| A25 | 一次补证、一处更正、元数据更正 | 新审核、受影响闭包、旧报告与原件不变 |
| A26 | 切换受试者/节点/旧报告与原件 | 无陈旧异步响应，历史与当前不混，未核定位无伪精确框 |
| A27 | 文档内指令/恶意文件名/路径/超大解析 | 作为数据，拒绝不合法路径；限制解析资源且不漏静默失败 |
| A28 | 可辨事实很多但个别页面不可读 | 可辨事实可保存，不依赖未知范围的条款可判；相关未决可见 |
| A29 | 新证据没有链接旧fact却反驳先前“未见” | 否定检索按证据集合依赖失效，不漏增量反证 |
| A30 | 相同根因已关闭，但未补有效证据 | 操作状态不修改条款判定；原证据/历史保持 |

## 4. 指标定义，不用一个 accuracy 抹平风险

**覆盖：**提供页数、各处理状态、未覆盖区域；要求总数及各种处置。100%处置率不等于100%正确，也不能全unknown凑成功。

**读取：**所有检验行召回、手写检出、值/单位/符号/对象/时间联合正确率，分别报关键正常和异常。仅统计识别出来的字段会漏掉未读字段，分母必须来自gold。

**审核：**已知风险漏报、关键误清（需要未决/不满足却被系统清为满足/未触发）、错误升级、未决原因准确及来源定位可达。测试集关键误清计数要求0；这只是该测试集发布条件，不是总体风险为0的统计证明。

**人工：**医学经理主动操作分钟数、必须点击的次数、真正需人工判断的问题、不必要人工确认数量；问题聚合前后数量及受影响条款数。问题少不是独立质量目标。

**性能：**首次有用输出、全部自动处理完成、各阶段服务/排队/重试、人工等待、外部补证等待分别计时；协议首次解构单列。报告页数/像素/观察数/条件数/模型版本/并发/网络条件及失败率。

原始 token无回执则为null，不用字符数冒充；记录字符量可用于结构增长比较。小样本报告每次和中位数/范围，不以一两次运行声称稳定p95。成本有计量则报告，无则不编造。

## 5. 性能实验的比较方式

同一冻结输入、同一规则和评估gold，比较旧路径与新路径，区分冷缓存/热缓存、首次/增量，标记provider变化的混杂。先固定代表配置，不搞开放式模型横评。

重点观察：完整VLM转录次数、局部核实区域/字段数、条款包重复输入、无关配对输出、重试与重复模型加载、全局并发利用率。相关减少不等于质量已保持，必须同时看漏报与误清。

建议目标是已发布规则下常见几十至百页病例尽量接近30分钟；真实数据可能不达标，不设为硬终止或删证据的门槛。首个结果应随着可用资料出现而可见；整例状态仍如实显示处理中/未决。

## 6. 工程执行与证据

确认测试隔离后，在当前项目环境运行已存在的候选测试；新增上述场景时采用当前 tests/v2 分层，命名与fixture参照所在目录。前端先读 package.json 的实际scripts，不猜脚本名。完整pytest失败需区分原有/新增/环境原因。

本包无网络探针运行示例：
```bash
python /path/to/pack/probes/probe_locator_compaction.py \
  --repo "$REPO" --out "$AUDIT_OUT/locator_probe_results.json"
```
脚本仅读取该函数AST，不导入app、不读.env、不访问临床库。函数重构后不适用时写明，不为通过探针而改产品。

真实浏览器至少1080P、2K、4K，测试正常数据、风险堆叠、旧报告、长表与大量来源；截图/录屏只是可用性证据，不能代替数据assertion。每个有源fact至少在代表样本可点击回对应原件/位置；不能只验空状态页面。

数据库/恢复测试使用隔离副本，模拟enqueue→调用→persist之间崩溃、重复点击、租约到期与旧响应晚到；不能直接破坏真实临床库。
