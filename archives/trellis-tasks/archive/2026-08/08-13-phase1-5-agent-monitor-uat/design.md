# 设计：多模型医学监查员角色验收

## 验收结构

采用最小的独立审查结构，不让同一模型既产出又验收：

1. **视觉与交互审评**：按正式视觉会商路线，以医学监查员身份在真实浏览器自由探索，重点审查信息架构、中文、交互负担、响应式和康哲交互轨美学。
2. **临床逻辑与证据审评**：按正式复杂任务会商路线，独立审查规则树、阶段语义、证据回源、行动分类和 Patient Profile 的临床可解释性。
3. **Codex 复现与裁决**：只接收报告、截图、路径和测试锚点；逐项在当前运行环境复现，决定接受、修复或延后至明确阶段。
4. **独立复测**：修复者不得关闭自己的问题；由新鲜上下文测试者复测，Codex 做最终浏览器和临床产品验收。

## 真实环境边界

- 测试地址由桌面 V2 启动器或 `scripts/start_v2_uat.sh` 提供，必须核对 `uat-status.json` 与页面版本。
- 当前数据来自 `frontend/src/data` 和 `contracts/v1/fixtures`；允许改变浏览器本地演示状态并复位，不写 legacy 项目。
- 浏览器证据至少包含页面、受试者/规则或任务对象、视口、操作路径和预期/实际差异。
- 真实方案、OCR、临床事实抽取和模型审核尚未接入；任何涉及这些能力的发现作为后续阶段合同审查，不作为当前运行结果。

## 发现处理

- **当前阻断**：会导致错误临床理解、错误状态、关键证据不可达、主路径无法完成、严重裁切或内部实现语言暴露。必须在 Phase 1.5 修复。
- **当前重要**：显著增加资深监查员负担或误操作，但仍可正确完成。优先修复；未修复需有可接受理由。
- **后续阶段合同**：当前原型无法真实执行，但会决定 Phase 2-8 的领域、存储、Agent 或证据实现。写入对应阶段合同和测试，不伪造实现。
- **不采纳**：无法复现、与权威设计冲突、会削弱证据链或属于安全/多用户范围。记录拒绝理由。

## 视觉合同

- 参照 `kangzhe-design` 的 `site` 轨，不采用固定 1280×720 画布；采用其浅色全局导航、多页互通、跨页下钻、站点组件和响应式审美。
- `site` 轨中的“纯静态、无前端框架、file:// 直接打开”属于独立静态站点交付技术约束，与已批准的 V2 React/FastAPI 应用架构冲突，本系统不采用；视觉与交互合同继续生效。
- 主强调色 `#FF9900`、副强调 `#FFCC00`、风险红 `#C00000` 仅按语义使用；浅色面积为主。
- 正文默认不低于 16px，高密度表格不低于 14px；布局用弹性网格、最小最大约束和内容驱动尺寸。
- 页面主任务优先，品牌只提供稳定身份，不抢占临床信息；不使用大面积装饰卡片、渐变或营销式首屏。

## 停止条件

- 任一测试者发现错误临床结论、证据错配、父子逻辑误导或当前主路径阻断，即停止“通过”判定并进入根因修复。
- 路线仅在明确终态失败、无可恢复会话或同会话恢复耗尽后 fallback。
- 未覆盖的真实能力必须保留为后续阶段，不能为了形式上的“全流程通过”提前越过 Phase 2-8。

## 本轮根因修订合同（2026-08-14）

### 当前阶段必须修复

1. **看板筛选口径**：`存在冲突`、`需专业判断`是审核节点可叠加的关注类别，不能继续按唯一主状态匹配。筛选与计数必须使用同一纯函数，并明确同一节点可同时命中多个关注类别。
2. **冲突来源并列回源**：冲突组中的每个事实必须显示立场、值、来源文件、资料版本、页码、摘录和定位精度；不得只显示“存在冲突”标签，也不得自动选择一个来源。
3. **规则逻辑表达**：例外条件必须说明其对主条件判定的作用；谓词不得出现“为 等于 是”等机械拼接。父规则摘要只描述子项当前状态与父子层级，不能在展示层重新计算临床结论。
4. **导航上下文**：从全局导航进入入排工作台时保留最近一次受试者和审核节点；无效节点明确提示，不得静默回落到另一名受试者。
5. **资料缺口语义**：Patient Profile 空主题只表示当前没有结构化事件，是否构成缺口由当前节点应备证据决定；不得把所有空泳道写成资料缺口。
6. **行动分类**：溯源提醒保持独立类别，可单独筛选；不得合并成阻断或笼统的“需关注”。
7. **证据信息完整性**：证据弹窗显示资料快照版本；应备证据行显示规则编号和具体要求，并区分当前子项要求与节点全部要求。
8. **示例数据一致性**：明确障碍的判断与阻断程度、Profile 事件日期与审核节点日期、事件关联规则必须满足共享不变量；修生成源和合同校验，不给单个受试者打补丁。

### 本轮补足但不冒充后续能力

- 合成 Patient Profile 至少提供人口学、目标疾病、既往史、用药/治疗、检查评分和审核节点的代表性时序事件，用于验证信息架构；明确标注为试用资料，不宣称已实现真实资料自动抽取。
- 页面正文和高密度区域按 `kangzhe-design` 站点轨检查可读性、浅色全局导航、康哲暖色身份和跨页下钻；不改为静态 `file://` 站点。

### 验证不变量

- 冲突或专业判断计数大于零时，对应筛选结果不得为空。
- `exclusion_triggered` / `inclusion_not_met` / `requirement_not_met` 不得配 `blocking_level=none`。
- 空 Profile 泳道不得自动生成缺口结论。
- 例外条件成立的界面语义不得被读成“主条件成立所以触发”。
- 无效审核节点 URL 不得打开其他受试者。
- 溯源提醒可以被筛出，但不会改变当前节点的主要结论。

### Patient Profile 事件证据关系

个例时间轴事件与资料入口使用显式关系，不根据“页面上存在某段证据”推测：

- `direct`：事件绑定的事实拥有该 EvidenceSpan，入口称“打开原始依据”。
- `review_basis`：事件是审核汇总，入口称“查看判断依据”。
- `related_rule`：只有关联规则资料，入口称“查看关联规则资料”，不得声称是事件原始依据。
- `unavailable`：没有事件级独立定位，不显示链接，并明确提示“尚无该事件的独立原始资料定位”。

每个可点击事件同时携带 `evidenceTargetComponentId`。该组件必须是所选 EvidenceSpan 在当前审核节点内的实际判断属主；URL、页面选中规则和证据片段不得出现静默改指向。事件若声明 `fact_ids`，其 EvidenceSpan 必须属于这些事实之一，否则合同校验拒绝数据。
