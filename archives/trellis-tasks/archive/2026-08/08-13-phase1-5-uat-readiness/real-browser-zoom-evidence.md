# 真实浏览器缩放验收记录

验收日期：2026-08-13

## 验收对象与方法

- 浏览器：Google Chrome 151.0.7922.109，独立用户目录、独立调试端口；验收前本机没有运行 Chrome，不会干扰用户原有浏览器窗口。
- 物理窗口：约 1440 CSS 像素宽的 Chrome 窗口。
- 缩放操作：使用浏览器自身的 Command+0 和 Command+Shift+=，不是修改 Playwright 视口。
- 通过信号：CSS 可视宽度和 `devicePixelRatio` 必须按浏览器缩放同步变化；三档均执行“个例风险 → 规则子项 → 原始证据 → 返回”。
- 视觉证据：使用 macOS `screencapture` 对真实 Chrome 窗口截图；不使用 CDP 页面截图证明真实缩放视觉结果。

## 预期外结果与处理

1. **Edge 快捷键没有改变缩放。** Edge 隔离实例和调试端口均可用，但 macOS 辅助功能层把两个相同应用实例合并，快捷键落到用户原有 Edge 窗口。CSS 宽度和 DPR 未变化，因此该结果判为失败，没有把截图标签当作成功。随后改用当时未运行的 Chrome 独立实例。
2. **CDP 页面截图偏移或空白。** 在 150%/200% 且页面因点击证据发生纵向滚动时，Playwright 的 CDP 截图出现偏移或空白；同时 DOM 几何显示固定遮罩和弹窗位于可视区。macOS 系统级窗口截图确认用户实际看到的弹窗完整可见，因此根因是 CDP 截图与真实缩放/滚动组合的捕获缺陷，不是页面空白。
3. 已删除失败的 Edge 图片、CDP 诊断图片及旧 `zoom150`/`zoom200` 等误导命名；自动化中的视口变化统一称为“布局压力”，不得替代真实浏览器缩放验收。

## 可复现入口

- 测量脚本：`frontend/e2e/real-browser-zoom-check.mjs`。
- 脚本现根据 100% 基准宽度与屏幕倍率推导 150%/200% 预期值，并在个例首页、审核工作台、证据弹窗三段路径同时校验标签、视口宽度、DPR 和页面级横向溢出；标签与真实缩放不符会直接失败。
- 脚本连接隔离浏览器后读取 CSS 宽度、DPR、滚动位置、应用外框、遮罩和弹窗矩形，并执行完整证据往返。
- 使用 `--hold` 可在弹窗打开后保留现场，再由系统级窗口截图完成最终视觉验收。
